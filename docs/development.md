# 开发与验证

## 可复现入口

根目录安装 Node.js 22+ 依赖：`npm ci`。`package-lock.json` 锁定版本，避免不同机器自行漂移依赖。

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 从 `src/` 生成全离线 HTML |
| `npm test` | 检查当前构建及三套布局；先构建 |
| `npm run check` | 依次运行以上两步 |
| `python scripts/render-layout-comparison.py --font <字体路径>` | 从检查生成的家具占地数据更新比较图；需 Pillow |

构建不启动服务器、不上传文件、不发布网站。打开 `output/3d/ideal-home-3d.html` 即可使用。构建脚本通过自身位置定位仓库，检查脚本也统一到仓库根目录，不依赖开发者绝对路径。

## 自动检查的覆盖与边界

`scripts/check-layouts.mjs` 使用实际 Three.js 场景构造器，检查：

- 三套方案的可见家具和变换结果确实不同，来回切换不会累计偏移。
- 受保护物品与已登记墙、门、窗的变换和材质保持不变。
- 当前家具的平面外包框没有超过容差的相交；主过道没有被家具占用。
- 各房间指定漫游起点没有落在家具占地内。
- 实际显示模式函数、家具隐藏和房间隔离逻辑可以配合方案切换。
- 当前 HTML 已生成，取消的预算界面没有残留。

报告写入 `output/3d/qa-r10.json`，占地数据写入 `output/3d/layout-footprints-r10.json`，不进入 Git。检查不会改写示例事实记录。

Canvas 绘制使用替身；这些检查没有运行 WebGL、没有验证屏幕效果、没有做完整的寻路或门扇开启区域分析，也不验证建筑构造。几何检查依据的是暂定模型，不是现场尺寸。

## 浏览器人工验收

需要浏览器复核时，至少检查以下用户流程：

1. 正常加载，无控制台错误；桌面和手机宽度下能找到布局按钮。
2. 固定视角切换 A / B / C，家具组合明显变化，固定柜和建筑关系不动。
3. 平面图默认线框，三套布局在白模和线框中仍有区别。
4. 选中只属于某套方案的家具后切换方案，旧选择不会残留。
5. 隐藏家具、单独查看房间、进入房间、夜间灯光和保存画面可用。

当前记录：R1.0 几何与状态检查已通过；该版本未完成浏览器画面复核。此前环境的本地文件浏览器访问受限；不能据此声称视觉验收通过，也不能用旧截图充当当前结果。

GitHub Actions 配置运行 Windows / Linux 的 Node 构建和同一套几何检查，不包含浏览器截图测试。CI 是否通过以实际运行结果为准。
