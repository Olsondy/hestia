## Problem Statement

每套部署原本只有一家企业，跨企业访问从未被系统地测试；共享部署上线前需要证明两家企业彼此不可见。

## Solution

建立两家企业的跨企业隔离测试矩阵并纳入 `pnpm test:db`，演示数据准备两家企业，在两个本地域名下完成浏览器联合验收。

## User Stories

1. As a 维护者, I want 每个对外接口都有跨企业访问测试, so that 新接口漏写检查时测试会失败。
2. As a 演示者, I want 本地一次准备两家企业的演示数据, so that 现场能展示两家互不可见。

## Implementation Decisions

- 测试矩阵：以 A 的成员、A 的客户、未登录访客分别访问 B 的线索、方案、修订、分享码、绑定申请、图纸需求、文件、石材与软装目录、后台任务与事件流；期望拒绝，且响应不区分“不存在”与“无权限”。
- 新增一项检查：列出所有客户与工作台路由，未被矩阵覆盖的路由使检查失败。
- `pnpm demo:seed` 支持准备两家演示企业及其域名（`a.localhost`、`b.localhost`），包含同一手机号在两家各自的客户账号。
- 验收记录写入 `docs/validation/`。

## Testing Decisions

- [x] `pnpm test:db` 中的跨企业矩阵全部通过，路由覆盖检查通过。见 [M06 验证](../../validation/M06-isolation.md)。
- [ ] 真实浏览器（390 与 1440 视口）：在 `a.localhost` 与 `b.localhost` 分别以同一手机号登录客户端、以各自成员登录工作台，看到的数据互不相同；在 A 域名输入 B 的分享码提示不存在。

## Out of Scope

渗透测试；生产环境验收；RLS。
