# 我方托管一套共享服务，企业按工作空间隔离，账号按企业隔离

用户于 2026-11-10 明确：演示之后，甲方企业希望降低运维与运营成本，不想为服务端备案和购买服务器，只负责面向客户的小程序（主体与小程序备案）；服务端应用全部由我方提供。首批要接入甲方 A 与甲方 B，分别为它们的小程序客户端与企业工作台提供服务。

本决定覆盖 [ADR-0016](0016-dedicated-deployment-per-enterprise.md) 中“每家企业独立部署一套”的部分，以及 [ADR-0007](0007-shared-core-personal-and-enterprise-workspaces.md) 中“账号全平台唯一”的设想。对话中说的“租户”即本文的**企业工作空间**，领域用语仍以 `CONTEXT.md` 为准。

## 决定

- **一套服务，多家企业**：我方运营一套 Web、Agent Worker、出图 Worker、图纸转换 Worker、PostgreSQL 与私有文件存储，A、B 各是其中一个企业工作空间。独立部署的固定成本（常驻实例、托管数据库、备份、监控）与每次发版的运维工作都按企业数量线性增长；共享部署摊薄固定成本，只维护一处。模型调用按用量计费，与部署方式无关。
- **按域名识别企业**：每个企业工作空间登记一个或多个入口域名（例如我方主域名下的 `a.…`、`b.…`），请求按域名确定企业。路径保持 `/c/…`、`/w/…`（ADR-0016）；后台接口 `/api/client/{企业}/…` 里的企业标识必须与域名所属企业一致，否则按不存在处理。不认识的域名与主域名本身显示我方入口页，不接到任何企业。`HESTIA_HOME_ENTRY` 保留为本地开发与单企业部署的回退。
- **数据层隔离**：同一个数据库，业务数据都归属某个工作空间，读写一律经工作空间成员或客户关系判断（现有 `project_access` 与各服务的访问检查）。私有文件按工作空间分目录；后台任务带工作空间，按工作空间限制并发，避免一家的批量出图长期占满队列；用量按工作空间可查，用于和企业结算。PostgreSQL 行级安全（RLS）暂不启用，作为企业数量增多后的兜底手段另行决定。
- **账号按企业隔离**：每个账号属于一个企业工作空间（个人工作台的平台账号不属于任何企业，首期仍不开放）。同一手机号在 A、B 是两个互不相关的账号；邮箱与手机号在同一企业内唯一。会话只在所属企业的域名下有效，换到另一家企业的域名必须重新登录。一家企业无法通过登录、绑定、分享码或接口得知某客户也是另一家企业的客户。
- **小程序登录**：甲方小程序作为原生壳，负责登录与承载 web-view；我方服务端用该企业的小程序凭据（AppID / AppSecret，按企业加密保存）换取身份，再以一次性、短时效的票据把登录交给 web-view 里的 H5。短信验证码登录保留，供直接打开 H5 时使用。
- **责任划分**：甲方负责小程序主体、小程序备案、在小程序后台把我方域名配置为业务域名与 request 合法域名；我方负责入口域名的 ICP 备案、全部服务端、数据、出图、升级与监控。
- **独立部署仍可选**：代码只有一套。有企业明确要求独立数据库或私有化部署时，按 ADR-0016 的方式单独部署并另行定价，不分叉代码。

## 考虑过的替代方案

- **继续每家独立部署**：隔离最强、互不影响，但固定成本与运维随企业数量成倍增长，初期两家企业的用量都撑不起各自的常驻资源。
- **共享应用、每家一个数据库或 schema**：隔离比同库更强，但迁移、连接池、备份恢复要按企业逐一执行，复杂度接近独立部署；等有企业要求时再评估。
- **账号全平台唯一（ADR-0007 原设想）**：客户在多家企业之间可以用同一账号，但 A、B 很可能是同业竞争关系，共享身份容易泄露“同一客户也找了别家”；不同企业的小程序 openid 本来也不同。个人工作台开放时另行决定平台账号与企业账号的关系。

## 影响

- `hestia_auth_user` 的手机号、邮箱唯一约束改为按企业唯一；better-auth 的邮箱登录与手机号登录要按请求域名所属企业查找账号。现有数据需要迁移：每个现有账号归到它唯一关联的企业，关联多家企业的账号拆分或在迁移时明确报错。
- ADR-0007 补充中的“企业分享给我的”一栏、复制到个人项目等跨企业设想，在账号按企业隔离后不成立，留待个人工作台开放时重新决定。
- 跨企业隔离此前没有测试覆盖（每套部署只有一家企业），上线前须补齐跨企业访问测试，并作为 `pnpm test:db` 的固定内容。
- 微信对 web-view 业务域名的具体要求（包括是否要求域名备案主体与小程序主体一致或关联）以接入时的官方规则与审核结果为准；若要求一致，改为由甲方提供子域名并解析到我方服务。
- 云厂商、地域与资源规格仍未定（`web-stack.md` 7.2），本决定不代表已部署或已授权购买资源。

## 补充（2026-11-10，M02）

用户确认：账号按企业隔离只针对**客户账号**（手机号）。企业成员的邮箱账号仍是平台账号，可以同时是多家企业的成员（例如我方运维）；在某企业的域名上，只有该企业的成员或客户的登录有效，其他一律按未登录处理。邀请、建企业与邮箱登录流程不变，邮箱仍全局唯一。上文“每个账号属于一个企业工作空间”“邮箱与手机号在同一企业内唯一”按此理解为客户账号与手机号。
