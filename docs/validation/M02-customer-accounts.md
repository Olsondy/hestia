# M02 客户账号按企业隔离验证

日期：2026-11-10。范围：工单 #60，依据 ADR-0017 及其 M02 补充（只隔离客户账号，成员邮箱账号仍为平台账号）。PostgreSQL 17.7（同 M01），HTTP 路由处理函数直接调用。

## 实现要点

- **数据**：迁移 `0006_customer_accounts_per_enterprise`：`hestia_auth_user.workspace_id`（可空；删除企业时随之删除），手机号唯一改为「所属企业 + 手机号」唯一（平台账号视为同一范围）；约束：归属企业的账号只能是手机号账号、不带邮箱。`phone_otp_challenges.workspace_id` 记录验证码是哪家企业的入口申请的。
- **迁移现有账号**：自定义迁移 `0007_backfill_customer_accounts`：手机号账号只关联一家企业的归到该企业；没有客户关系的保持平台账号；关联多家企业的让迁移失败并列出账号 id，不自动拆分。本次在局域网数据库上执行，3 个现有客户账号全部归到各自企业，没有冲突。
- **登录**：验证码的发送、冷却、按手机号的频率限制、作废旧码和登录都按「企业 + 手机号」进行；按来源（IP）的限制仍跨企业共用。登录时在该企业范围内查找或创建账号，由「企业 + 手机号」的事务锁串行，不会重复创建。
- **会话**：页面与接口读取会话统一经 `sessionFor`。在已登记的企业域名上，会话账号须是该企业的客户账号，或是该企业成员 / 客户的平台账号，否则按未登录处理（`/api/session` 返回 `user: null`，需要登录的接口 401）。会话 cookie 不跨子域，本来就只发往登录时的域名。
- **跨企业补客户关系**：客户端接口会给已登录账号自动补上客户关系；现在归属另一家企业的账号在任何域名上调用都 401，不会变成这家企业的客户。
- **成员**：邀请、`pnpm invite`、`workspace:create` 与邮箱登录不变，邮箱仍全局唯一。

断言：同一手机号在 A、B 登录得到两个账号，各自归属、各自的客户关系；在 A 再次登录回到同一账号；同一企业内重复手机号被数据库拒绝（23505）。A 客户的会话在 A 域名有效、在 B 域名为未登录；在未登记域名下调用 B 的客户端接口 401，且没有成为 B 的客户。只属于 A 的成员平台账号在 A 域名有效、在 B 域名为未登录、在未登记域名有效。A 申请的验证码在 B 登录为 `OTP_NOT_REQUESTED`；A 的重发冷却不影响 B 发码，B 的新码也不作废 A 的码。迁移：单一企业的旧账号归属该企业，无关系的保持平台账号，关联两家企业时迁移报错并列出账号。

## 未验证

- 平台成员账号在非本企业的域名上用邮箱登录时，登录本身会成功、随后的请求按未登录处理，界面会回到登录页，没有专门提示；首期成员由我方邀请，暂不处理。
- 没有重新生成演示数据（`pnpm demo:seed`），演示脚本建客户账号走的是同一登录流程。
