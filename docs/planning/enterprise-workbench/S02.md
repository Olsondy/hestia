## Problem Statement

线索只有方案和事件，企业成员无法记录跟进到哪一步，也没有团队内部可见的备注。

## Solution

为每条线索增加跟进状态和内部备注，只有本企业成员可读写，并出现在线索视图中。

## User Stories

1. As an 企业成员, I want 设置线索的跟进状态, so that 团队知道这位客户的进展。
2. As an 企业成员, I want 追加内部备注并看到是谁、何时写的, so that 交接时不丢信息。
3. As a 客户, I want 企业的内部备注不出现在我的页面, so that 内部沟通不外泄。

## Implementation Decisions

- 跟进状态：新线索（默认）、已联系、跟进中、已成交、已搁置。变更记录操作者与时间，可查询历史。
- 内部备注只追加不修改，最长 500 字，记录成员与时间。
- 线索列表视图返回当前跟进状态、最近一次客户动作（提交、确认、留言、联系请求、绑定申请）及其时间，支持按状态、跟进状态、是否请求联系筛选。
- 接口带操作标识，幂等；客户端接口与分享预览不返回这些字段。
- 在 `CONTEXT.md` 补充“线索跟进”术语。

## Testing Decisions

- [ ] HTTP + PostgreSQL：成员可设置状态与追加备注；客户、其他企业成员与未登录访客不可读写；客户端视图与分享预览不含备注；筛选结果正确；重复操作幂等。
