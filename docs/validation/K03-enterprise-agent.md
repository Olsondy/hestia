# K03 企业 Agent 出整体方案候选验证

日期：2026-11-15。PostgreSQL 17.7（局域网主机上的本地 Compose 容器，经 SSH 隧道映射到 127.0.0.1:54329），对话运行器真实执行，模型为本机假服务。范围：工单 #54，依据 [ADR-0019](../decisions/0019-enterprise-agent-uses-validated-operations-only.md)（Agent 只调用已有、已校验的方案操作，结果一律为候选）与 ADR-0018（模型由我方分配，按调用预占与结算）。

## 实现要点

- **提案**（`packages/contracts/src/agent-schemes.ts`、`packages/conversation/src/model.ts`）：`resolve_turn` 新增 `propose_scheme`：每组饰面的石材、规格（毫米）、铺法和可选波打线，一套软装风格，以及客户可切换的风格（合计不超过 3 套）。模型只给目录 id，不给版本和坐标。
- **只读资料**（`packages/finish-requests/src/agent.ts` 的 `leadContext`）：线索空间上，应用把楼层、房间、饰面（标出客户需求里的饰面）、本企业在用石材（规格范围）、在用软装风格、已有方案摘要随本轮输入提供，代替完整几何；不含单价和其他企业资料。个人项目的输入不变。
- **校验**（`packages/finish-requests/src/scheme-check.ts`，纯函数）：石材、软装风格只认本企业在用版本；饰面必须属于该空间、不能重复指定；波打线只用于地面；铺贴经 `inspectSurfaceDesign` 检查规格范围与排版。有任何冲突就拒绝，不保存候选，原因写进本轮结果（`no_change` + `schemeIssues`）。客户需求里没铺的饰面、软装放不下的陈设只记为提示。
- **候选**（`scheme_candidates`，迁移 `0012_agent_scheme_candidates`）：通过校验的提案保存为候选，并排队出图（出图来源 `scheme-candidate`，现有确定性出图服务）。候选不改空间，也不改线索已有方案。同一轮（任务 + 操作标识唯一）只会有一个候选，重放返回同一个。
- **采用与发布**：成员采用候选时，空间必须和出候选时一样，并且重新校验石材目录和软装风格；之后它成为线索的待审方案（`finish_schemes.pending_review`），并重新出一张方案图。客户端、分享码预览、出图、3D 场景、调整和确认都看不到待审方案。成员发布后，客户才看得到。一条线索最多 6 套方案。接口：`GET …/leads/{id}/candidates`、`POST …/candidates/{id}/adopt`、`POST …/schemes/{id}/publish`，只有本企业成员能调用，M06 隔离矩阵自动覆盖。
- **资料上限按实际发送的内容计算**：对话的资料上限（32 KB）原来按完整空间几何计算，示例别墅超出上限，每一轮都停在 `CONTEXT_LIMIT`。线索的一轮并不发送几何，所以上限和额度预估都改为按实际发给模型的内容（`promptOf`）计算。个人项目发送的内容没变，计算结果也不变。
- **对话状态**：出了整体方案候选的一轮直接完成，不进入「等待选择」。候选挂在线索上，同一线索上其他成员仍可继续让 Agent 出方案。
- **与原文的出入**，详见 ADR-0019：
  - 企业方案不保存家具摆放，所以家具只在软装风格的规则内，按楼层和房间换款、补充陈设；按房间移动或重排家具需要另立工单。
  - 每套方案只能有一套软装风格。

断言摘要：
- **合法提案**：
  - 这一轮完成，结果是整体方案候选；
  - 发给模型的输入带本企业全部在用石材和客户需求饰面，不含单价；
  - 候选软装风格和可切换风格与提案一致，出图已排队，来源为 `scheme-candidate`；
  - 空间修订和客户可见方案数不变；
  - 同一轮重放返回同一个候选，这一轮只有一个候选。
- **不合法提案**：用别的企业的石材时结果为 `no_change`，原因包含 `STONE_NOT_IN_CATALOG`；规格 4000×4000 时包含 `TILE_SIZE_OUT_OF_RANGE`。两次都没有新增候选。
- **采用与发布**：
  - 采用后线索多一套待审方案，名称和风格与候选一致，方案图已排队，客户看不到；
  - 同一操作标识再提交不重复执行，另一次采用被拒（`CANDIDATE_ADOPTED`）；
  - 发布后客户看得到，再发布被拒（`SCHEME_ALREADY_PUBLISHED`）。
- **空间已变化**：候选标为过期，采用被拒（`CANDIDATE_STALE`）。
- **非成员**：在线索空间上建 Agent 任务、查看候选、采用候选都返回 404。

## 真实模型验收（2026-11-26）

环境：本机 Next.js dev（`a.localhost:3000` 企业、`admin.localhost:3000` 后台）+ 对话 Worker；PostgreSQL 为局域网主机容器（SSH 隧道）。模型服务为用户本机的 Magpie 网关（`http://127.0.0.1:3425/v1`，OpenAI Chat Completions 协议），模型 `deepseek/deepseek-v4-pro`。操作经 HTTP 接口完成，未用浏览器。单价为验收占位（输入 4 元、输出 16 元 / 百万 token），不是供应商报价。

| 步骤 | 结果 |
| --- | --- |
| 后台登记服务 → 连通测试 → 获取模型列表（34 个）→ 启用模型 → 设单价与最大输出 8192 | 通过 |
| Worker 接入检查 | 准入（`admitted`）：connect、stream、tools、protocol、usage 通过；`toolStream`（流式工具参数增量）未通过，不阻断准入；单元修改提案通过校验、模糊请求只给文字、截断结果被拒 |
| 分配给演示企业（额度 5000 分、并发 2），企业管理员启用并设为默认 | 通过 |
| 山景别墅线索上发「客厅和餐厅地面用浅色大理石，大板直铺，背景墙用深色石材做点缀；软装整体偏现代简约」 | 第一次失败 `MODEL_ABORTED`：运行器把单次调用超时写死为 20 秒，没有用服务登记的超时（见下）。修复后重跑：68 秒完成，输入 4728 / 输出 4024 token |
| 候选 | 1 套「浅色大板现代简约」：客厅、餐厅地面白色细纹大理石 1800×900 直铺，电视背景墙深色金脉石 600×600，软装现代简约；校验提示楼梯过厅与楼梯踏面未铺贴（`FINISH_NOT_COVERED`，提示级），回复里如实说明并询问是否纳入 |
