## Problem Statement

`hestia_auth_user` 的手机号与邮箱全局唯一，会话在任何企业域名下都有效。按 ADR-0017，同一手机号在 A、B 应是两个互不相关的账号。

## Solution

账号归属企业工作空间；注册、登录、绑定、成员邀请都按请求域名所属企业进行，会话只在所属企业域名下有效。

## User Stories

1. As a 客户, I want 在甲方 A 和甲方 B 用同一手机号分别登录, so that 两家企业的记录互不相干。
2. As an 企业成员, I want 绑定、分享码与申请都无法透露客户在其他企业的存在, so that 企业之间不泄露客户关系。
3. As a 维护者, I want 现有账号迁移时冲突明确报错, so that 不会静默合并两个人的数据。

## Implementation Decisions

- 账号增加所属工作空间（可空，空表示平台账号，供首期不开放的个人工作台）；手机号、邮箱改为在同一所属范围内唯一。
- 手机号验证码与 better-auth 邮箱登录按请求企业查找与创建账号；验证码的频率限制按企业与手机号分别计数。
- 会话 cookie 不设跨子域；服务端核对会话账号所属企业与请求企业一致，不一致视为未登录。
- 成员邀请（`pnpm invite`）与 `workspace:create` 的管理员账号创建在对应企业范围内。
- 迁移：账号只关联一家企业的归到该企业；没有企业关联的保持平台账号；关联多家企业的迁移失败并列出账号，不自动拆分。演示数据随之更新。

## Testing Decisions

- [ ] HTTP + PostgreSQL：同一手机号在 A、B 各得一个账号，项目、绑定与积分互不可见；A 的会话在 B 域名下为未登录；同企业内手机号与邮箱仍唯一；邀请与管理员账号落在正确企业；迁移的归属、平台账号与冲突报错三种情况。

## Out of Scope

平台账号与企业账号的关联；个人工作台开放；账号合并。
