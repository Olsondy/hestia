## Problem Statement

一家以别墅、酒店、展厅为主要客户的石材硬装企业，需要先看到可运行的效果，才决定是否立项。企业希望两件事：客户在手机上自己提交户型和石材偏好就能得到铺贴效果，企业由此获得带具体方案的销售线索；企业人员为客户做好的方案，可以通过链接发给客户查看和确认。

Hestia 当前以个人用户和家具布局为中心：项目直接归属单个用户，没有企业工作空间、客户身份和手机号登录；空间只有单层，没有楼梯；房间地面只有颜色，墙没有面，材质只能作用于家具，无法表达石材铺贴。

## Solution

按 [ADR-0007](../../decisions/0007-shared-core-personal-and-enterprise-workspaces.md) 交付一次可离线演示的 H5 客户端，覆盖两个企业入口：

1. **客户自助**：客户用手机号登录企业的 H5 入口，以示例别墅或上传的 DXF 图纸提交方案需求，选择空间与石材，得到 2–3 个铺贴方案的效果图，在给定选项内调整并确认。
2. **成员分享**：演示数据预置一个由企业成员“已做好”的别墅项目和分享链接。客户不登录即可预览；登录并满足绑定条件后，项目绑定到客户账号，可以调整与确认。

服务端按正式逻辑开发：工作空间与成员、客户关系、手机号验证、项目归属、分享与绑定、成员审核与发布、多楼层空间、饰面铺贴与校验、后台出图。仅短信发送使用模拟适配器，演示数据来自 fixture。企业成员的工作台界面本次不实现、不演示，成员侧能力通过服务端接口和种子脚本提供。

交付顺序：服务端能力先行，各票以 HTTP 与后台任务验收；H5 客户端先做交互原型，用户审阅通过后才开始实现。

## User Stories

1. As a 客户, I want 用手机号和验证码登录企业入口, so that 不需要记住密码。
2. As a 客户, I want 在演示环境看到明确的演示验证码提示, so that 没有真实短信也能走完流程。
3. As a 客户, I want 用示例别墅体验, so that 没有图纸也能看到效果。
4. As a 客户, I want 上传自家 DXF 图纸, so that 方案基于我的真实户型。
5. As a 客户, I want 知道非 DXF 图纸需要辅助转换, so that 不会误以为已经自动识别。
6. As a 客户, I want 选择要铺石材的空间（各层地面、背景墙、楼梯）, so that 只为关心的部位出方案。
7. As a 客户, I want 从企业石材库挑选款式和铺法, so that 方案使用企业实际供应的材料。
8. As a 客户, I want 提交后得到 2–3 个有实际差异的铺贴方案效果图, so that 能比较选择。
9. As a 客户, I want 在手机上转动查看 3D 别墅, so that 理解整体效果。
10. As a 客户, I want 自动结果不可靠时看到“等待企业审核”而不是错误结果, so that 不会被不准确的方案误导。
11. As a 客户, I want 在给定选项内换石材、换铺法并重新出图, so that 不懂设计也能调整。
12. As a 客户, I want 确认方案并留言或请求联系, so that 企业知道我的选择。
13. As a 客户, I want 不登录就能预览企业分享给我的方案, so that 打开链接就能看到效果。
14. As a 客户, I want 登录后把分享给我的项目绑定到自己的账号, so that 之后可以调整和确认。
15. As a 客户, I want 只有我本人能绑定分享给我的项目, so that 转发出去的链接不会让别人控制我的方案。
16. As a 客户, I want 只看到绑定给我或我自己提交的项目, so that 资料不被其他客户看到。
17. As an 企业成员, I want 客户的提交和确认自动成为工作空间里的线索, so that 能及时跟进。
18. As an 企业成员, I want 审核并发布自动结果不可靠的项目, so that 客户只看到可靠方案。
19. As an 企业成员, I want 以定向手机号、绑定码或审批方式分享项目, so that 绑定可控。
20. As an 企业成员, I want 撤销链接、解绑和重新分享, and 留有记录, so that 能处理发错或换人。
21. As a 个人用户, I want 原有账号和项目继续可用并归入我的个人工作空间, so that 定位调整不丢失已有成果。
22. As a 演示者, I want 断网时也能完整演示客户端两条入口, so that 在企业现场不依赖网络。
23. As a 维护者, I want 生产环境无法启用模拟短信, so that 演示开关不会被误带上线。

## Implementation Decisions

- 依据 ADR-0007。ADR-0001 固定事实、候选与采用、版本与幂等、后台任务与出图约束继续适用。作为总规格 #1 之外的新增范围；暂停中的工单不因本规格恢复。
- **工作空间**：项目、资源、出图与用量归属工作空间，不再直接归属用户。现有用户迁移为各自的个人工作空间，项目随之迁移且访问不变。企业工作空间有成员与角色。客户不是成员，通过客户关系和项目绑定获得访问。
- **账号**：全平台唯一。客户以手机号验证登录；成员和个人用户沿用邮箱密码，可以后续再绑定手机号。客户从哪个企业入口（H5 路径中的工作空间标识）登录，就建立与该企业的客户关系。
- **手机号验证**：验证码生成、哈希存储、时效、错误次数与频率限制按正式逻辑实现。短信发送经适配器；`SMS_PROVIDER=mock` 不外发，在服务端日志和演示界面提示验证码。生产环境启用模拟发送时服务启动失败。
- **多楼层**：空间契约增加楼层、楼板、楼梯与楼板开洞，一个坐标系上下对齐，保持米和 x/z 平面约定。渲染器支持整栋、单层和剖切查看。示例别墅改编自 house-plan-designer（MIT）三层别墅示例，保留许可声明，标注为演示。
- **饰面与铺贴**：饰面是建筑的一部分（各层地面区域、墙面、楼梯踏面），属于固定事实，不随家具移动。铺贴方案引用石材目录项与版本，记录规格、铺法（至少直铺、工字、人字、斜铺）、缝宽、起铺点与方向，至少支持一种波打线。排版引擎由程序计算整块与切块；校验窄条、超出饰面和缺失石材，区分硬冲突与提示。铺贴修改走现有候选与命令链路，不挪用家具材质替换。
- **石材目录**：属于工作空间的私有目录。演示使用 CC0 来源的示意贴图，记录来源与许可，界面标注“示意素材”。企业真实素材不进仓库。
- **图纸导入（A 方案）**：DXF 由后台 Worker 调用改编自 house-plan-designer `cadvec` 的转换，经现有 `floorplan-import` 生成空间候选并校验。其他格式不自动识别，进入“辅助转换”状态，由成员提供 HouseSpec 后导入，界面如实标注。不恢复暂停中的 T02/T11 栅格识图。
- **方案生成**：客户提交后，后台按空间类型和尺寸以规则生成 2–3 个铺贴方案并出图，不调用生成式 AI。导入或排版校验不通过时进入待审核，成员通过服务端接口修正后发布；工作空间可以配置“全部审核后发布”。
- **客户调整**：只提供选项式调整（石材、铺法、波打线开关等），每次调整生成新的候选修订并确定性重新出图。确认绑定具体候选版本，沿用现有采用规则。
- **分享与绑定**：分享链接使用不可猜测的令牌，可设有效期、可撤销，只授予预览已发布方案。绑定须满足定向手机号匹配、一次性绑定码或成员审批之一。一个项目一个主客户；绑定、解绑、撤销都留记录。客户自己提交的项目无须绑定。
- **线索**：客户提交、确认、留言与联系请求，在工作空间内形成可查询的线索记录。本次只提供服务端查询，不做成员界面。
- **客户端界面**：手机优先的 H5，加载离线可用的字体与贴图。延续家居杂志方向的设计规范与仓耳渔阳体，实施 UI 时使用 Impeccable，不启用 hooks。效果图优先，3D 查看作为补充。
- **原型门槛**：H5 先交付可点击的交互原型（登录、提交需求、方案结果、调整确认、分享预览与绑定、各类等待与失败状态），使用演示数据，不接服务端。用户审阅通过并明确同意后，才开始 H5 实现；开始实现时通知用户。服务端工单不依赖原型，可以先行。
- **演示数据**：种子脚本通过正式服务接口创建演示企业、成员、客户、示例别墅项目与分享链接，可以重复执行且结果幂等，不直接写数据库绕过规则。

## Testing Decisions

以下测试入口沿用现有规格的做法。测试只断言可观察行为与持久化结果，不镜像内部函数。

1. **HTTP + 真实 PostgreSQL**：工作空间迁移与隔离、客户关系、手机号验证的时效/次数/频率、分享令牌权限、三种绑定条件、撤销与解绑、线索记录、生产环境拒绝模拟短信。
2. **后台任务 + 真实 PostgreSQL / pg-boss**：DXF 导入转换、方案生成、出图、校验失败转审核，以及重复投递和重启后不重复生成。
3. **几何与排版夹具**：多楼层对齐与楼梯连接、饰面边界、各铺法的整块与切块数量、窄条与越界判定。
4. **真实浏览器手机视口**：仅用于 H5 实现与离线演示验收，覆盖两条入口的完整流程、断网演示、刷新恢复与视觉检查。自动测试不能替代视觉验收。

服务端工单以第 1–3 类入口验收，不要求页面。最高测试接缝为公开 HTTP 接口与后台任务服务，既有 `scripts/validation/*-api.ts` 与 `pnpm test:db` 中的项目、候选、出图集成测试为先例。

验收先检查已有服务。未经用户同意不启动或重启 Web、数据库或 Worker。

## Out of Scope

企业成员工作台界面及其演示；Agent 与模型调用的改动；真实短信服务商、微信登录与小程序；栅格图片和 PDF 的自动识图；客户对话式调整；用料估算与报价；付费、订阅与积分在企业空间的规则；企业真实石材素材；生产部署与备案；连纹、拼花图案库与台面；个人用户的工作台改造。

## Further Notes

- 暂停的工单保持暂停，本规格不依赖它们。
- 演示可离线完成的前提：不调用模型，字体、贴图、示例数据均在本地，短信为模拟发送。
- 楼层与饰面契约同时服务以后的个人场景，不写成企业专用。
