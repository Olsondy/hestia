## Problem Statement

客户端以 web-view 嵌在甲方小程序里，目前只能短信验证码登录；小程序登录需要用各企业自己的小程序凭据在服务端换取身份，而服务端由我方托管。

## Solution

甲方小程序原生壳取得登录凭证与手机号授权后调用我方接口，换取一次性票据，打开 web-view 时带上票据，H5 用票据建立该企业下的会话。

## User Stories

1. As a 客户, I want 在小程序里授权手机号后直接进入方案页面, so that 不必再输入验证码。
2. As a 维护者, I want 每家企业的小程序凭据分别加密保存, so that 一家凭据泄露不影响另一家。
3. As a 客户, I want 直接打开 H5 时仍可用短信验证码登录, so that 不在小程序里也能使用。

## Implementation Decisions

- 企业工作空间保存小程序 AppID 与加密后的 AppSecret，`pnpm workspace:miniprogram <slug> …` 管理；AppSecret 不进日志与接口响应。
- 接口：原生壳提交登录 code 与手机号授权 code，服务端经适配器向微信换取 openid 与手机号，在该企业范围内找到或创建账号，记录 openid，返回一次性票据（短时效、只能用一次、绑定企业）。
- H5 以票据换会话后从地址中去掉票据；过期、已用或企业不符的票据显示可理解的提示并提供短信登录。
- 适配器：测试与演示为模拟实现，生产调用微信接口；生产环境不得启用模拟（与短信一致）。
- 提供原生壳最小示例与接入说明（登录、打开 web-view、业务域名配置），放在 `docs/` 下，不提交任何企业的 AppID。

## Testing Decisions

- [ ] HTTP + PostgreSQL（模拟适配器）：票据只能用一次、过期失效、企业不符被拒；同一手机号经小程序与短信登录得到同一企业账号；A 的票据在 B 域名下无效；AppSecret 不出现在响应与日志中。
- [ ] 真实微信接口：需要甲方提供 AppID 与测试环境，未提供前标为未验证。

## Out of Scope

小程序原生页面开发（由甲方负责）；微信支付；订阅消息；unionid 跨应用打通。
