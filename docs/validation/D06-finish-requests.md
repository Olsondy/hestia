# D06 客户提交方案需求并获得方案验证

日期：2026-11-02。范围：工单 #35（服务端）。本机 PostgreSQL 14（独立库），未启动 Next.js 或常驻 Worker；出图使用真实执行函数并注入 PNG（不启动浏览器），DXF 转换使用真实 `python -I` 转换器。

## 实现要点

- **方案需求**（`finish_requests`，迁移 0026）：归属企业工作空间与客户，记录来源（示例别墅或图纸）、所选饰面、偏好石材（1–3 款）与备注；本身即企业线索。每个需求有自己的项目（建在企业工作空间内，创建者为客户）。
- **方案生成**（`packages/finish-requests/src/generate.ts`）：确定性规则，不调用生成式 AI。三种风格（留白：大板直铺加深色波打线；暖调：方砖斜铺；肌理：条板人字铺），各用一款偏好石材，规格受石材可供范围约束；墙面工字铺、楼梯直铺；单个饰面排版被拒时退回直铺；相同方案去重。全部经 D04 排版校验。
- **出图**：每个方案入队一张后台效果图（渲染来源新增内部类型“铺贴方案”），关页后照常完成，重开可查询状态。
- **审核与发布**：方案全部可采用且企业未设置“全部审核”（`workspaces.settings.reviewAllRequests`）时自动发布；否则进入待审核并记录原因。成员接口发布时只保留通过校验的方案。客户只看得到已发布方案。
- **图纸来源**：客户先建需求再上传图纸；DXF 后台转换（D05），非 DXF 为辅助转换。按已确认默认，图纸结果一律待企业审核；成员发布时以转换候选作为项目空间，每个房间派生一个地面饰面（有楼梯则派生踏面），再生成方案并发布。尺度标为估算。
- **接口**：客户 `GET /api/client/{entry}/catalog`（公开）、`GET|POST /api/client/{entry}/requests`、`GET .../requests/{id}`、`POST .../requests/{id}/drawing`、`GET .../schemes/{schemeId}/image`；成员 `GET /api/workspaces/{id}/leads`、`POST .../leads/{requestId}/publish`。
- 另：`validatePlacement` 的楼层化等 D04 改动保持；`createFloorplanImport` 新增仅供已授权调用方使用的选项，客户经需求服务上传图纸。
