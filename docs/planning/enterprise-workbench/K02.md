## Problem Statement

方案只包含铺贴，客户无法比较软装风格，确认时也只确认了硬装。

## Solution

方案扩展为整体方案（硬装 + 软装）：规则生成时带默认软装风格并给出 2–3 套可选风格；客户可在其中切换，生成新修订并确定性出图；确认绑定包含软装的修订。

## User Stories

1. As a 客户, I want 在方案给定的几套软装风格之间切换, so that 选出喜欢的整体效果。
2. As an 企业成员, I want 客户确认的修订包含硬装与软装, so that 交付时知道客户选了什么。

## Implementation Decisions

- 方案修订记录铺贴设计与软装（风格引用 + 家具布局）；方案视图返回当前软装风格与可选风格列表。
- 新增客户调整类型“切换软装风格”，沿用 D07 的修订、撤回、确认与幂等；切换后后台出图。
- 规则生成：每个方案选一套默认风格，可选风格为企业目录中适配该空间的 2–3 套。
- 客户端不调用生成式 AI；家具布局由风格规则或成员 / Agent 确定，客户不能自由摆放。

## Testing Decisions

- [x] HTTP + PostgreSQL：切换风格生成新修订、撤回、确认后再切换需重新确认、非法风格被拒、非绑定客户不可调整。
- [x] 后台任务：切换风格出图，重复投递不重复生成。见 [K02 验证](../../validation/K02-whole-schemes.md)。

## Out of Scope

客户替换单件家具；界面（H02）。
