## Problem Statement

H5 客户端是企业演示的主要界面，用户要求先看交互原型，确认后才开始实现。

## Solution

交付一份手机优先、可点击的 H5 交互原型，使用演示数据，不接服务端，覆盖两条入口的全部页面与状态，供用户审阅。

## User Stories

1. As a 产品负责人, I want 在手机上点完客户自助入口的全部页面, so that 判断流程是否顺畅。
2. As a 产品负责人, I want 点完打开分享链接、预览、登录与绑定的流程, so that 判断绑定方式是否合理。
3. As a 产品负责人, I want 看到等待出图、待审核、需辅助转换、验证码错误、绑定失败等状态, so that 异常情况也被设计过。
4. As a 产品负责人, I want 原型使用家居杂志方向与仓耳渔阳体, so that 视觉与产品一致。

## Implementation Decisions

- 页面：企业入口首页、手机号登录（含演示验证码提示）、提交方案需求（示例别墅或上传图纸、选择空间与石材）、出图等待与待审核、方案结果（效果图、3D 查看占位或演示、方案对比）、选项式调整与撤回、确认与留言、分享预览、绑定（定向自动绑定、绑定码、提交申请）、我的项目。
- 原型放在 `example/prototypes/` 下的独立目录，与生产代码隔离；数据为演示 fixture，明确标注演示与示意素材。
- 延续 DESIGN.md、家居杂志方向与仓耳渔阳体，使用 Impeccable，不启用 hooks。
- 原型只用于审阅交互与视觉，不作为生产实现的代码基础。

## Testing Decisions

- [ ] 真实浏览器手机视口（含常见窄屏）逐页截图，覆盖全部页面与列出的状态。
- [ ] 用户审阅并明确同意；审阅意见与结论记录在本工单。未获同意不得开始 H01。

## Out of Scope

服务端接入、真实数据、成员工作台、小程序。
