## Problem Statement

企业反馈问题时，我方需要看到企业工作台里的实际情况。按 ADR-0018 补充，超级管理员可以只读进入任一企业的工作台，但目前企业工作台只认本企业成员，所有读写都按成员关系判断。

## Solution

超级管理员在企业域名上用自己的邮箱登录后，以“平台支持”身份只读进入该企业工作台：能看、不能改；每次进入写审计，企业管理员能在「企业设置 · 访问记录」里看到。

## User Stories

1. As a 超级管理员, I want 从后台企业页进入任一企业的工作台查看, so that 排查企业反馈的问题。
2. As an 企业管理员, I want 看到我方每次进入的记录, so that 知道谁在什么时候看过什么。

## Implementation Decisions

- 企业域名上的会话：超级管理员的平台账号视为该企业的“平台支持”访问者，不加入、也不出现在成员列表（`sessionFor`、`accountBelongs`、`project_access` 的读能力）。
- 只读在服务端强制：工作台的所有写接口对平台支持一律返回拒绝（403 `READ_ONLY_SUPPORT`），不依赖页面隐藏；读接口与成员同样的范围。
- 每次进入（新会话首次打开工作台）写平台审计与企业侧访问记录：谁、何时、看了哪些页面。
- 页头标“平台支持 · 只读”，写操作的按钮禁用并说明；企业设置新增「访问记录」（仅企业管理员与平台支持可见）。
- 后台企业页「进入工作台（只读）」打开该企业的登记域名 `/w`。

## Testing Decisions

- [ ] HTTP + PostgreSQL：超级管理员在任一企业域名可读；平台管理员（非超级）、其他企业成员不可；所有写接口返回 403；不出现在成员列表；进入记入审计与访问记录；撤销后立即失效。纳入 M06 隔离矩阵。
- [ ] 真实浏览器：只读标识、禁用的写操作、访问记录 1440。

## Out of Scope

代企业修改数据；访问原因填写与企业审批。
