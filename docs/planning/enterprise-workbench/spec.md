## Problem Statement

家装 H5 演示（#29，原“石材硬装 H5 演示”）只交付了客户端：客户提交需求、查看与调整方案、确认，以及打开企业分享的方案并绑定（现为分享码，ADR-0012）。企业一侧的工作——查看线索、审核自动结果、发布方案、为客户预置方案并分享、处理绑定申请、跟进客户——目前只有服务端接口和种子脚本，企业成员没有可用的界面，演示时也无法展示“企业拿到线索之后做什么”。

## Solution

按 [ADR-0007](../../decisions/0007-shared-core-personal-and-enterprise-workspaces.md) 与 [ADR-0008](../../decisions/0008-one-stop-home-furnishing-hard-and-soft.md) 在通用**工作台**中实现一站式家装企业的成员界面（电脑端），视觉沿用已选定的家居杂志（editorial）方向，即 `example/prototypes/projects` 设计方向对比页中的“家居杂志”（B 版）。第一版覆盖：

1. 成员邮箱登录，进入所属企业工作空间。
2. 线索：客户提交、确认、留言与联系请求汇总为线索列表与详情，可记录跟进状态和内部备注。
3. 审核与发布：查看待审核的自动结果（含效果图），图纸需求先生成待审方案、成员核对后发布；非 DXF 图纸以辅助导入户型完成转换。
4. **Agent 辅助出整体方案**：在线索或预置方案中与 Agent 对话，产出硬装（铺贴）+ 软装（家具布局与软装风格）的候选方案，核对后发布。
5. 为客户预置示例别墅方案，并以分享码分享（可选指定手机号，ADR-0012）；撤销分享码、解绑客户、审批绑定申请，查看操作记录。
6. 查看企业石材库与软装风格目录（只读）。
7. 客户端补充：客户在方案给定的 2–3 套软装风格中切换并重新出图（不调用生成式 AI）。

工作台入口与开放注册仍由部署配置决定：面向企业客户的部署根路径进入客户端，成员通过 `/w/{企业标识}` 进入工作台。代码不按身份限制谁能进入工作台，权限由工作空间成员关系决定。

交付顺序：服务端补口先行；工作台界面先交付可点击原型，用户审阅通过后才开始实现，开始实现时通知用户。

## User Stories

1. As an 企业成员, I want 用邮箱登录并进入所属企业的工作台, so that 处理本企业的客户与方案。
2. As an 企业成员, I want 看到所有线索及其状态（待审核、已发布、客户已确认、待处理绑定申请、请求联系）, so that 知道先处理哪一条。
3. As an 企业成员, I want 按状态和跟进情况筛选线索, so that 不漏掉需要回电的客户。
4. As an 企业成员, I want 在线索详情里看到客户手机号、提交内容、偏好、方案效果图、确认的修订与留言, so that 联系客户前了解全部情况。
5. As an 企业成员, I want 记录跟进状态（新线索、已联系、跟进中、已成交、已搁置）和内部备注, so that 团队知道每位客户进展到哪一步。
6. As an 企业成员, I want 在发布前查看自动生成方案的效果图和排版提示, so that 客户只看到可靠的方案。
7. As an 企业成员, I want 为不能自动识别的图纸导入整理好的户型并生成方案, so that 辅助转换的需求也能出方案。
8. As an 企业成员, I want 为客户预置示例别墅方案, so that 不等客户提交也能先发方案。
9. As an 企业成员, I want 以分享码分享方案（可选指定手机号）并复制分享口令, so that 按企业规则把方案交给客户。
10. As an 企业成员, I want 撤销分享码、解绑客户、批准或拒绝绑定申请, and 看到记录, so that 处理发错、换人与冒认。
11. As an 企业成员, I want 查看企业石材库与软装风格, so that 知道客户可选的材料与搭配。
14. As an 企业成员, I want 让 Agent 按客户需求出硬装 + 软装的整体方案, so that 更快给客户可比较的方案。
15. As an 企业成员, I want Agent 的结果先作为候选，由我核对后发布, so that 客户只看到我认可的方案。
16. As a 客户, I want 在几套软装风格之间切换并看到效果图, so that 选出喜欢的整体效果。
12. As a 演示者, I want 演示数据里有处于不同状态的线索, so that 现场能讲清企业端的处理流程。
13. As a 维护者, I want 客户、未登录访客和其他企业成员都不能访问企业工作台的数据, so that 线索不外泄。

## Implementation Decisions

- 依据 ADR-0007 与 #29 的服务端能力（D01–D08）。工作台是通用模块：企业成员与个人用户共用账号体系与工作台外壳，企业功能按工作空间类型与成员关系显示。本次不改造个人工作台（Agent 对话、编辑）。
- **入口**：成员沿用邮箱密码登录；路由 `/w/{企业标识}`，登录后列出本人所属的企业工作空间。部署开关 `HESTIA_HOME_ENTRY` 只影响根路径，`/w/` 始终可用。成员账号由邀请创建（`pnpm invite`），本次不做成员管理界面。
- **线索**：线索即方案需求及其事件（提交、确认、留言、联系请求、绑定）。新增**线索跟进**：每条线索一个跟进状态（新线索 / 已联系 / 跟进中 / 已成交 / 已搁置）与按时间追加的内部备注（记录成员与时间），客户端不可见。跟进状态不改变方案和绑定。
- **审核与发布**：图纸需求改为两步——成员“生成待审方案”（导入候选采用为项目空间、派生饰面、规则生成并后台出图），核对效果图与排版提示后再“发布”。已有的一步发布接口保持兼容。非 DXF 图纸经现有辅助导入户型接口完成转换后进入同一流程。
- **分享与绑定**：复用 D08 接口。创建分享时分享码与分享口令只显示一次，界面提示成员立即复制发给客户；撤销、解绑、审批都需要二次确认并写入记录。
- **石材库与软装风格**：新增成员只读接口，返回本企业石材目录与软装风格目录（含已下架版本标记）。上传、编辑企业真实素材不在本次范围。
- **整体方案（ADR-0008）**：方案 = 硬装（D04 铺贴）+ 软装（家具布局 + 软装风格）。规则生成的方案带默认软装风格；软装风格按房间类型给出家具组合与材质，支持多楼层别墅。客户端只能在方案给定的软装风格中切换，切换生成新修订并确定性出图。
- **Agent**：沿用 ADR-0002 / ADR-0005 的运行时、受限工具与候选采用链路，扩展到企业工作空间与多楼层；新增铺贴、软装风格与多楼层布局工具。Agent 在线索或预置方案的空间项目上工作，产出候选；成员采用为待审方案后才能发布。需要配置真实模型（`HESTIA_MODEL_*`），企业用量按工作空间额度。
- **效果图与 3D**：工作台复用后台效果图与 `scene-runtime`；成员查看待审核方案的效果图，不需要客户可见。
- **界面**：电脑端优先（1280–1920 宽），兼顾 1024 宽平板。视觉依据 B 版（家居杂志）：暖纸背景、褐墨正文、酒红强调、细分隔线、左侧叙事栏 + 右侧大幅画面、底部条目栏，仓耳渔阳体；实施 UI 时使用 Impeccable，不启用 hooks。原型先行，审阅通过后再实现。
- **演示数据**：扩展 `pnpm demo:seed`，经服务接口准备不同状态的线索（客户自助已确认并请求联系、DXF 待审核、需辅助转换、待批准的绑定申请），并为演示成员设置可登录的演示密码（仅本地演示）。Agent 演示需联网；另准备 Agent 预先生成的方案与对话记录，网络不可用时展示。

## Testing Decisions

测试只断言可观察行为与持久化结果，不镜像内部函数。

1. **HTTP + 真实 PostgreSQL**：跟进状态与备注的成员权限、客户与其他企业不可读写；图纸需求生成待审方案后客户仍看不到、发布后可见、重复操作幂等；石材库只读接口的成员权限。
2. **后台任务**：生成待审方案的出图与重复投递不重复生成。
3. **Agent（真实模型 + 合成样本）**：在企业空间项目上产出硬装 + 软装候选，工具越权与非法组合被执行层拒绝，候选需成员采用才可发布；无模型配置时界面如实提示。
4. **真实浏览器（电脑视口）**：成员登录 → 线索列表筛选 → 详情 → 跟进 → 审核发布 → 预置方案并分享 → 客户端输入分享码绑定 → 成员看到绑定记录；审批与撤销。视觉与获批原型一致，逐页截图复核。

服务端工单以第 1–3 类入口验收；界面工单以第 4 类验收。

## Out of Scope

成员手动拖拽编辑方案（由 Agent 工具代替）；企业真实石材与家具素材上传与管理；成员邀请与角色管理界面；客户端开放 Agent；小程序；真实短信；报价与用料估算；数据导出与统计报表；个人工作台改造。

## Further Notes

- 原型与实现都以 B 版（家居杂志）为视觉依据；客户端 H5 已采用同一方向，两端风格一致但版式不同（电脑端 / 手机端）。
- 本规格不依赖暂停中的工单。
