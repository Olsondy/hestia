# 企业分享方案改用分享码，不发 HTTP 链接

D08 的分享有两种：定向手机号分享发一条 `/s/{token}` 链接；绑定码分享发链接，另外单独告知 6 位绑定码（48 小时）。用户于 2026-11-03 决定改为只发分享码：客户在企业的 H5 或小程序**内部**输入或粘贴码打开，后续小程序可以从剪贴板识别。本决定覆盖 D08 中“分享链接”和“一次性绑定码”的部分；绑定只归一位主客户、成员审批、撤销与解绑、全程记录不变。

## 决定

- **分享码**：每次分享生成一个 8 位码，字符集去掉易混的 0/O、1/I/L，共 31 个字符（约 8.5×10¹¹ 种）。显示为 `XXXX-XXXX`，输入时不区分大小写，横杠和空格可有可无。服务端只保存码的 HMAC，码只在创建时返回一次，遗失后撤销再分享。
- **分享口令**：成员复制出去的是一段口令，例如“【演示家装企业】方案分享码 HX7K-9QP2，在企业的小程序或 H5 首页输入即可查看”。识别时只取“分享码”后面的码，或者整段内容本身就是一个码，其余文字忽略，避免误识别剪贴板里的其他内容。识别出码后先向服务端校验，有效才提示打开。
- **打开**：输入码即可预览，不需要登录，只能看（效果图、方案对比、饰面清单，不含客户手机号、留言和内部信息）。调整、确认、留言前用手机号登录并绑定。
- **绑定**：成员分享时可以选填客户手机号。填了，用该手机号登录即自动绑定；换其他号码登录只能提交绑定申请，由成员批准。没填，第一位登录的客户直接绑定。绑定后这个方案的所有分享码都失效，绑定的客户从「我的项目」进入；成员解绑后，尚未使用的码恢复可用。
- **有效期**：成员选 7、30 或 90 天（默认 30），有效期内可以反复打开预览；成员可以随时撤销。不再有单独的 48 小时绑定码。
- **防猜**：错误的码按来源计数（来源取可信代理头，与手机验证码相同的 `HESTIA_OTP_SOURCE_HEADER`），默认 15 分钟内 10 次后暂停（`HESTIA_SHARE_CODE_MAX_FAILURES`、`HESTIA_SHARE_CODE_WINDOW_SECONDS`）。过期、撤销、已使用的码属于正确的码，不计入。
- **入口**：H5 首页和「我的项目」提供“输入分享码”，可以手动输入，也可以点“粘贴”从剪贴板读取（浏览器要求用户点击后才能读）。H5 内部打开码的页面为 `/s/{码}`。小程序（另行开发）在回到前台时读剪贴板识别口令，再用 web-view 打开 `/s/{码}`。这个地址只在应用内部使用，不发给客户。

## 影响

- `request_shares`：`token_hash` 改存分享码的 HMAC；去掉绑定码字段（`code_hash`、`code_expires_at`、`code_attempts`），`code_used_at` 改为“已使用”（绑定时写入）；新增 `share_code_failures` 记录错误尝试。旧的链接 token 不符合分享码格式，迁移后失效（尚无生产数据）。
- 接口：成员分享返回 `code` 与 `message`（口令），不再返回 `url`、`token`、`bindingCode`；客户绑定不再带 `code`。公开预览、场景与效果图接口的路径参数改为分享码。
- H5：去掉“输入绑定码”页，绑定页到达后自动尝试绑定；首页与「我的项目」增加输入分享码。
- 工作台（W04）：分享弹窗展示分享码并提供“复制分享口令”；P02 原型中的链接与绑定码按本决定实现，不改原型。

## 考虑过的替代方案

- **保留链接，另加分享码**：两套入口要维护，链接在微信里也容易被转发，用户明确不要链接。
- **只发码、取消指定手机号**：最简单，但码转给别人后，企业无法控制方案归谁。
- **先登录再输码**：更封闭，但客户在看到方案前多一步登录；码本身已经足以作为预览凭证。
