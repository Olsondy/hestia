# T17：有界单房间布局候选

2026-10-27。后端、真实模型合成调用、浏览器与独立复核均通过，主 Agent 已完成本地验收。范围限于下述单房间能力，不代表真实住宅泛化或完整整屋流程。

## 实现范围

沿用统一 `conversation-v1` / `resolve_turn`，模型仅提出 `propose_layout`，不提供逐件坐标或执行回调。提案绑定房间、当前真实用户输入及全部有来源硬需求；应用核对完整当前消息，旧需求、引述、假设、问句或“只整理、暂不生成”不能扩大本轮任务范围。词汇核对是保守的有限能力边界，未覆盖的要求进入澄清，不声称任意自然语言授权已经被证明。

`packages/layout-planner` 使用纯 TypeScript 搜索，支持尺度为 calibrated 或明确 synthetic 的单个轴对齐矩形房间。当前功能为会客和办公；复杂房形、未确认尺度、缺入口或门扇信息、无确定性检查覆盖的硬需求都不生成合格推荐。房间最大边长 20m，既有家具与固定对象各至多20件。

原有实物全部保留身份、规格、材质和高程；只调整允许移动对象的平面位姿。原位条件与锁定对象保持不动。已有功能家具可复用；缺少的沙发、桌和椅仅以受控目录默认规格补充。不会通过删除、换件或缩小现有实物凑出结果。

有界搜索最多6000节点、24个完整候选检查、2500ms；低于这些上限的测试预算可以提前终止，不能调高平台上限。有限搜索失败为 `not_found`，保留未检查状态和原因，不强造推荐。搜索不调用模型，记录节点、完整候选检查数、修正尝试数、时长、待澄清数；真实模型用量由统一运行器另外记账。

## 检查与候选生命周期

复用现有完整家具几何检查，并增加已有实物保留、原位保留、功能家具、桌椅使用关系与入口到沙发前/工作椅后连续通道检查。通道采用0.7m方形扫掠与0.35m网格，AABB障碍物和扫掠可能保守拒绝可行的斜向路径。这是有限几何规则，不是人体工学、无障碍、施工或结构安全认证；这些项仍明确未检查。

房间检查要求四个不同矩形角点、墙体端点落在房间边界范围内；边界同一直线但位于房间外的墙/开口不能通过夹取坐标冒认为室内入口。

规划结果进入真实候选，`0012-layout-planner.sql` 的 `planner_context` 保存规划版本、来源任务/意图、功能对象、保留条件及需求引用。候选内容哈希包含该上下文；编辑后旧检查和展示授权失效，采用前重新核对完整几何与规划检查。用户没有采用时当前方案不变。

同一项目修订不变而用户意图版本更新时，旧推荐也标为 stale，并拒绝重新检查、展示或采用。采用沿用现有真实浏览器展示/选择记录，不能由 Worker 伪造用户选择。采用事务按 task→project 顺序锁定，并仅结束匹配候选身份与来源意图的 `waiting_selection` 任务，不能结束新意图。

本轮审查修正了用户编辑推荐到revision2后再采用会使任务永久停在waiting_selection的问题。任务结束不再要求生成时旧revision等于用户实际选中的新revision；采用仍绑定当前有效展示/选择。任务保留原始candidateRevision与planReport，实际采用版本写入采用记录和权威事件，避免将旧推荐报告改标为编辑后版本。整体撤销仍使用现有采用记录。
