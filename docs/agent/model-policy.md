# Hestia 模型执行策略与验证计划

状态：draft-0.1，2026-10-25。依据 [ADR-0002](../decisions/0002-agent-led-consumer-workflow.md) 已确认的 Q7、Q8：首版仅平台模型，复杂设计优先质量，局部修改优先速度。本文不指定未经实测的供应商、型号、价格或响应时间。2026-10-25 更新：T01 已完成配置模型的真实 API 合成小样准入，参数和范围见 docs/validation/T01-model-protocol.md；T02 识图仍未通过，不把小样结果扩展为整屋设计能力。

## 1. 两种执行配置，同一套执行约束

执行配置由应用选择，用户不用学习型号、推理参数或工具。配置影响上下文、调用预算和任务组织，不改变对象权限、固定事实、候选隔离、几何检查、版本检查或提交授权。

| 配置 | `design_quality` | `edit_fast` |
| --- | --- | --- |
| 适用目标 | 初次空间理解、功能安排、跨对象布局、风格探索及方案比较 | 目标明确的单件移动、旋转、明确材质修改；以及相应局部反馈 |
| 用户例子 | “把客厅改成能会客又能办公的空间” | “把选中的书桌沿图纸向右移 20 厘米” |
| 工作方式 | 分阶段推进候选，核对需求，必要时提出有意义的备选 | 读取目标及必要周边信息，形成最小改动，检查并提交或说明冲突 |
| 默认候选 | 一个完整推荐，有实质取舍时最多两套 | 一个局部差异，不生成多套整屋方案 |
| 上下文 | 相关房间、需求、固定事实、尺度、目录和阶段结果 | 选中对象、方向与单位、相关约束、周边占地和最新修订 |
| 优先优化 | 需求满足、取舍合理、纠正次数和最终空间质量 | 正确完成一次修改所需的端到端等待时间 |
| 预算策略 | 可允许更多设计步骤，但受阶段与任务上限控制 | 避免无关查询、整屋重算和冗长回复，仍保留必要检查 |

这两种配置可以先使用同一个经过评估的模型，也可以在有证据时采用不同模型；不因此建立多个自主 Agent。某种模型若不支持需要的参数，不能在适配器中假装参数已生效。

视角切换、选择已展示方案、取消和查询状态等应用动作，在目标及权限已能确定时直接调用应用能力，无须强制经过 LLM。对自然语言理解存在歧义时可以借助模型提出解析，但解析结果仍受相应授权检查，不从任意文本关键词直接执行。

## 2. 路由与能力升级

路由参考可信的用户请求、任务阶段、编辑目标、所需工具能力和范围；不能根据句子长短、模型自报置信度或图纸中的文字决定权限。

| 条件 | 行为 |
| --- | --- |
| 唯一目标、明确变化、属于允许的局部操作 | 使用 `edit_fast`；所有校验和自动应用条件照常执行 |
| 请求替换/删除具体家具 | 可用局部配置生成最小候选，但仍遵循成果确认，不因配置较快就自动提交 |
| 涉及多对象取舍、功能需求、空间初稿或开放式审美 | 使用 `design_quality`，在候选内连续推进 |
| “再舒服一点”等看似简短但需推敲的要求 | 结合上下文判为设计任务，不按字数误归局部操作 |
| 对象/方向/必要信息有歧义 | 先查询或澄清；不能仅靠更强模型猜测用户选择 |
| 局部操作出现明确碰撞 | 报告冲突与替代；不自动升级为重排房间 |
| 已授权任务确需更强模型或更多上下文 | 可升级模型配置，但保持任务范围、总预算、候选和确认规则 |
| 新要求扩大房间或改变目标 | 应用依据真实用户输入更新范围和意图版本；不能由模型自行扩大 |

路由解析本身也是模型评估对象。即使解析器误分类，执行器仍需拒绝未授权操作；工具清单按配置进一步收窄，不能把“路由正确”当成唯一保护。

为减少局部延迟，可避免重复生成不相关视图和候选，但不能漏掉受影响邻近对象的检查。复用事实或检查结果必须验证项目、对象、规则和来源修订；用户身份、权限及项目边界不能因缓存被省略。

## 3. 平台模型配置与版本记录

平台配置包含供应商与端点、模型标识、适配器版本、输入能力、工具调用能力、支持的生成参数、超时、允许重试和预先验证的回退配置。配置由平台维护，用户和模型都不能通过提示词提交新的端点。

模型凭据只由服务端持有。首版不设计 BYOK 设置页、用户模型连接表单或浏览器模型直连回退；平台暂时不可用时保留项目与候选，不要求用户临时提供 Key 才能继续使用已有成果。

每项任务记录执行配置、模型与参数、prompt、工具契约、规则和资产版本。任务中的配置变化留记录，不让升级或回退悄悄改变模型行为而无法追查。应用提供可用工具的权威定义，system prompt 不重复维护另一套可能失配的参数 Schema。

## 4. 接口装配与真实结果回传

调用模型时按职责分开提供：固定 system prompt、当轮执行配置、任务范围与最新状态、必要用户消息、工具定义和最近工具结果。项目名称、图纸文字和目录描述始终是资料，不提升为系统指令。

| 输入/输出 | 归属及处理 |
| --- | --- |
| 执行策略、权限、剩余预算与确认记录 | 应用生成；模型只能读取，不能在调用中覆盖 |
| 项目和候选快照 | 查询工具提供，带修订及来源；长上下文压缩不删除锁定、未决问题或关键需求 |
| 文本回复 | 展示给用户，不作为执行命令；最终完成状态须与实际工具结果一致 |
| 工具调用 | 原生结构化调用；完整接收、去重、校验后交给执行器 |
| 工具结果 | 执行器的真实结果回传给模型，保留调用关联，不用模型编写的结果冒充 |
| 请求中断、拒答、截断或无法解析 | 按实际状态处理；不从残缺 JSON 中凑参数，不将拒答当成成功 |
| 用量与请求引用 | 由适配器记录；缺失则标为未知或待核对，不填零伪装低成本 |

统一协议是内部抽象，不承诺所有供应商天然等价。接入验证要覆盖图像、长请求、流式工具参数、结束原因、重复事件、拒答、超时、限流和用量缺失。

## 5. 失败修复、回退与质量边界

- 参数可修复错误在既定次数内返回具体原因；语义歧义交给澄清，不能用反复采样代替用户选择。
- 配置不支持所需工具或图片时，不送入该任务，也不静默改为仅靠自然语言执行。
- 供应商不可用时，仅允许切到已经通过对应任务评估的配置；没有合格回退则保存成果并说明中断。
- 不为省成本把复杂设计悄悄降为未验证的快速模型；任务上限不足时收束已有成果，不能绕过上限追求“质量”。
- 回退和重试继续消耗原任务预算。超时后的外部请求先核对已知状态，迟到结果按执行代次拒绝，避免多个模型重复推动同一修改。
- 模型升级不改变用户已采用方案；新模型从当前事实继续处理新要求，不重绘既有项目来“统一风格”。

“优先速度”不是承诺固定秒数，“优先质量”不是无限重试，也不是必须多模型投票。是否增加识图专用模型或独立质量检查调用，应由实际失败类型和收益决定。

## 6. 对比评估与准入证据

使用 [运行设计](runtime-design.md#9-首版验收矩阵) 的单层图纸集，另为每个任务配置成功、歧义、失败和恢复场景。对比时固定用户需求、项目版本、工具与资产；记录采样设置及重复次数，不将一次成功视为稳定能力。

### 强制执行门槛

以下关键反例必须通过，发现失败即阻止该配置进入试用：越权修改、固定事实绕过、跨项目访问、过期确认提交、重复移动、取消后越过提交边界、把估算尺度当真实尺度、错误声明执行成功。验收依据执行记录和项目差异，不只看助手最后一句话。

通过已知反例不等于证明永不出错。持续收集真实失败并加入回归集；不能用高平均分掩盖一项关键执行缺陷。

### 设计质量与局部效率

| 指标 | 记录方式 | 选型用途 |
| --- | --- | --- |
| 需求满足 | 对明确需求逐项记录满足、部分满足、未满足和取舍说明 | 复杂设计优先比较，不由模型独立给自己打分 |
| 图纸可靠性 | 墙/门窗/尺寸错误、遗漏、冲突发现和人工修正耗时 | 确定图像模型与预处理工具是否足够 |
| 方案质量 | 人工看空间和静态图，比较功能安排、家具组合、风格一致性及可解释取舍 | 数据正确之外的核心结果，不只看文字是否漂亮 |
| 自主完成 | 不必要追问、重复确认、用户纠正次数和无帮助的循环 | 检查是否真正完成整项任务 |
| 局部准确性 | 目标、方向、单位、实际差异和撤销结果 | 快速配置必须先正确，再比较延迟 |
| 端到端时间 | 从用户请求到可检查候选或已提交局部结果，包含工具、重试和展示 | 不用首 token 时间代替用户实际等待 |
| 成本 | 整任务模型、重试、检查及渲染用量，未知用量单独列出 | 形成可持续的任务上限，而非只比单次 token 价格 |
| 恢复可靠性 | 中断、重启、关页、过期租约和新需求到达后的结果 | 验证后台任务契约 |

复杂设计：先满足执行门槛与可用质量，再比较任务质量、纠正负担与成本/耗时。局部修改：先满足同样执行门槛和准确性，再优先降低端到端时间。评估样本量不足时如实报告，不把少量样本的延迟百分位写成上线 SLA。

评估产物应包括样本定义与预期、实际项目差异、必要截图、操作轨迹、配置版本、用量及错误分类。记录不得包含 API Key 或未经授权的原始住宅资料。当前仅定义产物，不创建虚构的评估结果或通过标记。

## 7. 技术验证清单与设计完成条件

下列事项需要后续获得实施/验证授权后处理，不继续要求用户凭空选择参数：

| 待验证事项 | 需要得到的证据 | 对设计的可能影响 |
| --- | --- | --- |
| 候选模型能力 | 相同业务样本的质量、局部准确性、延迟和用量 | 选择主模型/配置，是否需要独立识图或快速模型 |
| 识图工具复用 | 外部脚本对范围内样本的输出、依赖和失败类型 | 固定工具封装、人工纠正流程及输入支持范围 |
| 渲染器适配 | 两套不同户型、增量修改、状态回传、静态图及版本一致性 | 采用外部预览组件或改造现有渲染器 |
| 后台持久化 | 关页、重启、重复投递、取消与提交竞争的可复现场景 | 调度、事务及检查点的具体实现 |
| 几何与尺度 | 门窗、旋转占地、通路、尺度冲突和固定事实反例 | 校验能力覆盖与首版可用输入 |
| 任务上限 | 完整任务用量分布、外部用量未知和高成本失败 | 数值预算、并发和有界重试配置 |

当前 Q1–Q8 已足以形成产品与执行边界基线；无需再为每个工具或技术参数新增确认轮次。供应商、库版本和数值限额是验证后填写的配置，不是让用户猜的产品决策。若验证证明已确认目标无法在约束下实现，再带证据讨论对应取舍。

初稿形成时仅交付设计文档。用户随后已批准按工单实施；当前完成范围以工单与 docs/validation/ 为准，T01 小样准入不替代整屋设计与恢复链路验收。部署仍未确认。
