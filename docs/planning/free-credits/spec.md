## Problem Statement

用户希望先通过公开示例了解 Hestia，注册后获得一份免费额度，用自己的户型完成设计和少量调整。当前生产入口仍要求邀请，未登录者没有公开示例入口，也没有注册赠送、积分余额和任务扣退规则。维护者需要先验证真实模型成本，不希望首期建设管理后台、匿名账号合并或付费套餐。

## Solution

首期提供“游客看示例 → 注册并登录 → 一次性获得免费积分 → 使用自己的户型设计”的流程。游客不建立匿名账号、不领取积分、不创建个人云项目、不调用真实 AI。注册用户以简单固定积分档位使用 AI；已有成果的查看、手动调整和无需 AI 重新生成的导出继续可用。

积分配置先由维护者通过数据库维护，程序自动发放、预留、扣除和退款。试用初始配置为问答 1 分、小改 5 分、整套设计 20 分、注册赠送 40 分；这些数字是可调整的占位配置，后续由真实供应商用量和费用反推，不代表已验证的上线价格。

## User Stories

1. As an 游客, I want 不登录就能浏览和操作公开示例, so that 我能了解产品是否适合自己。
2. As an 游客, I want 清楚知道示例是演示内容, so that 不会把它当作我的户型识别结果。
3. As an 游客, I want 在准备使用自己的户型时进入注册或登录, so that 能将资料保存到明确的个人账号。
4. As an 新用户, I want 无需邀请码即可注册, so that 可以自主开始体验。
5. As an 新用户, I want 注册成功后一次性获得免费积分, so that 可以先体验设计而不购买套餐。
6. As an 注册用户, I want 重复提交注册请求或再次登录不会重复发放, so that 余额与发放记录保持一致。
7. As an 注册用户, I want 查看自己的可用、任务占用和已扣积分记录, so that 知道额度用在了哪里。
8. As an 注册用户, I want 我的余额、项目和文件不能被其他用户访问, so that 自己的资料和权益受到保护。
9. As an 注册用户, I want 在接受 AI 工作前看到本次固定积分消耗, so that 能决定是否开始。
10. As an 注册用户, I want 问答、小改和整套设计使用少量易懂档位, so that 不必理解模型 token 或工具调用次数。
11. As an 注册用户, I want 同一项工作必要的追问和内部修正包含在原价格内, so that 不会因为回答助手问题而被反复扣分。
12. As an 注册用户, I want 积分不够时在任务接受前得到说明, so that 不会启动无法承担的任务。
13. As an 注册用户, I want 多个任务不会重复使用同一份可用积分, so that 余额不会因并发变成负数。
14. As an 注册用户, I want 排队时只占用积分, so that 尚未开始调用模型时取消仍可释放全部占用。
15. As an 注册用户, I want 在首次开始调用模型时扣除本次固定积分, so that 收费边界清楚可查。
16. As an 注册用户, I want 知道调用模型后主动取消仍扣本次积分, so that 能理解停止任务的结果。
17. As an 注册用户, I want 关闭页面后任务继续且余额可恢复查看, so that 不必守着页面或重新发起任务。
18. As an 注册用户, I want 自动重试、重复事件和进程恢复不重复扣分, so that 平台故障不会增加我的支出。
19. As an 注册用户, I want 系统最终失败且未完成约定交付时退回全部积分, so that 不为失败任务支付积分。
20. As an 注册用户, I want 系统最终只完成一部分时保留可用成果并退回全部积分, so that 能继续利用已有工作。
21. As an 注册用户, I want 成功交付候选后按原价结算, so that 是否采用候选与扣分结果不会混淆。
22. As an 注册用户, I want 积分耗尽后仍能打开已有成果、手动调整和导出已有文件, so that 已完成的设计不会被锁住。
23. As an 注册用户, I want 首次赠送积分没有有效期, so that 可以按自己的装修节奏使用。
24. As an 注册用户, I want 已接受任务的报价不因后台调价而改变, so that 扣分和退款都有稳定依据。
25. As an 维护者, I want 在数据库修改各档分值和新用户赠送量, so that 不需要先建设管理后台。
26. As an 维护者, I want 区分用户积分记录和供应商实际用量, so that 能根据真实成本校准积分。
27. As an 维护者, I want 记录自动重试、失败和取消的实际用量, so that 不会只按成功任务低估免费体验成本。
28. As an 维护者, I want 首期不建设支付与订阅页面但保留发放来源, so that 以后可扩展订阅而不必推翻余额记录。

## Implementation Decisions

- 阶段：M1 身份与数据边界、M2/M5 模型任务结算、M6 用户流程验收；作为既有 V1 总规格 #1 的增量范围。依据 ADR-0006，覆盖 ADR-0004 的邀请制上线限制；其他平台模型、固定事实、持久化 Worker 和项目归属约束继续执行。
- 分两条用户能力交付：C01 负责游客示例、开放注册、一次性赠送和可查询余额；C02 负责任务报价、预留、扣除、取消、退款及余额不足后的成果访问。每票包含必要数据、服务、页面和验证，不按前后端目录拆分。
- 沿用现有身份会话、项目授权、PostgreSQL 事务和持久化 Worker，不建设匿名身份、游客个人项目或账号合并。现有账号继续可登录；历史账号不因登录而自动补发“新用户奖励”，历史数据补发不在本票范围。
- 新增可维护的积分规则、账号余额及可追溯的积分变动记录。赠送与任务记账有稳定业务标识、唯一性和并发保护；用户不可通过客户端提交任意余额、档位金额或修改配置。具体表结构由实施时按既有数据模式确定。
- 首期没有管理后台，配置通过数据库维护；提供初始配置与操作说明。配置更新影响之后接受的新任务及之后注册的新用户，不重算既有余额、已发奖励、已接受任务报价或退款金额。
- 接受任务时原子检查并预留本次固定积分；余额不足不能留下已接受任务或账务残留。同账号跨项目并发共用同一可用余额。
- 首次真正开始调用模型时，预留转为扣除一次。队列领取、进入 running、执行纯本地步骤、渲染或流式输出开始均不能替代该边界；现有确定性任务运行器不启动模型，不能拿它的状态冒充接口已调用。
- 扣分覆盖同一项工作的必要澄清、模型多步调用、检查、修正和有界自动重试。报价和任务范围确定后不临时追加积分；展示报价不改变已确认的候选采用与局部直接修改规则。
- 调用前主动取消释放预留；调用后主动取消保留本次固定扣除。取消引起的调用中断不能伪装为系统失败退款。关闭页面不是取消。
- 正常完成保留扣除，无论用户是否采用或喜欢候选。系统最终 failed 或非用户取消的 partial 且未完成约定交付时全额退回，保留已有成果；有界重试尚未结束时不提前退款。重复终态、回复丢失和恢复不得重复扣除、释放或退款。
- 复用既有任务终态与取消记录，通过持久化顺序判定取消和失败竞争，不新增一套互相冲突的运行状态机。保留真实已提交的设计修改，取消不等于撤销。
- 用户积分和平台模型/计算预算分别管理，不能把现有 protocol-step 用量当作积分或供应商 token。供应商未知用量仍按既有预算规则核对，不影响对用户既定退款义务的正确处理。
- 原型和生产公开示例均使用非私密演示内容。页面继续采用家居杂志方向与仓耳渔阳体，沿用已有设计规范；实施 UI 时使用已指定的 Impeccable，不启用 hooks。
- 用户已要求停止逐场景细分：混合问答与修改的合并计费、小改批量边界、验证邮箱后发放等讨论建议不是已批准规则，不得作为额外门槛写死。实施按这三类工作入口显示明确报价，细节按真实流程收窄，不能静默增加档位、按家具逐件计费或承诺无限修改。

## Testing Decisions

用户于 2026-10-25 明确认可以下三个主要验收入口。测试只断言用户可观察行为与持久化结果，不镜像内部函数或为简单文案增加测试。

1. 注册／项目 HTTP + 真实 PostgreSQL：复用已有身份集成与项目 API 验证。确认公开注册一次性赠送、重复请求/登录不重送、余额和资源归属隔离、游客不能创建个人项目或调用 AI，浏览示例不创建匿名身份、项目或积分。
2. 任务公开服务 + 真实 PostgreSQL／pg-boss：复用已有后台任务的并发、取消、故障恢复和幂等案例。在真实供应商适配边界使用可控协议替身注入开始调用、失败与迟到，数据库、队列和执行器真实运行。验证跨项目并发预留、余额不足无残留、调用前后取消、系统 failed/partial 全额退款、自动重试和恢复不重复扣退，以及配置变化不改变旧任务金额。
3. 真实浏览器最短流程：游客看示例 → 注册并看到赠送积分 → 使用个人项目提交任务并观察占用/扣分/退款 → 积分耗尽后继续查看已有成果。覆盖刷新恢复、桌面及手机的可用性与视觉检查；自动测试不能替代视觉验收。

真实供应商成本校准单列：用授权样本与实际供应商账单核对任务用量，包含重试、取消和失败；协议替身只能证明结算逻辑，不能证明模型质量或分值合理。完整整套设计成本验证依赖既有真实设计链路，未具备时标明未验证，不伪造通过。

验收时先检查已有服务。没有用户授权不得新启动或重启 Web、数据库或 Worker；需要隔离进程恢复演练时沿用既有显式授权方式。此工单创建不授权启动服务。

## Out of Scope

匿名账号与积分、游客个人项目、匿名身份升级、游客数据迁移、匿名与注册奖励叠加、账号合并；管理后台、支付、充值、订阅套餐实现、周期赠送、签到或邀请奖励；多档积分有效期、按执行百分比收费、按 token 向用户计费；重做身份框架或任务状态机；模型选型与购买、真实费用预先保证、正式部署与备案办理。既有原型本地项目不因此自动上传。
