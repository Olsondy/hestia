# 前期每家企业独立部署一套；平台方案保留但不推进

> 2026-11-10：“每家企业独立部署一套”由 [ADR-0017](0017-shared-hosting-tenant-isolated-accounts.md) 覆盖，改为我方托管一套共享服务；独立部署保留为企业明确要求时的单独选项。路径不带企业标识、代码保持多工作空间能力两条继续有效。

用户于 2026-11-04 明确：资金与资源不足以运营一个多企业平台，前期服务单独的企业，一家一套独立部署（各自的域名、数据库与后台服务）。平台化方案保留，但不是当前方向。

## 决定

- **部署单位是一家企业**：每套部署只服务一个企业工作空间，用 `HESTIA_HOME_ENTRY` 指定（ADR-0015）。它是独立部署的必填配置；根路径官网入口页的两扇门接到这家企业的客户端与工作台。
- **路径不带企业标识**（同日用户要求）：客户端 `/c/…`、工作台 `/w/…`，企业由 `HESTIA_HOME_ENTRY` 决定；旧的 `/c/{企业}/…`、`/w/{企业}/…` 链接自动跳转到新地址。后台接口 `/api/client/{企业}/…` 仍带标识。
- **代码保持多工作空间能力**：工作空间隔离、成员关系与接口里的企业标识照旧，不为单企业部署删减；将来转为平台时，在入口层恢复带标识的路由即可。
- **跨企业功能搁置**：`status.md` 中“账号全平台唯一”“个人工作台里列出企业分享给我的方案”“复制到个人项目”等依赖多企业同库的设想，在独立部署下不成立，暂不实现，保留为平台方案的记录。
- **个人工作台**：面向公众、不属于任何企业，首期不开放（见 `status.md`）；若以后开放，另行部署，不混入企业的部署。

## 影响

- 每套部署的运维、升级与数据各自独立；同一版本的代码分别部署到各企业。
- 企业品牌（名称、域名）属于各自部署的配置与数据，不写进代码，也不提交到仓库（AGENTS.md「Documentation Ownership」）。
