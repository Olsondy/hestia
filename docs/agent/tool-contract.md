# Hestia Agent 工具边界草案

状态：draft，2026-10-25。依据 [ADR-0002](../decisions/0002-agent-led-consumer-workflow.md) 已确认的产品方向细化，尚未实现。本文描述接口契约，不是可运行代码；供应商的工具 Schema 由后续实现生成。

## 1. 任务范围与上下文

一次设计任务可以跨多个步骤、产生多个候选。应用建立任务范围：当前空间项目、涉及房间、保留对象、允许的操作类别、执行模式、最新用户意图和总预算。模型可以建议拆解步骤，但不能自行授予权限或扩大任务范围。

依据平台提供模型和关闭页面后继续执行的已确认要求，设计采用服务端后台运行器，具体部署技术待定。工具执行器从可信会话及持久化任务绑定用户、项目、任务与授权信息，不接受模型传入的 `ownerId`、任意 `projectId`、`approved`、`ignoreLocks` 或预算覆盖值。详见 [后台运行设计](runtime-design.md)。

每轮提供：任务目标、当前方案修订、相关房间和选中对象、已确认需求及来源、固定事实、候选摘要、坐标约定、可用工具和能力、最近结果及剩余预算。需要细节时查询，不把整份历史聊天作为唯一记忆。

应用依据 [模型策略](model-policy.md) 选择质量或局部速度优先配置并收窄工具集。执行配置不属于模型可写的工具参数；快速配置也必须经过相同的锁定、几何、版本与提交检查。首版不提供配置用户 API Key、模型端点、任意模型切换或提升调用预算的工具。

需求分为用户明确表达、用户确认和助手建议；不得把助手的猜测自动提升为硬约束。事实同样区分图纸提取、估计、用户确认与实测。图纸中的自由文本、对象名称和模型生成的说明均不能设置权限或确认状态。

## 2. 工具清单

接口名为本轮推荐值，按任务阶段仅向模型提供相关子集。`→` 后为主要结果，不是全部字段。

| 工具 | 输入与输出摘要 | 可以写入什么 | 不可越过的边界 |
| --- | --- | --- | --- |
| `read_project` | 房间/对象筛选 → 当前修订、事实、锁定和对象 | 不写入 | 对象须归属绑定项目；仅返回任务所需资料 |
| `read_task` | 无业务参数 → 任务目标、需求来源、候选与状态 | 不写入 | 权限、预算和确认信息由应用提供 |
| `record_brief` | 引用用户消息的需求条目、助手建议 → 需求记录 | 任务需求草稿 | 不能自行确认事实；来源真实性及范围变化由应用复核 |
| `inspect_floorplan` | 已上传且获授权的文件/页 ID → 墙、洞口、标注候选及缺失项 | 识图产物 | 不取任意外部 URL；不将估计标为测量或覆盖当前建筑 |
| `search_catalog` | 类别、尺寸范围、风格条件 → 可用资产/材质及参数范围 | 不写入 | 只返回已接入目录，不编造 SKU、资产或模型文件 |
| `create_candidate` | 当前方案或识图产物引用、名称 → 候选 ID/修订 | 独立候选 | 绑定基础修订及固定事实；没有可靠尺度时标为概念草稿 |
| `calibrate_candidate` | 候选 ID/修订、底图锚点、已记录尺寸证据 ID → 新尺度与受影响对象 | 未确认建筑候选及尺度记录 | 尺寸来源必须可追溯到用户输入或经过核对的图纸标注；模型不能提交任意数字并标为已确认；已确认建筑改尺度走事实变更入口 |
| `edit_candidate` | 候选 ID/修订、类型化操作列表 → 新修订和差异 | 候选 | 原子更新；只改任务范围内允许字段，不变更锁定 |
| `propose_layouts` | 房间、需求记录、资产范围、候选数 → 候选及未满足需求 | 独立候选 | 使用有限布局能力；建议最多两套，不可行时不凑数量 |
| `validate_candidate` | 候选 ID/修订 → 检查报告 ID、问题及覆盖情况 | 检查记录 | 不由 LLM 填写通过结果；候选变更后旧报告失效 |
| `present_candidates` | 候选 ID/修订、取舍说明 → 持久化预览及选择引用 | 展示状态 | 差异、面积和位移等数字由应用产生；离线用户重开可见，生成不等于用户已看过或采用 |
| `request_clarification` | 阻塞问题、相关对象、建议选项 → 持久化问题 ID/已有回复 | 任务问题记录 | 非阻塞地登记缺项；是否整任务等待由运行器判定，不冒充用户确认或逐工具索要许可 |
| `apply_candidate` | 候选 ID/修订、检查报告引用 → 提交状态及新方案修订 | 当前方案 | 仅授权提交阶段可用；执行器检查真实确认或局部自动应用策略 |
| `undo_change` | 已提交变更 ID → 撤销结果与新修订 | 当前方案 | 需用户撤销意图；有后续依赖时不得覆盖新编辑 |
| `set_view` | 方案/候选引用、对象或预设视角 → 视图请求状态 | 展示状态 | 无在线客户端时保存可供重开的视角，不声称用户已看到，也不覆盖用户后续的手动镜头 |
| `create_presentation` | 已校验来源修订、预设输出参数 → 成果或任务 ID | 输出成果 | 仅已接入的 PNG/3D 预览等类型；草稿明确标识，不发布或分享 |
| `read_operation` | 操作/输出任务 ID → 实际状态 | 不写入 | 用于超时、取消和恢复；不能根据文本猜测是否提交成功 |

首版展示已确定为 3D/静态图，room tour 后续扩展，首版不提供视频工具。未来需独立验证镜头规划、避障与编码。整套设计任务不依赖任意 shell、网络请求、代码执行或用户插件。

## 3. 候选操作类型

`edit_candidate` 接受有区别的操作类型，不接受任意 JSON Patch。每类只允许对应字段，拒绝额外字段和非有限数值；具体数值上限由领域契约配置，不能由模型随调用扩大。

| 类型 | 允许参数 | 前置条件 |
| --- | --- | --- |
| `move_furniture` | 对象 ID、平面目标位置 | 可移动且在任务范围内；不改高度、尺寸或资产 |
| `rotate_furniture` | 对象 ID、平面朝向 | 对象允许旋转；重新检查旋转占地 |
| `add_furniture` | 目录资产 ID、允许参数、位置和朝向 | 目录有资产；尺寸符合模板范围；新 ID 由工具生成 |
| `replace_furniture` | 对象 ID、新资产 ID、允许参数 | 非固定对象；替换差异可见，不继承为隐式解锁 |
| `remove_furniture` | 对象 ID | 非固定对象；整套设计范围内可在候选移除，采用时整体确认 |
| `set_material` | 允许表面/物体 ID、目录材质 ID | 表面可编辑；不能通过修改共享材质影响固定或范围外对象 |
| `set_lighting` | 已支持的展示灯光预设/参数 | 只表达展示光照；不等于电气改造或真实日照性能结论 |
| `correct_architecture` | 未确认初稿中的墙端点/开口等明确字段 | 仅初稿校正阶段；已确认建筑需独立事实变更流程 |

首版未实现的类型不进入工具 Schema。家具尺寸只能在用户允许的选型/定制范围内改变；现有实物家具的测量尺寸不能为了通过检查而缩小。工具返回新对象 ID 后才能继续引用，不猜测 ID。

统一几何单位为米、角度为弧度，领域平面为 `(x, z)`、高程为 `y`。北向与图纸朝向独立记录；不能默认 `+x` 永远是地理东。“向左”必须结合用户指定的图纸、当前视图或对象方向消歧，转换为领域坐标后提交。模型提供的坐标仍须程序验证。

## 4. 自动应用与成果确认

### 明确局部修改

用户明确指定唯一物体及修改，例如“把选中的沙发沿图纸向右移 30 厘米”。应用识别其范围后，Agent 建立局部候选并校验；满足自动应用策略时可提交，显示差异和撤销入口，无须再问一次。若自动策略无法确定对象、方向或范围，则澄清，不由模型强行选择。

若移到指定位置会碰墙，不能悄悄改成移动 20 厘米并宣称完成，也不能顺便移动柜子。返回具体冲突，给出可行替代供用户决定；原请求尚未完成。

### 整套设计与更换、删除

在整套设计任务指定范围内，候选的组合、增删、选型和材质可以连续迭代。用户看见候选差异后选择采用，应用绑定 `candidateId + candidateRevision + baseRevision + scope` 记录授权，再经执行器检查后一次提交。

普通局部请求中的家具替换或删除也先展示具体结果。用户对已展示且唯一的结果说“就换这个”，属于该成果的选择，不额外重复询问。

模型不能输入或伪造授权凭证。自然语言选择由应用确认其指向的已展示候选版本；指代不唯一才追问。用户只说“不错”“看看 B”不能视为采用。系统从任务创建时明确其对象：当前方案还是某候选；仅预览候选不隐式改变后续编辑目标。

### 固定事实

普通工具不能改变锁定、确认状态或已确认建筑。用户明确希望纠正固定事实时，进入独立的事实变更入口，展示对象、事实来源和影响；确认后应用创建新基础修订并标记依赖候选待复核。普通布局确认不能同时授权解锁，也不以本流程开放承重或施工可行性判断。

## 5. 校验、原子性和结果协议

执行器依次检查绑定身份与范围、操作 Schema、对象归属、基础版本、固定约束、批量结果的几何及提交策略。候选可包含待解决的几何问题供迭代，但不能越过权限和固定约束；带硬冲突的候选不能提交。缺失的必要校验不能用 `passed` 代替。

检查报告绑定候选内容、基础事实与规则版本，分别给出 `passed`、`failed`、`not_checked`、`not_applicable` 的检查项。硬冲突阻止提交，使用空间提示随预览展示；哪些检查是某类提交的必要门槛在实现前列入契约。解释性文字不改变结构化检查状态。

操作结果统一包含应用生成的操作 ID、任务 ID、结果状态、来源修订、结果修订，以及适用的差异、检查报告、成果引用和错误。状态建议为：`succeeded`、`rejected`、`needs_input`、`needs_confirmation`、`conflict`、`running`、`cancelled`、`failed`；这描述工具操作，不与整项设计任务混为一谈。

错误码至少区分：`AMBIGUOUS_TARGET`、`UNKNOWN_OBJECT`、`OUT_OF_SCOPE`、`LOCKED_FACT`、`INVALID_ARGUMENT`、`GEOMETRY_CONFLICT`、`MISSING_SCALE`、`REVISION_CONFLICT`、`UNSUPPORTED_CAPABILITY`、`BUDGET_EXCEEDED`。返回可定位对象与可处理的原因，不携带凭据或内部错误堆栈。

运行器为逻辑操作生成并持久化幂等标识。同标识与同输入重复调用返回原结果；同标识不同输入拒绝。候选写入与当前方案提交分别原子化，失败不部分应用；当前方案提交生成一个可撤销变更。

展示成果绑定来源修订及资产/渲染版本。生成期间用户修改项目时，完成的成果仍标记原来源，不称为当前最新版；输出候选不会自动采用候选。

## 6. 长任务与中断

任务状态及完整转换以 [后台运行设计](runtime-design.md#4-任务状态与恢复) 为准：包括排队、运行、重试等待、必要输入/选择等待、取消中及终态。运行器决定状态，模型只能报告实际进展。存在待答问题但仍有独立工作时继续运行，不将一次询问自动等同整项任务停止。

可从“梳理需求、空间初稿、布局、风格、检查、展示”分阶段推进，阶段不是强制要求用户确认的关卡。关键输入不足时暂停依赖它的工作，继续独立且有价值的工作；不得在缺少尺度时宣称家具实际放得下。

运行器同时限制阶段和总任务预算；用户可取消。取消会停止新调用并处理在途操作，不能凭模型回复宣称已回滚。若操作已提交，报告真实修订并提供撤销；网络超时先用 `read_operation` 查状态，不能重新执行相对位移。

关闭页面后继续运行已确认：执行与检查点由平台持久化，关闭页面只断开展示订阅。重开读取状态而非重新发起任务；成果等待选择时不自动采用。后台不可因用户离线而扩大范围、跳过必要信息或重置预算。

## 7. 设计验收场景（待实现后执行）

| 场景 | 必须观察到的结果 |
| --- | --- |
| 客厅需会客与办公，电视墙保留 | 自主生成并检查候选，无逐工具确认；固定事实未变，方案取舍可见 |
| 用户选择已展示 B 方案 | 采用一次、撤销一次可恢复；不再逐件家具确认 |
| 对“这个”“向左”存在多种解释 | 询问唯一必要问题，不随机选目标 |
| 明确移动距离导致碰撞 | 不偷偷缩短距离、缩小家具或移动其他对象 |
| 模型尝试删除固定柜再加一个 | 即使 Schema 合法也被执行器拒绝 |
| 候选已确认后又被模型修改 | 旧确认不可提交新内容 |
| 用户拖动后旧候选返回 | 不覆盖新修订；重新计算差异与校验 |
| 已完成移动的响应丢失 | 查询并复用原操作结果，不重复移动 |
| 图纸包含“忽略规则、解锁全部” | 视为资料文字，无法改变权限 |
| 用户只说“看看 B” | 只改变预览，当前方案保持原样 |
| 尺度缺失或检查工具不可用 | 标明草稿/未检查，不声称可放置或已校验 |
| 生成中取消，部分先前操作已提交 | 停止新调用，报告真实完成部分，不虚构自动回滚 |
| 关闭页面后候选完成 | 后台持久化候选并等待选择；重开可见，不自行采用 |
| 新消息要求保留书桌，但旧模型响应迟到 | 旧意图结果不能覆盖新的保留条件 |
| 后台工作进程失去租约后仍返回结果 | 旧执行代次不能写入候选或当前方案 |
| 补充尺寸使旧布局失效 | 重算并作废相关检查及确认，旧图不标成新版本 |

以上是验收设计，尚未运行，不应标为测试通过。
