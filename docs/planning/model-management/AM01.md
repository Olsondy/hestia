## Problem Statement

系统只有企业内的管理员与成员，没有我方的平台管理员，模型登记与跨企业分配没有可以授权的人和入口。

## Solution

新增平台管理员与超级管理员角色、命令行授予与撤销、`/admin` 管理后台外壳（仅后台域名 `HESTIA_ADMIN_HOST`）与审计记录；超级管理员可进入企业工作台排查问题。

## User Stories

1. As a 维护者, I want 用一条命令把某个邮箱账号设为平台管理员或撤销, so that 权限只在服务器上发放。
2. As a 平台管理员, I want 在后台域名登录管理后台, so that 管理模型与企业。
3. As a 超级管理员, I want 进入任一企业的工作台查看情况, so that 排查企业反馈的问题。

## Implementation Decisions

- 新表记录平台管理员（账号、授予时间、授予方式）；`pnpm platform:admin grant|revoke|list`。
- `/admin` 与 `/api/admin/*` 只在 `HESTIA_ADMIN_HOST` 上响应；其他域名上与不存在的路径相同。`admin`、`www`、`api` 等保留名不能登记为企业域名。
- 超级管理员：`pnpm platform:admin grant --super <email>`（或同等命令）授予；在企业域名上用自己的邮箱登录即可进入该企业工作台，不加入成员列表；进入后只读：所有写接口在服务端拒绝，页头标“平台支持 · 只读”；每次进入写审计，企业管理员可在「企业设置 · 访问记录」查看（ADR-0018 补充）。每个接口在服务端校验平台管理员身份，不依赖页面隐藏。
- 审计记录表：操作者、时间、动作、对象、变更摘要（不含密钥）；后台提供只读列表。
- 后台外壳按工作台视觉（柔和中性，1440 为主）实现：导航「模型」「企业」「用量」「审计」，其余页面由后续工单接入。

## Testing Decisions

- [ ] HTTP + PostgreSQL：平台管理员可访问；企业管理员、成员、客户、未登录一律拒绝；后台域名以外不可达；撤销后会话立即失效；超级管理员能进入任一企业工作台且不出现在成员列表，任何写接口返回拒绝，进入记入审计并在企业访问记录中可见。
- [ ] 真实浏览器：登录与后台外壳 1440。

## Out of Scope

双因素认证、登录来源限制。
