# S01 图纸需求直接出方案验证（ADR-0013）

日期：2026-11-03。范围：工单 #43（按 ADR-0013 改写）。本机 PostgreSQL（127.0.0.1:54329）、Next.js dev（127.0.0.1:3000）、图纸转换 Worker（`pnpm worker:import`）；未运行出图 Worker，未预生成效果图。

## 实现要点

- **DXF 直接出方案**：转换 Worker 完成 DXF 后调用 `generateForImport`；上传请求在关联图纸后也调用一次（浏览器验收中发现 Worker 可能在需求关联图纸前就转换完，第一次实现因此停在“识别中”）。候选通过校验即采用为项目空间、派生饰面、规则生成方案、排队出图，只把通过排版校验的方案发布给客户；需求行加锁、已有方案时跳过，重复调用不重复生成。
- **识别不了**：候选不通过或没有可用方案时，转换记为失败并写入客户能看懂的原因；需求状态 `conversion_failed`，视图带 `conversionError`。客户可重新上传（替换图纸，重新识别），或交给企业整理（`POST /api/client/{entry}/requests/{id}/hand-over`，进入排队）。
- **排队处理**：照片、PDF、DWG 上传后为 `assisted_conversion`，客户端显示“已收到图纸，排队处理中”，「我的项目」显示“排队处理中”。
- **限次**：每位客户在每家企业每天（北京时间）3 次上传，失败也计入，超出返回 429 `DRAWING_DAILY_LIMIT`；`workspaces.settings.drawingUploadsPerDay` 可调。
- **不再待审**：成员发布接口只用于开启“全部审核后发布”的企业。H5 上传页、等待页与状态文案相应更新；工作台线索状态增加“图纸未识别”“排队待整理”。
- 全程不调用模型。
