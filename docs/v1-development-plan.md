## 1. 交付目标与开发原则

首版交付一条完整用户路径：**单层图纸 + 居住需求 → 可纠正空间初稿 → 布局与风格 → 用户采用 → 对话迭代 → 3D 与静态图**。用户无需配置模型，也无需逐条批准工具调用。复杂设计优先质量，明确局部修改优先速度，两者经过相同的执行校验。

开发顺序从一条真实 Agent 路径展开：先在有可靠尺度的测试空间中完成局部修改，再接入用户图纸与整套设计。局部修改闭环只是内部里程碑，不能代替首版完整任务验收。持久化、固定事实、候选隔离与正式提交控制从底座开始建设，不能等模型接通后再补。

| 首版必须有 | 首版不展开 |
| --- | --- |
| 图片、PDF 选页；单层、直墙及直线斜墙；可纠错的空间初稿 | 原生 CAD/DWG/DXF、多层及自动透视重建 |
| 必要的底图叠加、校准、对象点选、轮廓/门窗校正和撤销 | 完整 CAD 工具箱和以手动设计器为中心的交互 |
| 默认一个完整推荐，有实际取舍时最多两个候选；完整布局及材质能力 | 为数量凑方案、仅换色冒充新布局 |
| 平台模型、后台任务、恢复、取消、必要提问及成果采用 | BYOK、自定义端点、通用插件、任意脚本执行 |
| 同一项目数据生成交互 3D 和静态图 | Room tour 视频、独立 AI 美化成片、预算报价、水电施工设计 |

2026-10-25 最初技术栈讨论的邀请制范围见 [ADR-0004](decisions/0004-mainland-invited-pilot-managed-services.md)，后续已被 [ADR-0006](decisions/0006-open-registration-free-credits.md) 调整为开放注册、注册后赠送积分：游客只看示例，不做匿名账号、匿名积分、游客项目转移或账号合并，首期仍不提供付费。实现基线继续采用 [技术栈](web-stack.md) 和 [ADR-0003](decisions/0003-modular-monolith-with-durable-workers.md) 的 Better Auth 邮箱密码身份，可信身份和项目归属由应用落实。M6 应按新范围验收游客入口、注册赠送与任务积分规则；现有 T04 邀请身份的验收证据保留，不作为新增能力已完成的证据。

## 2. 开发顺序与可审查成果

主依赖为 **M0 → M1 → M2 → M3 → M4 → M5 → M6**。每阶段以可运行成果、数据差异和验收记录结束，不以文件数或工具数量结束。

| 阶段 | 核心交付 | 进入条件 | 退出门槛摘要 |
| --- | --- | --- | --- |
| M0：关键验证与契约冻结 | 模型/识图/渲染小样，统一数据及检查契约，技术选型记录 | 实施已获授权；先推进合成验证，真实评估等待授权样本与 API | 至少一条可行的模型、数据、渲染链路；明确试用阈值与失败替代路径 |
| M1：项目、候选与执行底座 | 持久化项目、任务和候选；有限命令、几何门槛、原子提交与撤销 | M0 核心契约确定 | 不接真实模型也能证明越权/固定事实/版本/重复调用不会产生错误提交 |
| M2：真实 Agent 最小闭环 | 平台模型 → 有限工具 → 校验 → 局部应用 → 3D 变化；基础后台恢复 | M1 执行器可用，M0 模型验证通过 | 明确修改准确可撤销；歧义不猜；关页继续、重开不重复执行 |
| M3：图纸到可纠正空间 | 导入、识图候选、尺度证据、最小校正界面、初始空间采用 | M2 运行器与候选机制可用 | 新图纸生成自身初稿；缺尺寸可推进概念；校准及确认后进入真实空间设计 |
| M4：整套自主设计 | 需求保持、布局生成、资产选择、风格、比较及成果采用 | M3 产生可设计空间，M1 几何能力覆盖所用操作 | 完整任务无需逐工具许可；推荐满足约束，候选差异真实，采用及后续修改一致 |
| M5：成果交付与异常收敛 | 后台静态图、完整状态交互、恢复故障矩阵、用量限制 | M4 完整主路径可运行 | 离线期间也能生成成果；中断/取消/新需求不造成错误提交或虚假完成 |
| M6：样本验收与受控试用 | 固定评估报告、真实浏览器验收、部署/恢复演练及试用说明 | M0–M5 阶段门槛通过 | 10 个范围内样本完成；关键反例全部通过；质量与局部延迟达到预先冻结阈值 |

可以独立准备样本、资产清单和评估记录格式；M3 的输入预处理也可在 M2 稳定期间提前验证。共享的数据契约、权限和版本语义由同一基线维护，不能为了并行形成两套事实来源。此处的阶段通过是开发验收，不是让最终用户每阶段都批准一次。

### M0：先消除决定架构的未知项

工作包：

1. 整理 10 个授权且去标识的目标样本清单，先选清晰图、扫描图、手绘图各一个做小样；准备已知尺度、需求、固定事实和人工核对基准。保留部分样本作为验收集，不全部用于反复调 prompt。
2. 用一个主模型的质量/快速配置验证图片、完整工具请求、流式中断、错误及用量。需要专用识图或快速模型时再对比；不强制接两个供应商。生产写入尚未开放，小样通过协议替身与隔离数据运行。
3. 对外部图片分析脚本做输入/输出和依赖小样；将 HouseSpec 转为内部候选，校验单位、墙中线、方向、尺度来源和固定事实。脚本的推测不能成为事实确认。
4. 比较现有渲染器改造与外部模板适配：用两套不同户型验证加载、对象 ID、增量修改、选择回传、镜头保持和静态图；验证选定方案可在服务端生成图片。外部 HTML 失败时采用现有渲染器适配路径；两条路径都不能通用渲染时，先补足生成器再推进依赖它的阶段。
5. 确定数据版本、工具 Schema、错误协议、必要几何检查、数值容差、资产最小集合和身份边界；按已确认技术栈验证服务端、持久化、工作进程、包管理与应用入口的具体版本及集成能力，不重新逐库选型。验证若揭示架构冲突，再以证据重评；不能沿用旧浏览器 Agent 架构。
6. 定义模型评估评分表、试用最低质量、局部响应时间目标及任务预算的初始上限；基于小样设值并记录依据。M4 再校准整任务预算，M6 不能看完结果后倒改阈值。

验收与证据：至少一个平台配置完成真实图片及合法工具请求；失败和截断结果不产生项目修改。两套户型可通过同一选定渲染适配路径显示，坐标转换往返在约定容差内。输出能力矩阵、样本清单、契约版本、选型及复用结论；不以“页面能打开”判定渲染器可接入，也不把协议替身成绩当真实模型成绩。

若样本、服务权限或能力不足，明确未通过的依赖；不通过缩减固定事实保护或虚构识图能力继续。具体型号、组件、延迟和成本数值在此阶段用证据补齐，不再要求用户凭空猜参数。

### M1：建立 Agent 可以安全调用的领域底座

工作包：

- 统一项目、建筑、固定事实、可移动家具、材质、尺度证据、候选、修订和需求来源。项目为事实来源；视图与聊天不直接写正式状态。
- 建立可信身份和项目/文件归属，持久化任务、候选、操作结果、采用事件、检查报告与预算记录。原图与输出以授权资源引用访问。
- 实现候选创建/编辑/检查、正式提交、撤销与操作查询；首先覆盖移动、旋转和明确材质变化。其他操作按后续能力开放，不把未实现工具暴露给模型。
- 原子提交同时记录新修订和幂等结果；采用绑定候选内容、基础修订和范围。手动校正、后续拖动与 Agent 使用相同领域命令。
- 建立基础几何检查：有限数值、合法轮廓/开口、家具边界与旋转占地、固定物体冲突；门扇区和使用空间等按契约列出必要项与提示项。新增操作必须同步扩充检查，缺少必要检查时拒绝采用。

验收与证据：

- 同一批命令中一条非法，项目与撤销历史均不出现半成品；失败的候选更新也保持原子性。
- 重复操作只生效一次；同操作标识不同参数被拒绝；旧修订、旧检查报告、旧采用事件不能覆盖新状态。
- 两个测试身份直接请求对方项目、附件、候选及成果均被拒绝，不依赖最终账号 UI 是否已确定。
- 固定柜被移动、删除后重加、通过材质共享影响范围外对象等反例均被拦截；普通命令不能改锁定或已确认建筑。
- 矩形、凹形、斜墙及旋转家具的几何样例有可定位报告，分别显示通过、失败、未检查和不适用。

阶段成果是通过契约测试的领域执行器与持久化服务，不要求完整手动工作台。

### M2：尽早打通真实 LLM 与后台任务

工作包：

- 实现供应商适配器、版本化 system prompt、按任务收窄的工具注册表及应用选择的执行配置。模型仅提出结构化工具请求，执行结果必须来自 M1。
- 在有可靠尺度的测试空间中贯通 `read_project/read_task → create_candidate → edit_candidate → validate_candidate → apply_candidate`；接入澄清、展示、撤销和操作查询。
- 实现后台任务领取、执行租约、检查点、状态订阅、基本取消和预算预留。浏览器关闭不影响执行；服务端长期凭据不进入浏览器、prompt 或项目成果。
- 最小 UI 提供对话、对象点选、任务进度、差异、问题回答和撤销。用现有工作台承载，尚未开放的整套设计入口明确标示开发状态。

验收与证据：

- “将选中书桌沿图纸向右移动 20 厘米”得到对应数据差异和 3D 变化，提交一次，无额外确认，撤销恢复；不以模型口头回答作为成功。
- “这个向左一点”在目标/方向不明确时澄清；给定距离碰撞时不偷偷缩短距离或移动其他物品；固定对象保持不变。
- 注入未知字段、任意对象、伪造通过结果、截断 JSON、重复流式工具事件均不产生越界提交。
- 请求已持久化后关闭浏览器，任务仍推进；重开恢复同一任务。工作进程重启、提交成功但响应丢失后，按操作记录恢复且不重复移动。
- 取消直达任务控制；模型故障或上限不足返回真实状态。日志可追踪配置、意图版本、调用、工具与项目修订，且不包含凭据。

这是首个可演示的真实 Agent 里程碑；演示使用测试空间，不能宣称已完成用户图纸识别或整套设计。

### M3：接入图纸、尺度和用户校正

工作包：

- 图片导入及 PDF 选页、旋转/裁切、叠图与文件引用；将选定页面和必要区域送入已验证识图能力。
- 接入 `inspect_floorplan`、`record_brief`、`calibrate_candidate` 和未确认建筑的 `correct_architecture`。模型和脚本都只生成候选，记录事实来源和不确定项。
- 最小校正面板允许定位和调整墙端点、门窗、尺寸证据及固定设施；通过对话或点选完成纠错，不以开发者修改 JSON 作为用户流程。
- 实现 missing/estimated/calibrated/conflicted 尺度状态；必要输入缺失时继续需求、风格与概念草稿，补尺寸后重算相关几何及布局。
- 初始空间采用前展示叠图、尺度与关键事实；通过门槛后形成基础修订。对已确认事实的纠正走独立应用入口，展示影响、用户确认后使依赖候选失效，普通 Agent 工具不能解锁。

验收与证据：

- 至少完成清晰图、扫描图、手绘图各一个真实模型贯通案例；新图不复用示例户型冒充识别结果。
- 漏墙、错门和尺寸冲突能在 UI 定位并修正；同一领域数据生成 2D/3D，无第二份坐标状态。
- 缺尺度时成果自身标注概念草稿，不能采用为确认空间或宣称家具放得下；已知长度证据补充后重新计算，不只修改说明。
- 旧尺度的检查、采用事件和输出失效；已校准也不自动证明所有几何正确。固定事实纠正仅更新用户明确确认的内容。
- 保存、刷新和重启后保留底图变换、证据与待答问题；不重复询问已回答问题。未覆盖输入明确说明限制。

### M4：从局部工具扩展为整套设计

工作包：

- 依据用户来源的需求组织“需求—空间—布局—风格—检查—展示”任务，区分明确需求与助手建议；已有有效事实直接沿用。
- 接入受控目录与 `search_catalog/propose_layouts`，完成新增、替换、删除、材质及展示灯光操作；为操作补足几何与范围校验。
- 布局能力在已知资产、范围和约束中生成候选；先实现有限的摆放规则/搜索与确定性检查，不把 `propose_layouts` 写成另一个无限 prompt 循环，也不承诺全局最优。
- 默认一个完整推荐；有真实取舍时最多两个。支持房间之间的协调、已有家具保留、局部反馈与需求版本更新。
- 展示真实差异、满足/未满足需求和取舍；应用记录用户对具体成果的采用。初始空间与方案采用可合并，必要尺度和关键事实门槛仍须满足。

验收与证据：

- 在至少两种不同户型完成“二人居住、有宠物、需要办公、保留固定设施”的整套任务；无需用户逐个指定家具坐标或批准工具调用。
- 比较方案的家具位置、朝向或组合确有变化；材质差异单独呈现；不为凑第二套放宽已确认需求。
- 明确硬约束全部保留；无法同时满足时提出可定位的冲突和取舍，不标为完整满足。人工审查空间与实际图像，不能由模型独立给自己打分。
- “看看 B”只预览；“采用 B”绑定展示版本一次应用；普通替换/删除也先展示采用，明确局部移动仍可自动应用。
- 候选变更或用户新要求使旧确认无效；用户采用后继续对话编辑，不回退到旧事实。固定事实在全流程中不漂移。
- 按 M0 评分表评价需求保持、纠正次数、无用追问、完整候选等待和用量；据完整任务数据校准上限及质量/快速路由，记录变更依据。

### M5：补齐可交付成果与异常路径

工作包：

- 将 `create_presentation` 接入后台输出服务，生成绑定修订、资产及渲染版本的静态图；3D 与静态图使用同一领域数据。浏览器截图只作交互便捷入口，不承担关页后的输出任务。
- 完善进度、必要问题、等待采用、部分完成、失败及取消 UI。等待采用不能显示整项设计已完成；后台完成不等于用户已经看过。
- 扩展故障注入：重复调度、租约失效、旧响应迟到、模型超时、用量未知、并发编辑、新需求和取消/提交竞争。
- 固化任务预算、重试和合格模型回退；无合格回退时保留已有成果。确认恢复不重置预算，不以后台无限重试掩盖失败。

验收与证据：

- 关闭页面后仍可完成静态图任务；重开可下载并打开文件。导出候选不自动采用；概念图自带标识，旧修订成果不冒充当前成果。
- 3D 与静态图的家具、门窗、材质及固定设施一致，至少两个不同户型做视觉核对。
- 租约过期执行者及旧意图结果不能写状态；新用户保留要求能约束后续操作；不同编辑导致版本冲突时不覆盖新内容。
- 取消先于事务提交则不提交；事务先完成则如实保留并可撤销。结果不明保持核对状态，重启后可继续核对。
- 模型响应丢失产生不确定用量记录；有界重试/切换计入原任务。到上限保存成果及未完成项，不宣称完成、不请求用户 Key。

M2 已有基本恢复与取消；此阶段覆盖组合故障和输出服务，不把可靠性首次推迟到发布前。

### M6：用真实任务验收并形成试用版本

工作包：

- 执行 10 个授权样本：5 个清晰平面图、3 个扫描图、2 个手绘图，覆盖凹形、斜墙、尺度缺失/冲突及模糊门窗。缺失信息样本预备可追溯补充资料，验证等待与补充后完成两段流程。
- 对固定局部操作、完整任务和关键反例做重复评估；记录实际模型、prompt、工具、规则和资产版本。协议替身覆盖故障，真实模型覆盖理解与生成，真实浏览器及人工核对覆盖交互和视觉。
- 在目标部署环境演练状态持久化、进程重启、凭据注入、数据备份恢复和版本回滚。恢复后项目、原图、候选及成果引用仍对应。
- 根据 M0 确定的试用身份方式完成项目与资源隔离；如开放独立用户登录，再验收相应会话与访问流程。部署、数据保留与服务支持范围写入试用说明。

发布门槛：

1. 10 个范围内样本均可通过产品内校正和必要资料补充完成完整路径；不要求识图零错误，不允许开发者改数据库/源码替用户过关。不支持样本必须如实记录，不能发布时临时剔除失败样本。
2. 已定义的关键执行反例全部通过；固定事实绕过、越权、重复移动、过期确认、错误尺度采用或虚假执行成功有任何未修复缺陷，则不进入试用。
3. 完整方案质量、局部准确性、用户纠正负担及局部延迟达到 M0 冻结、M4 有据调整的门槛；候选产生与最终完成耗时分别统计。小样本结果不称为上线 SLA。
4. 最小演练任务完成：“图纸 + 居住/宠物/办公需求 → 推荐及有实际取舍的替代 → 采用 → 微调书桌 → 静态图”，穿插一次关页恢复、一次缺尺寸补充、一次版本冲突；结果与执行记录一致。
5. 试用用户能独立找到补充资料、校正、采用、撤销、取消与成果入口，不需要开发者代操作；真实浏览器检查及视觉审查有记录。

交付评估报告、已实现/未支持清单、部署恢复记录和已知问题。未经执行的项保持“未验证”，不能因为文档齐全或测试替身通过就标为发布完成。

## 5. 排期、验证记录与迁移

不先承诺总人日。旧估算依赖浏览器直连与完整编辑器优先，不能通过调整数字继续套用。M0 结束后按选定技术、模型/渲染复用结果、已具备样本和实际参与人数重估 M1–M6；M2 完成后用真实链路吞吐与修复负担复估。识图纠错、通用几何和后台渲染是主要不确定项；不通过压缩验收掩盖它们。

每阶段验收记录统一包含：目标/契约版本、输入与预期、真实输出/项目差异、使用真实模型还是替身、必要视觉证据、耗时与用量、失败及未验证项、通过/未通过结论。已通过且未受新变更影响的检查无需反复扩大；模型、prompt、工具或几何规则变更时复跑受影响样本与关键反例。

原型源码已迁入 `example/prototypes/projects/src/`，`example/prototypes/projects/index.html` 与 `dist/index.html` 保留可访问产物；生产应用在 `apps/web` 实施。不能直接修改生成 HTML；原型已有本地项目不自动上传，若需导入需独立解析版本、校验及建立归属。新流程通过验收后再切换主要入口。生产仅开放家居杂志（editorial）方向；原型保留两套历史视觉，不要求生产维护主题切换。
