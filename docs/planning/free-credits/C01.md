## Problem Statement

未登录用户目前只能看到身份入口，不能先体验公开示例；正式用户仍依赖邀请。产品需要游客先看示例，注册后领取一次免费积分，使用自己的户型设计，同时不引入匿名账号和合并流程。

## Solution

提供游客公开示例与开放注册流程，注册成功后一次性发放可配置免费积分，并提供当前用户余额与变动记录的查询和展示。首期初始赠送量为 40 分，无有效期，后续由维护者根据实际成本调整数据库配置。

## User Stories

1. As an 游客, I want 无需登录浏览和操作公开示例, so that 可以先了解产品。
2. As an 游客, I want 示例明确标注为演示, so that 不会把示例当成我的户型识别结果。
3. As an 游客, I want 使用个人户型时进入注册或登录, so that 私人资料保存到正式账号。
4. As an 新用户, I want 不依赖邀请码完成注册, so that 可以自主开始体验。
5. As an 新用户, I want 注册成功后自动获得一次免费积分, so that 无需购买即可使用 AI。
6. As an 注册用户, I want 重复提交和再次登录不重复发放, so that 积分记录准确。
7. As an 注册用户, I want 查询自己的可用积分与历史变动, so that 知道额度来源。
8. As an 注册用户, I want 其他人不能读取或改变我的余额和项目, so that 私人资料和权益不被越权访问。
9. As an 已有用户, I want 原有登录和个人项目继续可用, so that 新注册方式不会丢失已有成果。
10. As an 维护者, I want 通过数据库修改新用户赠送量和工作档位, so that 不需要先建设管理后台。

## Implementation Decisions

- 阶段：M1 基础能力增量及 M6 用户入口验收。所属规格：https://github.com/Olsondy/hestia/issues/26；前置依赖：T04/#5（已完成）。相关决定：ADR-0006，沿用 ADR-0003/0005 的身份、数据库与资源授权边界。
- 复用现有邮箱密码身份，开放普通注册；保持已有账号与项目归属。游客没有匿名账号、积分或个人项目，不能直调受保护的图纸、项目、任务和余额 API。
- 公共示例只提供演示内容与本地浏览交互，不把真实模型调用开放给游客，也不使用任何用户私密项目作为示例。既有本地原型项目不自动上传。
- 建立 C02 可复用的积分配置、账号余额和变动记录基础。发放事务和业务唯一性保证每账号只有一次新用户赠送；注册重复提交、重放或响应丢失后重试不重复发放。注册成功与赠送的中断可恢复，不能要求用户再注册一个账号。
- 初始配置：问答 1 分、小改 5 分、整套设计 20 分、注册赠送 40 分；可通过数据库维护，提供初始化及修改说明，不建设管理后台。已发余额不因配置修改重算，历史账号不在本票自动补发新用户奖励。
- 用户只能查询自己的余额与记录，不能通过前端金额或普通 API 修改奖励、余额和规则。服务端校验配置，避免非法分值被用于发放或计费。
- 不把“验证邮箱后发放”或手机验证作为本轮新增必选条件；它们未获确认。注册安全沿用身份框架现有能力，首期不承诺解决所有多账号领取行为。
- UI 延续家居杂志方向、仓耳渔阳体及现有设计规范；实施时使用已指定 Impeccable，不启用 hooks。

## Testing Decisions

复用用户已认可的“注册/项目 HTTP + 真实 PostgreSQL”和真实浏览器入口，不新增按表或组件逐个镜像的测试体系。既有身份集成测试和项目 API 验证是先例；旧的“普通注册必须拒绝”断言应按新产品范围调整。

- [ ] 未登录浏览公开示例不创建匿名用户、个人项目或积分记录，示例明确标注。
- [ ] 游客访问受保护资源、上传个人资料或发起 AI 任务被拒绝；其他账号不能查询或修改当前用户的余额与项目。
- [ ] 新用户可自行注册登录，一次性获得配置的赠送量；重复/并发请求、再次登录及响应丢失后的重试不重送，注册与赠送中断可恢复。
- [ ] 原有账号及项目可继续访问；已发积分不因配置更新改变，配置更新后新用户按新值发放。
- [ ] 数据库初始化与修改说明可操作；非法配置不能生效为负奖励或非法分值。
- [ ] 真实浏览器检查游客入口、注册入口、赠送余额及刷新后的展示；桌面和手机无阻断流程的布局问题。

先使用已有服务；未经用户同意不启动或重启服务。记录实际执行证据，不能把此前邀请制验收当作开放注册已通过。

## Out of Scope

AI 任务预留与扣退执行（由 C02 完成）、匿名账号/匿名积分/合并或游客项目迁移、管理后台、支付订阅、邀请奖励或周期赠送、历史账号批量补发、额外手机号或邮箱验证产品流程、正式部署。

## Further Notes

本票提供可独立验收的“游客看示例 → 注册领取积分 → 查看自己的余额”能力。C02 接入后才能据此声称 AI 任务已经受积分控制；本票不解除现有真实模型和整套设计能力的依赖。
