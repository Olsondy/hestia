# M06 跨企业隔离测试矩阵与两企业联合验收

日期：2026-11-10。范围：工单 #64，依据 ADR-0017。PostgreSQL 17.7（同 M01）。**状态：自动部分通过；浏览器联合验收未做，工单保持开放。**

## 隔离矩阵（`isolation.integration.test.ts`，已加入 `pnpm test:db`）

- **做法**：遍历 `apps/web/app/api` 下的全部路由，对每个能指向另一家企业数据的路由与方法，在 A 的域名上分别以 A 的成员、A 的客户、未登录访客调用两次：一次带 B 的真实标识（企业、工作空间、方案需求、方案、分享码、分享、成员、项目、出图），一次带不存在的标识。要求没有一次成功，且两次的状态码和错误码完全相同，A 无从得知 B 的数据是否存在。
- **路由覆盖**：不带他企业标识的路由（自己的会话与积分、公开目录、登录注册、项目与工作空间列表）列在白名单里；新增路由既不在矩阵里也不在白名单里时，路由参数无法匹配，测试会失败。
- **对照**：同一套调用方式下，B 的成员在 B 的域名上能读到 B 的线索、访客能用分享码预览，说明矩阵能发现真正的泄露。
- **结果**：2/2 通过；231 次调用中，404（企业入口 / 不存在 / 分享码不可用）145 次、401 48 次，没有一次因来源校验被拒（403 `ORIGIN_REJECTED` 为 0）。另有 38 次（400 输入格式 34、415 4）在权限检查之前就因请求体不合格被拒，这些调用没有走到权限判断，对应接口的权限由各自工单的测试覆盖（M01、M02、S02、D08 等）。

## 两企业演示数据

`pnpm demo:seed --two-enterprises [--no-render] [--reset]`：保留原演示企业（`demo-home`）并登记域名 `a.localhost`，另建「演示家装企业乙」（`demo-home-b`，域名 `b.localhost`，独立成员、石材与软装目录、一个分享码）。同一个演示手机号在两个域名各自登录，是两个互不相干的账号。已在局域网开发数据库上运行一次（`--no-render`，未预生成效果图）。不带 `--two-enterprises` 时行为与之前相同。
