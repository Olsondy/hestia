# AM03 企业模型分配、月度额度与并发上限验证

日期：2026-11-14。范围：工单 #69，依据 ADR-0018 及其 2026-11-12 补充（额度可设“不限”）。PostgreSQL 17.7（局域网主机上的本地 Compose 容器，经 SSH 隧道映射到 127.0.0.1:54329），HTTP 路由处理函数直接调用；不调用任何模型。

## 实现要点

- **数据**：迁移 `0011_model_grants_and_calls`：`workspace_model_settings`（月度额度，分；`NULL` 为不限；新企业默认 0 即“未设额度”；同时运行的 Agent 任务数，默认 2）、`workspace_models`（企业 × 模型：企业侧启用与默认，每家至多一个默认，默认必须已启用）、`model_calls`（每次调用一行：预占、结算、所用单价版本、token、未核对标记）。三张表都归属企业工作空间，M04 的企业数据导出与删除按外键自动纳入。
- **平台管理员**（`/api/admin/workspaces`）：只能新分配已准入、已定价的模型；已分配的模型之后需要重新检查时可以保留。额度、并发与分配的每次变化写审计。
- **企业**（`/api/workspaces/{id}/models`）：成员只拿到已启用、可用的模型与默认模型，用于 Agent 选择；企业管理员还能看到平台已停用、暂不可用的模型与本月额度摘要，并能启用、停用、设默认（默认模型不能直接停用，不可用的模型不能设为默认）。另一家企业的域名上读取按不存在处理。
- **预占与结算**（`reserveCall` / `settleCall`，AM05 接入运行器）：调用前按“输入估算 + 最大输出”在当前单价下向上取整到分；锁住企业的额度行，检查“本月已用 + 预占中 + 本次”不超过额度，超出时不发出（`QUOTA_EXCEEDED`，额度为 0 时提示“还没有设置本月额度”）。企业同时运行的任务达到上限返回 `ENTERPRISE_BUSY`，服务的总并发（所有企业共享）达到上限返回 `SERVICE_BUSY`，两者都是可重试的排队信号。结算按预占时的单价版本计算；用量未知时按预占额计入并标为未核对，不记零。超过 30 分钟仍未结算的预占不再占并发名额，但继续计入额度，等恢复流程结算。月份按 Asia/Shanghai 自然月。
- **页面**：平台后台「企业」列表与详情（可用模型分组勾选、月度额度“设上限 / 不限”、并发、本月已用与预占）；企业工作台页头齿轮（仅企业管理员）进入「企业设置 · 模型」（启用、设默认、平台已停用标识、本月额度）。表单与状态组件（开关、进度条、额度明细等）移到工作台共用样式，后台与工作台共用。

断言摘要：企业管理员调用平台接口 403；分配未检查的模型 `NOT_GRANTABLE`；分配两个模型、额度 1000 元后列表与审计正确（并发未变不写审计）。企业：已分配未启用时成员看不到；成员修改 403；设默认后成员看到两个模型与默认；停用默认模型 409；未分配的模型 404；另一家企业的域名读 404；平台停用后企业管理员看到“平台已停用”、成员看不到、预占被拒。预占：1 万输入 + 4000 最大输出按 4.00 / 16.00 元每百万 token 预占 11 分，按实际 9000 / 1000 结算 6 分，重复结算不变；用量未知按 11 分计入并标为未核对；未分配的企业被拒。并发：额度只够两次预占时 6 个并发请求恰好成功 2 个，其余 `QUOTA_EXCEEDED`；额度不限时两个任务占满并发后第三个任务 `ENTERPRISE_BUSY`，同一任务的下一次调用不受影响；服务总并发 3 被两家企业共享，满时另一家 `SERVICE_BUSY`，结算一个后可预占；额度 0 提示未设置。

M06 隔离矩阵：新增的企业模型接口与全部后台接口都在矩阵里；在企业甲的域名上，任何身份访问企业乙的数据，与访问不存在的数据得到相同的 404。
