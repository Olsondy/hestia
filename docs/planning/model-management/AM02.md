## Problem Statement

模型只能写在环境变量里，准入靠代码内指纹；换模型要改代码或重启，也无法同时登记多个模型。

## Solution

平台管理员在后台登记模型服务（地址与加密密钥）、测试连通、获取模型列表并启用多个模型 ID，按模型运行接入检查；只有协议适配器写在代码里，不预置供应商。

## User Stories

1. As a 平台管理员, I want 选择协议（Chat Completions、Responses 或 Anthropic Messages）并填写地址与密钥登记一个模型服务, so that 接入任意兼容这三种协议的供应商。
2. As a 平台管理员, I want 在服务列表上一键测试每个服务的连通, so that 及时发现密钥失效或服务故障。
3. As a 平台管理员, I want 从服务获取可用的模型 ID 并启用其中多个, so that 不用手抄模型名，同一个密钥下的多个模型都能给企业用。
4. As a 平台管理员, I want 为每个模型一键运行接入检查, so that 确认模型可用并留下证据。
5. As a 平台管理员, I want 修改单价只影响之后的调用, so that 历史结算不变。

## Implementation Decisions

- 两层登记：模型服务（地址、密钥、协议级兼容设置、超时、总并发）与模型（服务里启用的模型 ID：显示名称、说明、最大输出、模型级参数、单价、状态），字段见规格；单价独立成版本记录。
- 测试连通：最小请求，记录连通、鉴权与耗时，不计额度、不改准入。获取模型列表：Chat Completions 与 Responses 读 `GET /models`，Anthropic 读 `GET /v1/models`；不支持时允许手动添加；记录获取时间，标出新出现与已消失的 ID。
- 三种协议适配器，调用层为 AI SDK Core，按登记的地址与密钥每次调用现建实例：OpenAI Chat Completions（`@ai-sdk/openai-compatible`）、OpenAI Responses（`@ai-sdk/openai` 的 Responses 模型）、Anthropic Messages（`@ai-sdk/anthropic`）。新增两个依赖，与 `ai`、`@ai-sdk/openai-compatible` 一起升级到共用同一版 `@ai-sdk/provider` 的版本并锁定。
- 适配器对外统一为：流式文本、工具调用（含工具参数流）、结束原因、输入与输出 token；不支持的能力在接入检查中标为不支持，不假装生效。
- 兼容设置按协议提供有限开关：服务级（流式是否返回用量、最大输出字段名、思考参数写法、API 版本等）与模型级（思考开关、推理强度、思考预算），不允许填写任意请求体。
- 密钥 AES-256-GCM 加密（`HESTIA_SECRET_KEY` 缺失或长度不足时启动失败）；接口只回显末四位；更换密钥单独接口。生产环境地址必须 HTTPS。
- 接入检查：后台发起、在 Worker 中真实调用，覆盖连通、流式、工具调用与 Hestia 协议样本（沿用 T01 协议检查），结果与证据入库；改服务的地址、协议、兼容设置使其下模型准入失效，改模型参数使该模型失效；换密钥只需测试连通。
- 停用：新任务不可选，进行中的任务在当前调用后停止并告知。

## Testing Decisions

- [ ] HTTP + PostgreSQL：登记服务、获取列表（含不支持列表时手动添加）、启用多个模型 ID、测试连通、改价产生新版本、换密钥、停用；密钥不出现在响应、日志与审计记录中；数据库里为密文。
- [ ] 协议适配器：三种协议各用本地假服务验证请求格式、流式与工具调用解析、用量读取、超时与错误映射（只验证适配层，不冒充真实模型）。
- [ ] 真实模型：管理员为每种协议录入至少一个真实模型并通过接入检查；未录入的协议记为未验证。
- [ ] 真实浏览器：模型服务列表（测试连通）、服务管理（获取与启用模型 ID）、模型设置与接入检查结果 1440。

## Out of Scope

上述三种以外的协议（如 Google Gemini 原生协议）；按企业的模型分配（见 AM03）。
