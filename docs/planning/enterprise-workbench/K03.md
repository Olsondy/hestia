## Problem Statement

已有 Agent 只服务单层个人项目，工具只能改家具布局与视觉风格，不能为企业项目出包含铺贴与软装的整体方案。

## Solution

把 Agent 运行时接入企业工作空间的空间项目，扩展受限工具：铺贴（选石材、规格、铺法、波打线）、软装风格、多楼层家具布局；结果为候选，由成员采用为待审方案。

## User Stories

1. As an 企业成员, I want 对 Agent 说“客厅大气一点，二层主卧新中式”, so that 得到整体方案候选。
2. As an 企业成员, I want Agent 只能在企业目录和校验规则内出方案, so that 不会出现企业没有的石材或排不下的布局。

## Implementation Decisions

工具范围已定（2026-11-15，[ADR-0019](../../decisions/0019-enterprise-agent-uses-validated-operations-only.md)）：Agent 只调用已有、带校验的业务操作，结果一律为候选。

- 沿用 ADR-0002 / ADR-0005 与 AM05：统一对话入口、Worker 内调用模型、流式回复、关页不取消、持久事件；模型取自工作空间的分配，调用前预占额度、调用后结算（ADR-0018）。每轮一次调用、一个 `resolve_turn` 提案，新增提案 `propose_scheme`（整体方案）。
- 只读资料不做成工具调用：应用把线索的饰面（含楼层）、企业在用石材（规格范围）、在用软装风格与已有方案摘要随本轮输入提供。
- 铺贴：每组饰面给石材、规格、铺法，可选波打线；应用按企业目录解析在用版本，经 `inspectSurfaceDesign` 校验规格范围与排版，越权或非法组合（不在目录的石材、不属于该空间的饰面、超出规格、排版冲突）被拒并返回原因，不保存候选。
- 软装风格：只能从企业在用软装风格里选一套，并给客户可切换的 2–3 套；应用按房间类型逐楼层换款并补充陈设（K01 `furnish`），放不下的陈设记为提示。
- 出图：只对通过校验的候选排队出图（现有出图服务）。
- 候选单独保存（`scheme_candidates`），不改空间与已有方案。成员采用后成为线索的待审方案（`finish_schemes.pending_review`），客户与分享码看不到；成员发布后客户可见（线索已发布时）。
- 不做：识别图纸、修正建筑结构、直接改当前方案、由模型给出家具坐标。现有 `layout-planner` 只支持个人项目单房间布局，企业方案不保存家具摆放，按房间移动或重排家具另立工单；每套方案只有一套软装风格。
- 权限：只有该企业成员可在其线索空间上运行 Agent、查看候选、采用与发布；客户端与分享预览不可见对话与候选。
- 没有分配模型时返回“未开通”，不模拟结果（AM05）。

## Testing Decisions

- [ ] 真实模型 + 合成样本：一轮对话产出硬装 + 软装候选并通过校验；越权与非法组合被拒；重试与恢复不重复写入。
- [ ] HTTP + PostgreSQL：非成员不可运行；候选未采用前客户不可见。

## Out of Scope

客户端 Agent；个人工作台改造。
