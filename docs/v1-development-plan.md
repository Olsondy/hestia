# V1 开发计划与验收

日期：2026-10-19。状态：待实施的规划，本轮仅更新文档。功能以 [V1 范围](v1-scope.md) 为准，技术选型见 [Web 技术栈](web-stack.md)。

建议按“多用户个人项目空间 + 浏览器自接模型 + Key 不经过平台”组织开发。用户正在确认这种交付形态，尚未最终选择；开始实现前应确认此项。以下不表示已承诺上线日期，也不授权本轮修改应用代码。

## 1. 开发顺序

先验证接入边界，再完成可手动使用的编辑器，最后让 Agent 操作相同的领域工具。识图效果不能成为用户修正图纸的唯一入口。

| 阶段 | 工作与交付 | 阶段验收门槛 | 粗估工作量 |
| --- | --- | --- | --- |
| M0：关键验证与契约 | 选兼容版本；验证 Next / React / Konva / R3F；两个实际模型端点的浏览器直连、图片、流式、工具调用；确定数据契约和样本集 | 实际部署来源可调用；Key 不出现在平台请求与日志；两端点支持范围清楚；发现跨域阻塞时先调整支持范围或交付形态 | 3–5 人日 |
| M1：账号与项目底座 | 邀请注册、登录退出、密码重置、项目 CRUD、PostgreSQL 迁移、私有附件、修订与命令事务、导入导出数据版本 | 两账号隔离；备份恢复能重新打开项目；过期修订和重复操作不覆盖 / 重复修改 | 5–8 人日 |
| M2：数据与建筑生成 | 墙段图、开口、围合房间、固定约束、统一单位、几何校验；从旧原型提取可复用生成器 | 矩形与凹形两套数据由同一生成器显示；墙洞尺寸一致；不为第二户型增加专用坐标代码 | 5–8 人日 |
| M3：二维导入与编辑 | 图片 / PDF 选页、旋转裁切、比例校准、叠图、墙与洞口编辑、撤销重做、自动保存 | 不接模型也能从空白完成单层建筑；底图坐标可逆；非法轮廓可定位；重新打开不丢校准 | 7–10 人日 |
| M4：家具与 3D 工作台 | 12 类参数家具、固定物品、方案切换、材质 / 白模 / 线框、昼夜、房间浏览、占地和使用区检查 | 摆法确实不同；2D / 3D 同步；锁定对象不动；相机、选择与漫游障碍同步 | 5–8 人日 |
| M5：Agent 与识图 | 浏览器运行器、能力检测、有限工具、图纸初稿、差异预览、对话操作、布局候选、检查点与取消 | 模型只提交领域命令；明确家具移动准确可撤销；识图可修；断线恢复不重复执行；不支持服务明确降级 | 7–12 人日 |
| M6：导出与试用验收 | 项目包、平面 / 3D PNG、离线只读 HTML；真实浏览器检查；部署、备份和兼容说明 | 10 个范围内样本可完成；新设备重开、离线导出和账号隔离通过；所有已知限制有入口提示 | 5–8 人日 |

总量初估 **37–59 人日**，按一名熟悉该栈的全职开发者约 **8–12 周**。这是拆分工作的估算，不是 AI 执行耗时或交付承诺；不含样本授权等待、用户反馈等待、复杂资产制作和本机连接器。M0、M2 完成后重新估算，跨域与几何失败不能用压缩验证时间掩盖。

依赖顺序：M0 → M1 → M2 → M3 → M4 → M5 → M6。M0 提前验证模型接入，避免编辑器做完后才发现核心供应商不能直连。若实际开发拆分人员，素材准备和授权样本收集可独立推进；领域契约与几何决策保持统一。

## 2. 可审查的阶段成果

1. **接入样机**：模型适配兼容矩阵、浏览器请求路径记录、版本锁定记录和数据契约；这时尚不是完整产品。
2. **可手动完成项目的 Alpha**：M1–M4 完成，用户无需模型也可导入、描图、摆家具、保存和浏览。
3. **可纠错的 Agent Beta**：M5 完成，AI 初稿与对话修改复用已有编辑能力；保留手动修正和撤销。
4. **V1 试用版**：M6 完成，邀请用户独立试用，不依赖开发者替用户修改源码。

每个阶段更新已实现清单与实际限制，不能把计划中的功能列为发布特性。

## 3. 验证计划

### 数据与几何

- 单位和底图变换往返；尺寸修改后墙、洞口、房间和家具对应一致。
- 非闭合、自交、重叠洞口、越界开口能定位错误；凹形和斜墙有正常样例。
- 固定约束、家具旋转占地、门扇区、柜门使用区与通路检查有成功和失败样例。
- `baseRevision` 冲突、幂等重试、撤销重做、快照恢复和方案过期复核覆盖关键路径。

### 浏览器与模型

- Playwright 验证 Chrome / Edge 主要编辑流程，截图检查 2D / 3D 对齐、开口、房间隔离与夜间显示。
- CI 使用模型协议替身验证错误与重试，但不能用替身声称实际供应商可用。
- M0 和发布前，在实际部署域名验证至少两个真实端点；记录日期、模型 ID、图片、流式、工具、跨域和中断行为。凭据由测试者提供，不进入仓库。
- 10 个授权样本记录识别初稿错误、纠正步骤和耗时；确认所有范围内样本经人工纠正可完成。先积累基线，再确定质量改进目标。

### 多用户与凭据

- 两账号分别尝试读取 / 修改 / 导出对方项目与附件，包括直接请求已知资源 ID，均应拒绝。
- 邀请注册、退出、密码重置、会话过期及签名文件地址过期行为可复现。
- 验证模型 Key 只发往用户指定端点，不出现在平台 API、数据库、日志、监控、错误报告或导出；不要把真实密钥写入录制文件。
- 浏览器刷新后 Key 消失；关闭页面后任务可识别为中断；重新输入 Key 后从最后提交步骤继续。
- 不把“正常请求路径未传 Key”描述成网页脚本永远无法访问 Key。

### 导出与部署

- 项目包在新账号导入时重新分配归属和资源引用，不能沿用原账号访问授权。
- 离线 HTML 断网打开可浏览并切换已有方案，不包含凭据、登录会话或平台私有文件地址。
- 文档化数据库迁移、备份、对象存储恢复与回滚；一次真实恢复验证项目和附件对应。

## 4. 主要瓶颈与处理方式

| 瓶颈 | 第一版的处理 |
| --- | --- |
| 自接服务协议相似但能力不同 | 兼容矩阵按实际端点与模型验证；不把 OpenAI-compatible 等同全功能兼容 |
| 模型服务不允许浏览器跨域 | 先缩小直连支持范围；如核心用户必须接此服务，再决定开发本机连接器，不静默上传 Key |
| 手绘图缺少可靠尺寸 | 标尺校准、假设标记、叠图修正；不编造真实尺寸 |
| 2D 编辑与 3D 各存一份坐标 | 统一领域模型，两种视图只负责呈现与输入 |
| 大模型擅自移动固定柜或生成穿墙家具 | 确定性校验拒绝操作；模型只能有限修复，仍失败则交给用户调整 |
| 首版目标变成完整 CAD 或写实装修软件 | 保留直墙、单层、参数家具边界；复杂楼梯和商品资产库延后 |
| 看似只换色的方案差异 | 按家具实例位置、朝向、尺寸或组合比较，材质单独管理 |

## 5. 迁移与当前边界

- 当前 `src/` 和 `output/3d/ideal-home-3d.html` 继续作为可用原型；迁移时保留访问方式，直到新流程完成验证。
- 在后续实现的 M0 再决定新应用目录与构建入口，不在规划阶段创建空框架、安装包或替换构建脚本。
- 中性化案例用于回归测试，不上传真实住宅图纸、地名或住户信息。
- 本轮交付仅为这三份规划文档和导航更新，不运行针对未改变代码的构建，也不称产品功能已经实现。

尚待决定：是否采用本文的“在线多用户 + 浏览器直连”建议，接受首版只支持验证过的跨域端点，以及刷新后重新输入 Key。如果要求同时支持任意供应商且网页完全接触不到 Key，应将本机连接器升为核心交付，重新评估工期；这不是一个设置开关。
