# 从讨论中保留的决策

这些记录解释当前示例为什么这样画，不把记忆数字当成测绘结果。

| 讨论中的修正 | 当前采用的表达 | 对后续产品的启示 |
| --- | --- | --- |
| 最初认为约 80–90 ㎡，后来卧室横向记起有 8 米多 | 暂取 8.3 m 墙位跨度，原面积估计待复核 | 尺寸冲突应提示并保留来源，不能悄悄拉伸全屋 |
| 阳台不是与楼梯外沿齐平，而是向外凸出 | 保留西侧凸出和下方缺口 | 外轮廓应可手动校正，不能只识别标准矩形 |
| 书房与楼梯、过道合计东西宽度相等 | 书房暂取约 3 m，并保持对应关系 | 需要表达“对齐、相等”等关联约束 |
| 楼梯占地、平台和步数多次纠正 | 三段踏步、两个平平台；内侧扶手连续 | 复杂楼梯应有单独确认步骤，不能靠平面线条猜完 |
| 上楼段被简化成箭头不符合期待 | 恢复通三楼的真实梯段体积，标注假设 | 视觉简化不得删除用户关心的空间关系 |
| 四层布局重复，只需一个代表层 | 不扩展成整栋楼 | 输出范围由用户需求决定 |
| 床离门太近、房间看起来偏短 | 修正卧室横向跨度；床沿内墙向东移 | 先确认尺度，再讨论家具拥挤程度 |
| 原柜不可移动，空调有固定位置 | 三套方案锁定原柜、空调及其他确认设施 | 固定事实必须独立于家具布局方案 |
| 三套软装只改颜色，不符合要求 | R1.0 改家具位置、朝向、形态和组合 | 配色、家具样式、家具布局是不同能力 |
| 用户不需要预算模块 | 撤下预算及相关入口 | 不把额外功能当成完成核心需求的替代 |

后续新事实优先于此表；修改相关几何时应同步本表和示例假设。产品化路线仍为讨论稿。
