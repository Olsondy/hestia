# D08 分享链接预览与绑定验证

日期：2026-11-02。范围：工单 #37（服务端）。本机 PostgreSQL 14（独立库），未启动 Next.js；出图使用真实执行函数并注入 PNG。

## 实现要点

- **成员预置方案**：`POST /api/workspaces/{id}/leads` 由企业成员为客户准备示例别墅方案（来源 `member`，暂无客户），方案全部通过校验即发布。方案需求的“客户”改为可空，迁移 0028 同时记录创建者，客户提交的需求必须有客户。
- **分享**：`POST .../leads/{requestId}/shares` 只针对已发布的成员方案。填写手机号为定向分享；不填写则生成一次性绑定码（6 位，48 小时，5 次错误锁定）。链接令牌与绑定码只在首次返回，库中只存哈希；重试同一操作不再返回明文，提示撤销后重新分享。
- **预览**：`GET /api/share/{token}` 与 `GET /api/share/{token}/schemes/{id}/image` 无需登录，只返回已发布方案与效果图，不含客户、手机号、备注或确认记录；撤销、过期或未发布的链接一律返回失效。
- **绑定**：`POST /api/client/{entry}/shares/{token}/bind` 需要客户端登录。定向分享要求已验证手机号一致，否则 `PHONE_MISMATCH`（按已确认默认，不提供绑定码）；绑定码分享要求正确的一次性码。一个方案只绑定一个主客户，行锁保证并发时只有一人成功，其他人得到 `ALREADY_BOUND`。绑定后客户沿用 D06/D07 的接口查看、调整与确认。
- **申请与审批**：`POST .../shares/{token}/apply` 提交申请；成员 `POST .../applications/{id}/decision` 批准即绑定（其余待审申请作废），拒绝不绑定。
- **撤销与解绑**：成员可撤销链接（同时拒绝该链接下的待审申请）与解绑客户；客户自己提交的需求不能解绑。分享、绑定、解绑、撤销、申请、批准、拒绝都写入 `binding_events`，在成员线索中按时间返回。
