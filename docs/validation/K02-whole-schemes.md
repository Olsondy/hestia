# K02 整体方案（硬装 + 软装）与切换软装风格验证

日期：2026-11-03。范围：工单 #53。本机 PostgreSQL，HTTP 路由处理函数直接调用，出图任务用注入的渲染函数执行。

## 实现要点

- **数据**：迁移 `0004_scheme_soft_styles`：方案记录当前软装风格 `soft_style` 与可选风格 `soft_choices`，每个修订记录自己的 `soft_style`（均为风格与版本引用）。家具布局不单独保存，出图时由风格规则从项目原有家具确定地生成（`styledState`，K01 的 `furnish`）。
- **规则生成**：可选风格为企业目录中前 3 套在售风格；方案 A、B、C 依次以第 1、2、3 套为默认风格出图。企业目录没有风格时与之前相同（只有硬装）。
- **切换风格**：`POST /api/client/{entry}/requests/{id}/schemes/{schemeId}/soft-style` `{ operationId, expectedRevision, styleId, styleVersion }`。铺贴不变，生成新修订并后台出图；沿用 D07 的幂等、修订冲突、撤回（回到上一修订的风格并复用其效果图）与确认（确认绑定含软装的修订，之后再切换需重新确认）。不在可选范围内的风格 400，与当前相同 `NO_CHANGE`，已下架的风格 409；硬装调整保留当前风格。
- **视图**：方案返回 `softStyle`（名称、描述、色块）与 `softChoices`；已下架的版本仍能显示名称。客户端界面接入属于 H02。
