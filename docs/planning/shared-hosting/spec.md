## Problem Statement

甲方企业希望只负责面向客户的小程序（主体与小程序备案），服务端全部由我方托管。现在的代码按 ADR-0016 一家企业一套部署：入口由 `HESTIA_HOME_ENTRY` 指定唯一企业，账号的手机号与邮箱全局唯一，私有文件、后台队列与用量都没有按企业区分，跨企业访问也从未在同一套部署里测试过。要同时接入甲方 A 与甲方 B，只能再部署一套，固定成本与运维随企业数量成倍增长。

## Solution

按 [ADR-0017](../../decisions/0017-shared-hosting-tenant-isolated-accounts.md) 把部署改为我方运营的一套共享服务：

1. 每个企业工作空间登记入口域名，请求按域名确定企业，`/c`、`/w` 与客户接口只服务这一家。
2. 账号属于企业工作空间：同一手机号在 A、B 是两个账号，会话不跨企业域名。
3. 私有文件按工作空间分目录；后台任务按工作空间限制并发；用量按工作空间可查。
4. 支持导出与删除一家企业的全部数据。
5. 甲方小程序原生壳登录，经一次性票据进入 web-view 中的 H5。
6. 以两家企业、两个域名完成跨企业隔离验收。

## User Stories

1. As a 维护者, I want 用一条命令登记企业和它的入口域名, so that 接入新企业不需要新部署。
2. As a 客户, I want 从甲方 A 的小程序只看到甲方 A 的内容, so that 不会进错企业。
3. As a 客户, I want 在甲方 A 和甲方 B 用同一手机号各自登录、互不影响, so that 两家企业的方案与记录分开。
4. As an 企业成员, I want 只看到本企业的线索、方案、分享码、目录与文件, so that 客户资料不外泄。
5. As an 企业成员, I want 无法得知某客户是否也是其他企业的客户, so that 企业之间互不泄露客户关系。
6. As an 企业成员, I want 另一家企业批量出图时我的出图仍能及时完成, so that 不受别家用量影响。
7. As a 维护者, I want 按企业查看 AI 与出图用量, so that 能和企业结算。
8. As a 维护者, I want 导出或删除一家企业的全部数据, so that 企业停止合作或要求迁出时能交付。
9. As a 客户, I want 在小程序里一键登录后直接进入方案页面, so that 不必再输入验证码。

## Implementation Decisions

- 企业工作空间的入口域名、小程序凭据等按工作空间保存；敏感凭据加密，密钥来自环境变量，不入库明文、不进日志。
- 域名解析在服务端入口层完成，页面与接口共用同一结果；接口路径里的企业标识与域名不一致时按 404 处理，不泄露另一家企业是否存在。
- 账号增加所属工作空间；手机号与邮箱在同一工作空间内唯一。登录按请求域名所属企业查找账号，会话 cookie 只对当前域名生效，服务端再核对会话账号与请求企业一致。
- 现有数据迁移：每个账号归到唯一关联的企业；无企业关联的账号保持平台账号；关联多家企业的账号让迁移明确失败并列出，不静默合并。
- 私有文件键以工作空间开头；队列任务携带工作空间，Worker 领取时按工作空间限制同时运行数。
- 隔离以应用层访问检查为准，RLS 不在本规格内（ADR-0017）。
- 小程序登录使用适配器：测试与演示用模拟实现，生产用微信接口；没有真实 AppID 时如实记录未验证。

## Testing Decisions

只断言可观察行为与持久化结果。

1. **HTTP + 真实 PostgreSQL**：两家企业、两个域名下的页面与接口归属；同一手机号两个账号；会话跨域名无效；跨企业读写全部拒绝且不泄露存在性；迁移的拆分与报错；导出与删除的完整性；队列按企业的并发上限；用量按企业汇总。
2. **后台任务**：A 提交大量出图时 B 的出图在上限内被领取。
3. **真实浏览器（手机 390 与电脑 1440 视口）**：以 `a.localhost`、`b.localhost` 两个本地域名分别走客户登录 → 查看方案、成员登录 → 工作台，互不可见。

## Out of Scope

云厂商与资源选型、正式域名备案与上线；PostgreSQL RLS；每家企业独立数据库；企业自助开通与管理后台；计费与账单；个人工作台开放；跨企业的“企业分享给我的”；真实短信服务商接入。

## Further Notes

- 甲方负责小程序主体、备案与小程序后台域名配置；微信对业务域名主体的要求以接入时官方规则与审核结果为准（ADR-0017）。
- 本规格不依赖企业工作台剩余工单（W05、K03、W07、W06），也不恢复用户暂停的工单。
