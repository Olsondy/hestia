# M04 私有文件按企业分目录，企业数据导出与删除验证

日期：2026-11-10。范围：工单 #62，依据 ADR-0017。PostgreSQL 17.7（同 M01），真实出图执行器（注入 PNG）与临时本地文件存储。

## 实现要点

- **文件路径**：新文件写到 `workspaces/{企业}/projects/{项目}/resources/{资源}.{png|src}`（效果图、底图、上传图纸三处）。旧路径 `projects/…` 仍可读，`pnpm files:migrate-keys` 把状态为 ready 的旧文件移到所属企业目录并更新记录：先写新文件、再改记录、最后删旧文件，中断后重跑会接着做，第二次运行不再移动。
- **数据归属**：导出与删除都不写死表名，按数据库外键从企业逐层向下推出所有属于它的数据，以后加的新表自动包含。外键成环时拒绝执行。
- **账号**：企业的客户账号属于企业；成员的平台账号只作为“与这家企业打过交道的人”导出（id、姓名、邮箱、手机号、所属企业、创建时间），不删除。会话、密码、邀请、验证码、分享码失败记录、积分账本不导出，只随账号删除。
- **导出** `pnpm workspace:export <slug> <空目录>`：在一个只读的一致快照里导出，每张表一个 JSON（`tables/`），文件按原路径放在 `files/`，`manifest.json` 记录每张表的行数与 sha256、每个文件的大小与 sha256、找不到的文件。目录非空时拒绝。
- **删除** `pnpm workspace:delete <slug> --confirm <slug>`：确认标识不一致时拒绝。在一个事务里先删该企业在三个队列中的任务，再按“子表在前”的顺序删除数据和客户账号，最后删企业本身；提交后才删文件，事务失败时文件都不动，找不到的文件只报告、不中断。
- 两条命令只在服务端由维护者执行，不提供接口。

## 未验证

- 局域网开发数据库对应的文件在 Windows 主机上，本机没有对它运行 `files:migrate-keys`；正式环境需在文件所在的服务器上运行一次。
- 删除时正在执行的出图或 Agent 任务：队列任务会被删除，但已经在 Worker 里运行的那一次会在写回时发现记录已不存在而失败，不会写出新数据；没有专门测试这一时序。
- 导出包导入另一套部署不在本票范围。
