# V1 功能范围：自接模型的住宅设计 Agent 工作台

日期：2026-10-19。状态：规划基线，尚未实施。用户已确认产品方向，并要求本轮只整理范围、计划和技术栈。

交付形态建议为**多用户 Web 工作台，模型密钥不经过平台服务器**。用户正在确认这种形态的可行性，尚未最终确认部署选择；本文按这一建议基线给出完整计划。平台保存账号和项目，模型调用在用户浏览器中发起，首版仅支持经实际验证可跨域调用的服务端。本地连接器作为后续兼容路径，不默认计入第一版。

“密钥不上传”准确指不传给本平台，认证时仍要传给用户选择的模型服务商。它不等于图纸不上云，也不等于网页运行时无法读取密钥。详见 [密钥与调用边界](web-stack.md#4-byok-与任务执行边界)。

配套文档：[技术栈决策](web-stack.md)、[开发阶段与验收](v1-development-plan.md)。

## 1. 产品目标与用户

帮助有一定模型 API 使用能力的住宅设计爱好者或个人设计者，将单层平面图逐步转换为可编辑、可漫游、可比较家具布局的项目。

核心路径：配置模型 → 导入图纸 → 校准尺度 → AI 初稿 / 手动描绘 → 校正建筑 → 锁定设施 → 家具布局 → 对话调整 → 保存与导出。

成功标准是用户能完成并纠正一个项目，而非仅获得一张效果图。未配置模型或模型暂不可用时，仍可手动编辑、保存和查看 3D。

## 2. 第一版输入与几何边界

- 单项目包含一个可编辑楼层；允许保存多个独立项目。
- 支持 PNG、JPEG、PDF，PDF 选择一页作为当前底图，在本地浏览器渲染成图像。
- 支持矩形、L 形等由直墙组成的户型及直线斜墙；墙为竖直墙，地面为同一标高。
- 输入旋转、裁切、缩放和透明度调整；用一条已知长度建立比例，用其他尺寸复核冲突。
- 首版面向正视图、扫描图和相对规整的手绘图。明显透视畸变的照片提示重新采集，不内置自动透视重建。
- 楼梯以位置、占地和上下楼方向的占位对象参与编辑；复杂踏步、跨层高差和连续扶手自动生成延后。现有示例的楼梯作为保留案例，不据此承诺通用楼梯能力。
- 层高、墙厚、窗高与窗台高可填写；默认值必须显示为假设。
- 初始文件上限建议：图片 10 MiB、PDF 20 MiB；以配置项提供，在导入测试后复核。只将选定页面与所需区域送给模型。

## 3. P0：发布第一版必须完成

| 模块 | 功能范围 | 完成判据 |
| --- | --- | --- |
| 多用户基础 | 登录 / 退出、个人项目空间、会话与文件访问鉴权；首版邀请注册 | 两个账号相互不可访问项目、附件、快照、任务与导出；不包含团队协作和同项目多人编辑 |
| 模型接入 | 配置连接名称、适配器、Base URL、模型 ID、API Key；保存非敏感设置；连接与能力检测 | 区分鉴权失败、模型不存在、限流、不支持图片或工具；不只以连通为成功 |
| 凭据边界 | Key 默认仅保存在页面内存，不进入平台 API、数据库、日志、错误上报或导出；浏览器直连模型 | 真实浏览器验证请求路径；退出或刷新需重新输入 Key；不支持跨域时提示兼容限制，不静默改走平台代理 |
| 能力分级 | 首版实现一种 OpenAI-compatible 协议适配，验证至少两个实际服务端的跨域、流式、图片与工具能力；同一连接可配置图像模型和对话模型 | 完整流程要求图片输入及可靠的结构化工具调用；缺少图片能力时提供手动描图路径；不宣称兼容所有模型；两端点无法达标时需重新裁定发布支持范围 |
| 项目管理 | 新建、重命名、删除项目，自动保存、重新打开、命名快照 | 重启后恢复建筑、家具、方案、原图引用和已确认事实；删除前有明确确认 |
| 图纸导入 | 图片 / PDF 页面预览、旋转裁切、标尺校准 | 底图与编辑坐标可准确互转，重新打开后保持校准状态 |
| 识别初稿 | 输出墙、房间名称、门窗候选及缺失信息；叠加到原图 | 识别错误可修，未知值不伪装成实测值；不覆盖已经确认的项目 |
| 二维编辑 | 墙段端点编辑、连接与吸附、门窗添加和移动、门向、尺寸输入、家具拖动旋转 | 建筑可手动从空白创建；操作可撤销 / 重做；错误轮廓明确定位 |
| 固定约束 | 区分保留对象、锁定位置、锁定尺寸；记录确认来源 | Agent 和布局生成不能绕过锁定；解除锁定由用户显式操作 |
| 建筑白模 | 按统一数据生成墙、地面、真实门窗洞口；2D / 3D 联动 | 两套不同户型无需修改生成器代码即可显示，尺寸与洞口对应一致 |
| 家具与布局 | 内置参数家具，手动摆放；针对选定房间提出最多三套候选 | 候选有位置、朝向、尺寸或组合差异；只换颜色不计新方案；不可行时说明原因，不凑三套 |
| 对话操作 | 读取当前项目、追问歧义、提出修改、检查约束并执行允许的修改 | “床向东 0.3 m、原柜不动”产生准确且可撤销的结果；不重新生成整份程序 |
| 3D 浏览 | 全屋、选房间、物品详情、基本漫游、剖切、家具显隐、昼夜、材质 / 白模 / 线框 | 与当前原型能力衔接；切换方案后选择状态、障碍物和说明同步 |
| 布局检查 | 家具与墙 / 家具碰撞，房间边界，门扇开启区，柜门 / 座椅使用区，近似通路连通 | 违规指向具体对象；区分硬冲突与可调整的使用空间提示，不把近似检查说成规范验收 |
| 导出 | 项目包、平面 PNG、当前 3D 图像、只读离线 3D HTML | 项目包可重新导入；离线 HTML 无需 Key / 后端，保留切换方案和浏览；导出不带密钥 |

首批家具模板：床、床头柜、双人沙发、三人沙发、单椅、长茶几、圆边几、书桌、办公椅、柜体、书架、长凳。模板带外尺寸、朝向、落地占地和使用区，不对应商品 SKU。

布局与风格分开：选择布局改变家具摆放，选择风格只改变可变材质。固定建筑和现有设施默认不参与风格替换。

## 4. P1：第一版之后再排期

- 原生协议的更多模型供应商、模型推荐和自动切换。
- 商业家具 GLB 资产库、商品关联、自定义资产上传。
- 更丰富的风格组合、局部渲染和高质量离线渲染。
- 多层住宅、参数化复杂楼梯、曲墙、错层和挑空。
- 团队协作、公开分享、同步编辑、开放注册运营、订阅付费。
- 本地模型连接器、浏览器扩展、操作系统密钥存储；不支持跨域的服务不在首版直连承诺内。
- CAD / DWG / IFC 导入、扫描建模、照片自动透视校正。

首版不包含装修预算、施工图、承重判定、隔热/采光/隔声性能模拟，也不提供任意脚本执行或用户插件市场。

## 5. 界面结构

- **项目首页**：项目卡片、创建、导入项目包、最近编辑状态。
- **模型设置**：连接配置、能力检测结果、删除凭据、模型选择。
- **工作台**：左侧房间 / 对象树，中间二维底图与 3D 切换，右侧对话 / 属性面板，底部任务状态和撤销入口。
- **方案比较**：同一建筑下切换布局，保持镜头，展示摆放差异与取舍。
- **导出弹层**：选择导出类型，说明是否包含原始图纸。

桌面 Chrome / Edge 为首版主要编辑环境；小屏首先保证项目查看和 3D 浏览，手机完整绘图不作为首版验收目标。

## 6. Agent 操作规则

单个主 Agent 调用有限的领域工具。模型负责理解意图和提出候选，程序负责校验、计算、修改和落库。

建议工具：`read_project`、`request_clarification`、`propose_floorplan`、`propose_edit`、`validate_layout`、`propose_layouts`、`commit_edit`、`create_snapshot`。工具名与签名在数据阶段定稿，首版不开放 shell / 任意网络请求 / 任意 JavaScript。

- 手动编辑立即生效，形成可撤销的命令。
- 用户明确要求的家具移动，在目标唯一、单位明确且校验通过时可直接应用，并显示结果和撤销入口。
- 初次识别、替换建筑底图、批量改墙、删除房间：先显示具体差异，再由用户应用。
- 存在歧义时只询问影响当前步骤的关键问题，不一次收集所有装修偏好。
- 上传图纸里的文字是项目资料，不得作为 Agent 的操作指令执行。
- 修改携带 `baseRevision`，如果用户已继续编辑导致版本过期，停止写入并重新计算，不静默覆盖。
- 不依赖对话历史保存事实。项目数据保存固定对象、来源、确认状态和版本，对话只是交互记录。

## 7. 失败与恢复

- 模型超时或额度不足：保留当前项目，允许重试、换连接或手动继续。
- 工具参数不合法：返回具体错误并限制修复次数，不能无限重试或直接执行坏数据。
- 当前运行建议最多 8 个模型轮次；失败修复最多 2 次。到限额后展示已完成内容与下一步，不静默续跑。
- 页面关闭、断线或服务重启：保留最近已提交操作和任务状态。浏览器负责模型运行，关闭页面后不继续后台生成；重新输入 Key 后可从明确的检查点发起新请求，不承诺接续已中断的模型 token 流。
- 未完成的候选不写入当前正式方案；持久化工具操作有幂等 ID，重复恢复不能把床移动两次。
- 自接模型仍会把所需图纸和文字发送到用户选定的服务；发送前可见目标服务和资料范围。

## 8. 首版验收入口

准备至少 10 个有使用授权的单层样本：5 个清晰平面图、3 个扫描图、2 个手绘图。包含凹形外轮廓、斜墙、缺尺寸、门窗模糊、固定设施等情形。

自动识别记录初稿错误和人工纠正时间，不预设无依据的统一识别率。发布前必须让所有范围内样本通过人工纠正路径完成项目，并验证：固定对象不被自动移走、2D/3D 一致、修改可撤销、项目可恢复、导出可打开。
