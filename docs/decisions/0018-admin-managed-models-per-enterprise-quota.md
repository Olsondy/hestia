# 模型由平台管理员登记并分配给企业，按企业限额、按调用计量

用户于 2026-11-11 明确：企业端接入真实模型辅助功能前，模型不能写死在代码或部署配置里；要有模型配置管理页面，只能由管理员配置；Agent 交互处可以选择模型；不预置任何供应商；多家企业共用时要决定如何分配模型资源并统计用量。用户同时选定：

- 平台管理员（我方）登记模型与密钥并分配给企业；企业管理员只在分配给本企业的模型里启用、设默认，不接触密钥。
- 密钥由我方统一提供，按用量与企业结算（企业不自带密钥）。
- 每家企业指定可用模型并设月度额度，用尽即停；同时限制每家同时运行的 Agent 任务数。
- 用量按调用次数与输入、输出 token 统计，管理员为每个模型录入单价，折算为金额用于结算。

本决定覆盖：[ADR-0002](0002-agent-led-consumer-workflow.md) 与 `docs/agent/model-policy.md` 中“用户不凭型号选择、首版不提供模型切换”对**企业成员**的部分（客户与个人工作台不变）；`packages/conversation/src/admission.ts` 以代码内指纹登记唯一平台模型、运行时从 `HESTIA_MODEL_*` 环境变量读取模型的做法。AGENTS.md 中“C 端首版仅平台模型，不提供 BYOK/自定义端点”继续成立：企业成员只能在平台登记的模型里选。

## 决定

### 角色

- **平台管理员**是新角色，授予已有的邮箱账号（`pnpm platform:admin grant|revoke <email>`，只能在服务器上执行，不提供自助申请）。管理后台在 `/admin`，只在我方主域名（未登记给任何企业的域名）上提供；企业域名上访问一律按不存在处理（与 ADR-0017 一致）。
- **企业管理员**沿用工作空间成员的 `admin` 角色，在企业工作台的「设置 · 模型」里管理本企业的模型；普通成员只能在 Agent 交互处选择。
- 平台管理员的每次改动（登记、改价、换密钥、分配、调额度、停用）写审计记录：谁、何时、改了什么（密钥只记“已更换”）。

### 模型登记（平台管理员）

- 登记分两层（用户 2026-11-12 确认）：
  - **模型服务**：一组接口地址与密钥。包括服务名称（自由填写，仅作标注，成员看不到）、接口协议、接口地址、API 密钥、协议级兼容设置、超时、**总并发上限**（这个密钥下所有模型、所有企业共用，保护供应商限流）。
  - **模型**：服务里启用的一个模型 ID。模型 ID 从服务**获取**（Chat Completions 与 Responses 读 `GET /models`，Anthropic Messages 读 `GET /v1/models`）；服务不提供列表时由管理员手动添加。一个服务可以启用多个模型 ID，每个分别设置显示名称与说明（成员看到的，默认为模型 ID）、单次最大输出、模型级参数（思考模式、推理强度、思考预算）、输入与输出单价（元 / 百万 token）、状态（待检查 / 已准入 / 未通过 / 需重新检查 / 停用）。
  - 重新获取列表只读取服务商的模型清单、不计入额度；新出现的 ID 标为“新”，已启用但不再出现在列表里的 ID 标出提醒，不自动停用。
- **不预置供应商**：代码里只有**接口协议适配器**，不内置任何供应商名单、地址或模型；接什么全由管理员填写，登记时选择协议。首期支持三种协议（见下文「调用层与协议」）：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。新协议以新增适配器的方式加入。
- **兼容设置**：同一协议的不同服务商在细节上有差异（例如是否支持流式返回用量、思考参数的写法、最大输出的字段名），按服务设置；思考是否开启、推理强度等按模型设置。都只提供协议给出的有限开关，不允许填写任意请求体；接入检查按这些设置真实调用验证。
- **测试连通**：模型服务列表上每个服务都可以一键测试连通（也可全部测试）：用已存密钥发一次最小请求，记录是否连通、鉴权是否通过与耗时。它不计入任何企业的额度，不改变准入状态；连通失败在列表上醒目提示，企业成员调用时如实显示“模型服务暂时无响应”。
- **密钥**用服务端主密钥（`HESTIA_SECRET_KEY`，部署配置）以 AES-256-GCM 加密后入库；保存后只显示末四位，不回显、不进日志、不下发浏览器；更换密钥不改变登记 ID。接口地址生产环境必须为 HTTPS。
- **准入**：按模型（服务里的每个模型 ID）分别运行**接入检查**——用合成样本真实调用该模型，验证连通、流式、工具调用与 Hestia 协议（沿用 T01 的协议检查）；通过后记录检查时间、结果与证据，状态变为“已准入”。只有已准入、已填写单价的模型能分配给企业。改服务的接口地址、协议或兼容设置后，这个服务下已准入的模型都须重新检查；改模型的调用参数后该模型须重新检查；只换密钥做一次连通测试即可。这取代代码内的 `PLATFORM_ADMISSION` 指纹。
- **单价**有版本：改价从下一次调用起生效，每次调用记录当时的单价，历史用量不重算。
- 停用模型：新任务不能再选；进行中的任务在当前调用结束后停止并如实告知，已有成果保留。

### 分配与额度（平台管理员 → 企业）

- 平台管理员为每家企业指定**可用模型**（若干已准入模型）、**月度额度**（元）与**同时运行的 Agent 任务上限**。未分配任何模型的企业，Agent 入口显示“未开通”，不模拟结果。
- **额度按金额**：不同模型单价不同，统一折算为金额比较。月份按 Asia/Shanghai 自然月（与 M03 用量报告一致）。
- **执行时预占**：每次模型调用前按“输入估算 + 最大输出”预占金额，调用结束按实际用量结算、退回多余；供应商未返回用量时按预占额计入并标记“未核对”（沿用现有预算规则，不记零）。本月“已用 + 已预占”加上本次预占超过额度时，这次调用不发出，任务停在可恢复状态并提示“本月额度已用完”；已完成的成果保留。管理员调高额度后可继续。
- **并发**：企业同时运行的 Agent 任务达到上限时新任务排队（M03 的按企业公平队列），不拒绝；每个模型的总并发上限在所有企业之间共享，达到时排队。
- 企业管理员可在已分配的模型里启用或停用、设本企业默认模型；不能改额度、单价或分配。

### 选择模型（企业成员）

- Agent 交互处列出本企业已启用的全部模型（显示名称、模型 ID 与说明，不显示密钥、地址或单价），默认选中企业默认模型；额度已用完时整体不可用并说明原因。
- 任务记录所选模型登记及其版本；成员中途切换，从下一次调用起生效，已完成的步骤不重做。所选模型不可用（停用、准入失效、供应商故障）时如实提示并让成员改选，**不自动换用其他模型**（不同模型的成本与表现不同，不能替成员决定）。
- 客户端（H5、小程序）不出现模型选择。

### 调用层与协议

- **调用层沿用 AI SDK Core**（用户 2026-11-12 确认）。它已是 `docs/web-stack.md` 与 AGENTS.md 的技术基线，现有对话运行时（流式回复、工具参数边生成边解析）与 T01、T08、T10 的真实模型验证都建立在它上面。它是只负责“发请求、收流式结果与用量”的薄层：没有内置供应商目录与价格，可以按每次调用从模型登记现建实例，校验沿用项目统一的 Zod。
- 三种协议分别用 AI SDK 的官方协议包实现，按登记的地址与密钥现建实例：

  | 协议 | 实现 | 适用 |
  | --- | --- | --- |
  | OpenAI Chat Completions | `@ai-sdk/openai-compatible` | 大多数国内与第三方模型服务（`/chat/completions`） |
  | OpenAI Responses | `@ai-sdk/openai` 的 Responses 模型 | OpenAI 及兼容 Responses 接口的服务（`/responses`） |
  | Anthropic Messages | `@ai-sdk/anthropic` | Anthropic 及兼容其接口的服务（`/v1/messages`） |

  三个包与 `ai` 须共用同一版本的 `@ai-sdk/provider`，一起升级、一起锁定版本。
- 不论哪种协议，Agent 运行器看到的是同一套接口：流式文本、工具调用、结束原因、输入与输出 token。协议差异只留在适配器里；某协议或某模型不支持的能力，在接入检查中如实标为不支持，不在适配器里假装生效（沿用 `model-policy.md` 的规则）。
- Agent 的运行方式（持久化任务、关页不中断、崩溃恢复、旧执行不能覆盖新结果、预算与额度）始终由 Hestia 自己的后台运行器负责，不引入通用 Agent 框架的运行循环。

### 用量统计

- 每次模型调用记录：企业、成员、任务、模型登记与单价版本、输入与输出 token（未知则标记未核对）、折算金额、耗时与结果状态。
- 平台管理员看全部企业：按月、按企业、按模型汇总，可导出 CSV，用于与企业结算；企业管理员只看本企业：按月、按成员、按模型，以及本月额度剩余。`pnpm usage:report` 同步扩展。

## 考虑过的替代方案

- **继续用部署配置（环境变量）指定模型**：改模型要改配置并重启，不能按企业区分，也无法让成员选择；用户明确否决。
- **企业自带密钥（BYOK）**：企业自负费用、我方不用结算，但密钥分散、问题难以排查，且与“平台模型”的既定口径不一致；用户选择由我方统一提供。
- **只统计不限额**：实现最简单，但一家企业的批量使用会在月底前造成不可控的费用；改为月度额度、用尽即停。
- **共享总额度按比例分配**：企业之间的用量互相影响，结算不直观；改为每家独立额度。
- **按 token 而非金额限额**：不同模型单价差异大，同样的 token 额度对应的费用不同，不便于和企业约定。
- **调用层改用 pi-ai（`@earendil-works/pi-ai`，原 `@mariozechner/pi-ai`，MIT）**：它对各服务商的细节差异处理得更全，也能在会话中途换模型接续上下文；但它是为通用 Agent 产品设计的（最终用户自选供应商与订阅登录），核心是内置几十家供应商的目录与美元估价、环境变量与本地凭据文件、进程内的 Agent 循环，正好与“不预置供应商、人民币单价、密钥加密入库、持久化运行器”相反，用它要绕开大部分功能；依赖较重（会带入多家官方 SDK），包名刚迁移、1.x 较新；换用还要重写已验证的对话运行时并重做真实模型验证。以后若要接入大量非 OpenAI、Anthropic 协议且差异难以维护，可再评估只把它当作其中一个协议适配器使用。

## 影响

- 新增：平台管理员角色与 `/admin` 管理后台、模型登记与加密密钥、准入记录、企业模型分配与月度额度、调用级用量记录、审计记录。工单见 `docs/planning/model-management/`。
- 现有对话运行时（个人工作台，首期不开放）改为从模型登记读取已准入模型，`HESTIA_MODEL_*` 环境变量不再被运行时读取；依赖它的生产准入测试随之改写。真实模型验证仍须用真实接口与合成样本，不能用模拟结果冒充。
- 企业 Agent（K03 #54、W07 #56）以本决定为前提：任务绑定成员所选模型，调用经额度预占与用量记录。Agent 能使用哪些工具、产出什么另行决定，不在本决定范围。
- 新增部署配置 `HESTIA_SECRET_KEY`；它丢失后已存密钥无法解密，须重新录入。
- 平台管理员账号权限很高，首期只靠邮箱密码登录；双因素认证与登录来源限制作为后续加固另行决定。

## 补充（2026-11-12，部署方式、后台域名与超级管理员）

用户确认：

- **后台域名**：新增部署配置 `HESTIA_ADMIN_HOST`，只有这个域名响应 `/admin` 与 `/api/admin/*`；其他所有域名（我方主域名、企业域名、未登记域名）上一律按不存在处理。取代上文“只在未登记给任何企业的域名上提供”。共享部署为 `admin.<我方主域名>`（域名分配见 [ADR-0017](0017-shared-hosting-tenant-isolated-accounts.md) 补充）；独立部署由企业指定，例如 `admin.<企业域名>`。
- **独立部署**（ADR-0016 / ADR-0017）沿用同一套代码与页面，不分叉：平台管理员由企业指定的人担任，在本部署的后台里登记模型服务并**录入企业自己的密钥**，后台的「企业」只有这一家，分配、单价与用量用于企业自己核算成本。共享部署的密钥仍由我方统一提供，企业不自带密钥（上文替代方案中的否决只针对共享部署）。
- **月度额度可以设为“不限”**：只计量、不因额度停止；预占与用量记录照常。
- **超级管理员**（我方，用于排查问题）：不论共享还是独立部署都存在，可访问平台管理后台与该部署内所有企业工作台；与平台管理员一样只在服务器上用命令授予。进入企业工作台时在企业域名上用自己的邮箱登录（成员邮箱账号是平台账号，见 ADR-0017 补充），不加入、也不出现在企业成员列表；会话仍按域名隔离；每次进入写审计记录。进入后**只读**（用户 2026-11-13 确认）：能看项目、方案、Agent 任务与出错记录、企业设置与用量，不能改方案、发消息、改设置或启用模型，写接口在服务端一律拒绝；页头显示“平台支持 · 只读”。企业管理员在「企业设置 · 访问记录」里能看到超级管理员的每次进入（谁、何时、看了哪些页面）。需要替企业修改时，由企业成员操作或另行决定。
