# 企业 Agent 只调用已有、已校验的方案操作，结果一律为候选

用户于 2026-11-15 确认 K03（#54）的工具范围：企业 Agent 不获得新的自由能力，只调用系统里已有、带校验的业务操作；结果一律写成候选，成员采用、发布后客户才看得到。模型只提出方案，执行与校验都由应用完成（沿用 ADR-0002 / ADR-0005 与 `docs/agent/tool-contract.md` 的“模型提案、应用执行”）。

## 决定

企业线索的空间项目上，Agent 每轮仍是一次模型调用、一个 `resolve_turn` 提案（AM05 的额度预占与结算不变），新增一种提案 `propose_scheme`（整体方案）：

| 能力 | 模型给出 | 应用执行与校验 |
|---|---|---|
| 读当前方案与企业目录 | 不调用工具；应用把线索的饰面（含楼层）、企业在用石材（规格范围）、在用软装风格、已有方案摘要随本轮输入提供 | 只提供本企业在用版本，不含单价与其他企业资料 |
| 铺贴 | 每组饰面的石材、规格、铺法，可选波打线石材与宽度 | 石材按企业目录解析为在用版本并嵌入；饰面必须属于该空间；规格超出石材供货范围、排版冲突、石材不在目录都拒绝并返回原因（沿用 `set-tiling` 与 `inspectSurfaceDesign`） |
| 软装风格 | 一套软装风格，以及客户可切换的 2–3 套 | 只能从企业在用软装风格里选；按房间类型、逐楼层在原家具占地内换款并补充陈设（K01 `furnish`），放不下的陈设记为提示 |
| 出图 | 不能指定 | 只有通过校验的候选才排队出图（现有出图服务，确定性，无生成式 AI） |

- **结果是候选**：候选单独保存，不改线索已有方案、不改空间。成员“采用”后成为线索的**待审方案**，客户、分享码预览都看不到；成员“发布”后客户才看得到（线索本身已发布时）。
- **不做**：识别户型图纸；修正墙体等建筑结构；直接改当前方案；由模型给出家具坐标（新增或移动家具不开放给企业 Agent）。
- **重试与恢复**：同一轮的模型结果持久化后重放，只生成一个候选；采用、发布按操作标识幂等。
- **权限**：只有该企业成员能在线索空间上运行 Agent、查看候选、采用与发布（`project_access` 的 `member` 关系）；客户与分享码看不到对话与候选。

## 与 K03 原文的出入（实现时发现）

- **多楼层家具布局**：现有 `layout-planner` 只做个人项目的单房间“会客 / 办公”布局，产出的是移动家具的项目候选；企业方案（`finish_schemes`）只保存铺贴与软装风格，不保存家具摆放。所以本版的“按楼层与房间规划家具”由软装风格的规则换款与补充陈设完成，逐楼层、逐房间执行并校验；按房间移动或重排家具需要方案能保存布局，另立工单。
- **每套方案一套软装风格**：方案只引用一套软装风格（K02），不能“客厅一种、二层主卧另一种”。用户按房间提不同风格时，Agent 说明本版只能整套选一种，并按主要诉求选一种或追问。

## 后果

- W07（工作台 Agent 出方案界面）在此之上做对话面板、候选预览、采用与发布。
- 真实模型验收仍需在后台登记并分配真实模型（ADR-0018）；没有分配时 Agent 显示“未开通”。
