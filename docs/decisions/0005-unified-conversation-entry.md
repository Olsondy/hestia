# 统一对话入口，同一轮允许问答与设计操作并存

用户已确认统一对话入口。一条消息可以同时包含提问、设计修改和对已有任务的补充，不在入口把整条消息强制归类为“问答”或“设计任务”。模型结合上下文理解意图，可以输出说明和结构化工具请求；应用负责工具参数、范围、固定事实、几何、版本及采用规则的执行校验。问答结果与操作结果分别记录，回答完成不代表修改成功，修改失败不丢弃已完成的解释。

不增加专门的前置二分类模型作为默认路径，避免额外调用和错误分流。模型理解仍可能有误，意图或对象不明确时询问，整套方案采用继续执行已确认的成果确认规则。

用户随后确认模型调用统一放在 Worker 中执行，回复流式返回。普通问答走短执行路径，混合问答与修改无需从请求内临时移交后台；浏览器订阅断开不取消已接受轮次。查看项目、选择对象等不需要模型的交互不因此进入 Worker。

相较“普通问答在请求内、发现修改后转后台”，该选择减少两条执行路径及交接状态，代价是所有模型轮次都承担持久化、领取与事件转发开销；首字延迟需实测，不能承诺零开销。

用户随后确认整体实现架构定稿：采用 AI SDK Core + pg-boss + Hestia 专用有限状态运行器，领域执行器独立，回复通过 SSE 和持久化事件游标交付，见 [ADR-0003](0003-modular-monolith-with-durable-workers.md)。具体事件批量大小、调度参数和性能阈值仍需实测。[运行设计](../agent/runtime-design.md#21-统一对话入口与后台流式执行) 记录执行边界，不代表已实现或通过验收。
