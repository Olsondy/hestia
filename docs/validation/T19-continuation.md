## 能力与边界

沿用 T10/T17 的统一对话入口、持久用户输入、intentVersion、generation/lease、项目 revision、检查点、预算与候选事务。新输入和 dispatch 同事务持久化；旧生成线程在任意事件/项目提交边界都会因 generation fence 失权。用户修改项目之后旧响应不能覆盖新 revision。

T17 只允许最新消息完整复述“生成会客和办公布局”。现在允许当前任务原始用户消息已明确提出该单房间设计时，在活动设计中只补充受支持的保留条件，例如“原位保留沙发”，不需要重新描述会客和办公。应用从真实持久输入识别原始目标，核查其后每条输入、最新 intent、历史任务状态与所有既有硬需求；模型引用不足不会替代应用来源确认。模型不得从已采用完成的历史设计自动衍生新设计；用户再次明确提出完整新目标才可发起。

功能范围仍是单个矩形房间的会客与办公；被暂停、撤回、问句、引用、假设、不支持的新要求或任意无法核验的输入进入澄清，不声称覆盖任意自然语言。由原目标至本轮最多核对 8 条原文，超限必须先整理；这一限额不是产品额度。原位、不移动、保持位置和“不变”按保守策略固定全部已有可移动家具的当前权威项目位姿，避免猜对象边界；固定事实始终不变。若项目已被用户编辑，接受补充时读取最新实际 revision，按该时位姿重算，不沿用旧坐标。

应用只从同任务先前已持久历史 outcome 中定位候选，不接受模型指定候选。其归属、任务、来源意图、当前基础 revision 和完整原始快照必须匹配；取出对象仅作为待检输入，按最新事实和全部可验证要求重新运行既有几何、功能和通道检查。若仍满足，保存新的候选 ID、revision 和检查 ID，并在 `planReport.source.reusedFromCandidate` 记录来源；不复用旧检查、展示或选择授权。若不满足则继续有界搜索，保留原实物与约束；没有合格结果时不能伪造通过。旧候选继续保留历史，旧 intent 的候选/选择不可采用。任务仍等待用户查看和采用，新条件或确认不自动采用。

prompt 版本 `layout-continuation-5`、规划版本 `single-room-layout-2`，旧版候选/证据不改写。此次只改变应用计算与流式回复的数据，不改公开 HTTP schema；可选的来源字段只供读取报告。
