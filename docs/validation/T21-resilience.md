## 执行与配置边界

复用现有统一 `conversation-v1`、AI SDK `resolve_turn`、有限 `runTask`、pg-boss 调度、持久事件及 generation/lease/intent/project 栅栏。没有请求内模型调用、额外分类模型或第二套任务框架。

每个任务持久化 `conversation.execution`：配置、profile、每次尝试、调用次数上限、已知输入/输出 token、待核对预留、停止原因。正常补充、领取恢复、重试、阶段和 profile 变化均沿用此账本，不能通过续作清空。当前技术上限为 8 次调用、128000 token，单次输出 1600 token、20 秒；这是测试阶段的运行上限，不是用户积分、费用或最终产品额度。

单次预留为本轮序列化输入字节数加输出上限，输入超过 32000 字节则不发调用。这是应用保守预算估算，不是供应商精确计费或硬账单保证；system/tool 开销及分词以供应商实际报告为准。真实返回值完整记账，不截断为估计值；超限后不发后续调用。用量只返回一部分时记录已知部分，同时保留该尝试的预留，可能保守多占额度。

目前 `edit_fast` 和 `design_quality` 使用同一个经过 T01/T08/T10 真实合成小样验证的模型与相同权限门槛，不声称配置切换带来了已验证的质量差异。应用按当前轮次选参数：默认 `design_quality`，仅当唯一选中可移动家具且整条消息是受支持的单一明确平移或旋转指令时用 `edit_fast`。混合问答、开放式设计、问句、假设或未识别语法均保守用质量配置，不由上轮候选 scope 决定本轮 profile。

这一窄规则仅选择模型参数，所有消息仍走相同的一次模型理解与写入校验；其只读复用 `exactLocalCommand` 检查不会执行或授权空间修改。生产登记只含一套配置，没有已验证备用模型。

准入记录位于 `packages/conversation/src/admission.ts`，保存端点规范形式、模型 ID 与实际适配器版本的 SHA-256 指纹及证据路径，不保存端点或密钥。需要新调用时核对指纹，换端点/模型/适配器不能自动继承已验结论。2026-10-27 只读检查输出 `admitted: true, profileCount: 2`；没有输出凭据或端点。完整持久响应先复用，即使当前配置已不可用，也不因此重调或丢弃已保存成果。

## 重试、未知用量与恢复

只有供应商明确返回 429、没有生成文本/规范回复且没有正常完成的结果，才可在原任务内进行一次同配置重试；再次被拒绝时只允许使用已登记并通过对应 profile 准入的一个备用配置。生产没有备用时明确停止。SDK 自动重试为 0。

503、网络中断、超时或其他结果不明情形不自动重调。429 没有用量报告时也不记零：每次调用照计调用数，token 保持 null、保留预留并标记 `usage_unknown`。响应保存与用量结算在同一事务；重启复用已保存结果和拒绝记录，不重复记账。重试切换 generation，丢弃旧尝试的展示片段，防止把两次回复拼成一次。

取消、用户新输入替代、领取恢复耗尽及业务失败均先结算在途账项再释放执行占用；释放 lease 或 `usage_reserved` 不等于删除未知 token 预留。旧版任务迁移时，历史及当前完整响应缺少任一 token 的用量也保守保留；还未开始调用的排队输入不会虚构消耗。同一在途账项重复结算不会再次创建 `legacy-unresolved` 记录或双倍预留。

## 已有成果与状态

`conversation.retained` 返回真实已保留的回答、需求数量及候选引用。失败时存在可用成果使用 `partial`，没有成果使用 `failed`；正文、来源、候选仍可查看。`waiting_input` 表示当前缺必要信息；`waiting_selection` 表示已生成候选等待用户采用，两者均不作为已完成整套设计。单房间候选采用由既有候选展示、选择、检查和事务完成，匹配任务才结束等待；T17 验收另记。

同一轮同时整理 `brief` 和提出 `propose_layout` 时，`prepareLayoutProposal` 先检查模型未伪造或遗漏既有硬需求，再应用严格来源提案，并补入应用生成的新明确需求 ID。用户完整原文把旧建议升级为明确需求时，沿用该条 ID 并加入有效提案；模型不能靠新增摘要绕过旧条件。完整 brief 与有效决策在同一 fenced 事务保存，再生成并检查候选，当前方案不因此自动改变。
