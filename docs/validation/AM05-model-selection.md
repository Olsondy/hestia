# AM05 Agent 选择模型，运行时改读模型登记验证

日期：2026-11-14。范围：工单 #71，依据 ADR-0018 及其 2026-11-14 补充（个人工作空间同样由我方分配模型；有后台权限的账号在工作台有入口）。PostgreSQL 17.7（局域网主机上的本地 Compose 容器，经 SSH 隧道映射到 127.0.0.1:54329），对话运行器真实执行，模型为本机假服务。

## 实现要点

- **运行器取模型**（`packages/conversation/src/configurations.ts`、`run.ts`）：按任务所属项目的工作空间，从模型登记取所选模型；没有选择时用空间默认模型，再没有就用第一个已启用、已准入的模型；一个都没有时任务停止为 `MODEL_NOT_GRANTED`（“还没有开通可用的模型，不会模拟结果”）。所选模型被停用或准入失效时停止为 `MODEL_UNAVAILABLE`，**不自动换用其他模型**；原来“有限重试后换备用配置”的路径在登记模型下没有备用项，提示改选。
- **删除**：`PLATFORM_ADMISSION` 指纹（`admission.ts`）、从 `HESTIA_MODEL_*` 构造模型的 `configuredModel`、`productionConfigurations`。运行器与 Web 不再读取 `HESTIA_MODEL_*`；只有 `scripts/validation` 下独立的 T01/T02 评估脚本仍从这些变量取模型。两个实时布局验证脚本改为 `HESTIA_VALIDATION_MODEL`（登记里一个已准入模型的 id）。依赖指纹的生产准入测试改写为配置筛选测试，登记路径由新测试覆盖。
- **额度**：每次调用前 `reserveCall`（输入估算按上下文字节数 + 8000，只会多估），企业或服务并发已满时在运行器里排队最多 2 分钟，超时停止为 `MODEL_QUEUE_TIMEOUT`；额度不足时不发出调用，停止为 `QUOTA_EXCEEDED`。调用结束且结果持久化后 `settleCall`；重放已保存的结果、或发现先前调用结果未知时，按记录的预占 id 再结算一次（结算幂等，未知用量按预占额、标为未核对）。预占后如果在发出前就因冲突停止，按 0 释放。
- **选择与切换**：创建对话任务与追加消息都可带 `modelId`；只能选本空间已启用、已准入的模型（否则 409）。追加消息时的切换从下一次调用起生效，已完成的步骤不重做。
- **页面**：可复用的模型选择组件 `components/enterprise/model-picker.tsx`（只显示名称、模型 ID 与说明；额度用完时禁用；未开通时说明原因），供 W07 的 Agent 面板接入。`/api/session` 对有后台权限的账号返回后台地址，「企业设置 · 模型」据此显示“在平台后台配置模型”，没有权限的账号看不到。

断言摘要：没有分配模型时任务停止为“未开通”，没有任何请求发到模型服务；选未启用的模型创建任务 409。分配并启用两个模型、设默认后，任务用默认模型调用，调用记录已结算：输入 100、输出 30 token、1 分、非未核对。指定模型创建任务时用指定模型；追加消息时切换，下一次调用换成新模型，两次调用记录各自对应。所选模型被平台停用后任务停止为 `MODEL_UNAVAILABLE`，没有换用另一个已启用的模型，也没有发出请求；额度为 0 时停止为 `QUOTA_EXCEEDED`，没有请求、没有调用记录。
