# D07 客户选项式调整与确认验证

日期：2026-11-02。范围：工单 #36（服务端）。本机 PostgreSQL 14（独立库），未启动 Next.js；出图只入队，不执行。

## 实现要点

- **方案修订**（迁移 0027 `finish_scheme_revisions`）：D06 的已发布铺贴方案即本票的候选；每次调整生成新修订，经 D04 排版校验后入队重新出图。工单原文写“候选修订”，此处以方案修订实现，采用规则相同：修订号检查、操作幂等、绑定具体版本。
- **可选项**（`GET .../schemes/{id}/options`）：每个饰面列出企业石材库中的有效石材及其可供规格、该部位允许的铺法（地面四种，墙面直铺/工字，楼梯直铺）和是否可加波打线。
- **调整**（`POST .../schemes/{id}/adjust`）：一次改一个饰面的石材、规格、铺法或波打线；不在选项内的拒绝（`OPTION_NOT_ALLOWED`、`STONE_NOT_AVAILABLE`），排版冲突拒绝并给出原因（`ADJUSTMENT_REJECTED`，附问题列表），方案保持不变。同一操作重试不重复出图。
- **撤回**（`POST .../schemes/{id}/undo`）：回到上一次调整前的内容，生成新修订并复用那一版的效果图；可连续撤回到初始方案。
- **确认与留言**（`POST .../confirm`、`POST .../messages`）：确认绑定方案的具体修订，可附留言、请求联系与方便时段；确认后仍可调整，调整后 `confirmation.current` 变为 false，需重新确认（已确认的默认规则）。确认与留言写入线索事件，成员线索接口返回。
