## Problem Statement

一套部署只能服务 `HESTIA_HOME_ENTRY` 指定的一家企业，无法让甲方 A、甲方 B 共用同一服务。

## Solution

企业工作空间登记入口域名，服务端按请求域名确定企业，入口页、客户端 `/c`、工作台 `/w` 与客户接口都只服务该企业。

## User Stories

1. As a 维护者, I want 用命令为企业登记、更换或移除入口域名, so that 接入新企业不需要新部署。
2. As a 客户, I want 打开甲方 A 的域名只看到甲方 A 的入口和方案, so that 不会进错企业。
3. As a 维护者, I want 不认识的域名显示我方入口页, so that 配错时不会接到别家企业。

## Implementation Decisions

- 新增工作空间入口域名（全局唯一、小写、不含端口），一个企业可有多个。`pnpm workspace:domain <slug> add|remove <host>` 管理，幂等。
- 入口层按 `Host` 解析企业（经可信代理时读取转发头，规则与现有限流取 X-Forwarded-For 的方式一致）；解析结果供页面与接口共用。`HESTIA_HOME_ENTRY` 仅在域名未登记时作为回退，供本地开发与单企业部署使用。
- `/api/client/{企业}/…` 的企业标识与域名所属企业不一致时返回 404；工作台接口同样只接受域名所属企业。
- 主域名与未登记域名：入口页提示“请使用合作企业提供的入口”，`/c`、`/w` 不接到任何企业。
- 分享码在其所属企业的域名下才能打开，其他企业域名下按不存在处理。

## Testing Decisions

- [x] HTTP + PostgreSQL：两个域名分别解析到 A、B；接口企业标识与域名不一致为 404；未登记域名不接企业；`HESTIA_HOME_ENTRY` 回退仍可用；B 的分享码在 A 域名下不存在；域名命令幂等。

见 [M01 验证](../../validation/M01-domain-entry.md)。

## Out of Scope

正式域名备案与证书；成员登录后选择工作空间的界面；企业自助配置。
