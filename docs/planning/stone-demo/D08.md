## Problem Statement

企业成员做好的方案要发给客户。客户不应被迫注册才能看；但转发出去的链接不能让别人控制方案。

## Solution

分享链接只授予预览；登录并满足强制条件后绑定为项目主客户，获得调整与确认能力。成员可以撤销、解绑与重新分享。

## User Stories

1. As a 客户, I want 不登录打开链接就能看到方案, so that 门槛最低。
2. As a 客户, I want 登录后自动绑定分享给我的项目, so that 继续调整与确认。
3. As a 客户, I want 用绑定码或提交申请完成绑定, so that 员工不知道我的手机号时也能使用。
4. As a 客户, I want 别人拿到我的链接也无法绑定, so that 方案受到保护。
5. As an 企业成员, I want 撤销链接、解绑和重新分享并留有记录, so that 能处理发错或换人。

## Implementation Decisions

- 分享令牌不可猜测、只存哈希，可设有效期，可撤销；只授予已发布方案的预览，不暴露其他项目、客户或成员信息。
- 绑定条件（满足之一）：定向分享填写的手机号与客户已验证手机号一致；一次性有时效的绑定码，错误次数受限；客户提交绑定申请由成员批准。
- 一个项目一个主客户；已绑定后其他人只能预览。主客户或成员可以邀请他人加入。绑定、解绑、撤销与审批都写入记录。
- 成员侧操作只提供服务端接口，供种子脚本与后续工作台使用；客户侧页面在 H5 实现中完成。

## Testing Decisions

- [ ] 未登录可预览已发布方案，不能调整或确认；撤销或过期后不可访问。
- [ ] 三种绑定条件各自成功与失败；手机号不匹配、绑定码错误或超限、未批准均不能绑定；并发绑定只有一个主客户。
- [ ] 解绑后原客户失去调整权限；全部操作有记录。
- [ ] 经 HTTP 接口完成：令牌预览 → 登录 → 绑定 → 调整。

## Out of Scope

成员分享界面、微信卡片分享、小程序内打开限制。
