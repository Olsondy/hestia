# Hestia V1：由 Agent 完成单层住宅设计

发布状态：已获用户批准并发布为 [总工单 #1](https://github.com/Olsondy/hestia/issues/1)，标签 ready-for-agent；24 个子工单及原生依赖已核验。用户已确认技术架构并明确恢复开发，按依赖推进并允许独立子工单并行。

## Problem Statement

个人用户希望把住宅图纸和居住需求变为可比较、可调整、可展示的设计，而不是先学会完整设计器、配置模型服务或逐条指定家具坐标。现有原型有本地项目、示例空间、家具编辑与演示指令，但没有真实模型、自动识图、通用几何校验或可在离开页面后继续的任务服务，无法完成真实住宅的整套设计委托。

## Solution

提供平台模型驱动的设计助手：从单层图纸与需求出发，建立可纠正的空间初稿，处理尺度及固定事实，连续设计家具布局与视觉风格，展示一个完整推荐及有实际取舍时的一个替代。用户采用成果后可继续对话修改，并查看交互 3D 和静态图。

Agent 自主组织候选工作，应用负责权限、事实、几何、版本和提交。明确且唯一的局部移动、旋转或材质变化可以直接应用并撤销；初始空间、整套设计、替换及删除在具体成果边界确认。平台任务可在关页后继续、重开恢复并接受取消。

## User Stories

1. As an 个人用户, I want 直接描述居住人数、生活习惯和设计目标, so that 助手能围绕我的生活需求设计。
2. As an 个人用户, I want 无需填写模型 Key 或选择供应商, so that 我可以直接开始设计。
3. As an 个人用户, I want 创建并重新打开独立空间项目, so that 不同住宅的资料与方案不会混在一起。
4. As an 个人用户, I want 导入图片或选择 PDF 中的一页, so that 助手处理正确的单层图纸。
5. As an 个人用户, I want 调整图纸旋转、裁切与叠图显示, so that 我能核对识别结果。
6. As an 个人用户, I want 看到来自原图的墙、门窗、房间初稿, so that 不会把示例户型误认为我的住宅。
7. As an 个人用户, I want 识别不确定项及默认值明确标示, so that 我知道哪些信息仍需核对。
8. As an 个人用户, I want 通过点选或对话纠正墙与门窗, so that 无需开发者修改数据即可修正初稿。
9. As an 个人用户, I want 提供一条有来源的可靠长度并复核其他尺寸, so that 空间可以建立可信尺度。
10. As an 个人用户, I want 缺尺寸时仍能探索需求、功能与风格, so that 任务不会完全停住。
11. As an 个人用户, I want 概念草稿自身注明未校准, so that 不会把示意摆放理解为实际放得下。
12. As an 个人用户, I want 补充尺寸后重新计算几何和布局, so that 后续结果依据更新后的空间。
13. As an 个人用户, I want 确认初始空间和固定设施, so that 方案比较不会改变已经确认的住宅条件。
14. As an 个人用户, I want 单独纠正确实有误的固定事实, so that 不必通过普通布局操作解除保护。
15. As an 个人用户, I want 助手保留明确需求和已有家具条件, so that 设计不会在多轮对话后偏离目标。
16. As an 个人用户, I want 助手自行安排候选生成与检查步骤, so that 不需要逐个批准工具调用。
17. As an 个人用户, I want 得到一个完整推荐, so that 能先判断一套可用设计。
18. As an 个人用户, I want 在确有取舍时比较第二套布局, so that 我可以在不同使用方式间选择。
19. As an 个人用户, I want 布局比较展示真实家具位置、朝向和组合变化, so that 不会把换色误认为新的布局。
20. As an 个人用户, I want 材质与展示灯光保持整体风格, so that 可以评估空间观感。
21. As an 个人用户, I want 知道哪些需求已满足、哪些存在冲突, so that 可以作有依据的取舍。
22. As an 个人用户, I want 预览候选时保留当前方案, so that 浏览不会自动改掉已采用设计。
23. As an 个人用户, I want 采用已展示的具体候选只确认一次, so that 无需逐件家具重复确认。
24. As an 个人用户, I want 明确局部修改快速且准确应用, so that 日常微调不需要重新生成整套方案。
25. As an 个人用户, I want 对象或方向不明确时得到必要澄清, so that 助手不会猜错目标。
26. As an 个人用户, I want 指定修改不可行时看到具体冲突, so that 助手不会偷偷缩短距离或移动其他家具。
27. As an 个人用户, I want 替换和删除前看到具体结果, so that 可以判断是否采用。
28. As an 个人用户, I want 撤销已提交变化且不覆盖后续编辑, so that 调整是可控的。
29. As an 个人用户, I want 生成过程中补充保留条件, so that 后续操作使用最新要求。
30. As an 个人用户, I want 关闭页面后任务继续, so that 不必持续守在工作台。
31. As an 个人用户, I want 重开页面恢复进度、问题和成果, so that 不必重复发起任务。
32. As an 个人用户, I want 随时取消并看到已完成的真实部分, so that 可以停止不需要的工作。
33. As an 个人用户, I want 模型故障或达到平台上限时保留成果, so that 失败不会抹掉已有工作。
34. As an 个人用户, I want 交互 3D 与静态图来自同一方案修订, so that 展示与设计数据一致。
35. As an 个人用户, I want 离线期间也能完成静态图任务, so that 重新打开后能取得成果。
36. As an 个人用户, I want 我的项目和文件仅对有权访问的人开放, so that 其他用户不能通过猜测资源标识读取或修改。
37. As an 平台维护者, I want 追踪模型、工具、规则、prompt 和资产版本及任务用量, so that 可以复现问题和评估升级。
38. As an 平台维护者, I want 通过真实样本检验设计质量和局部响应速度, so that 发布结论有可检查的证据。

## Implementation Decisions

- 沿用 ADR-0001 的固定事实与布局分离，以及 ADR-0002 已确认的 Q1–Q8。实现技术栈已按 ADR-0003–0005 定稿；组件版本及能力仍需验证，供应商和部署研究候选不视为已确认。
- 采用一个主 Agent、有限工具和服务端持久化任务。并行开发的子 Agent 是开发组织方式，不代表产品采用多 Agent 架构。
- 项目与任务服务是外部行为入口；供应商适配、任务运行器、领域执行器及渲染输出分离。视图和聊天均不直接成为项目事实来源。
- 平台持有长期模型凭据，不进入浏览器、模型上下文、项目或成果；首版无用户 Key、自定义端点及任意代码执行入口。
- 应用选择质量优先或局部速度优先配置；两者共用权限、范围、固定事实、尺度、几何和提交门槛，不预设必须采用两个模型。
- 稳定对象标识、米制长度、弧度和 x/z 领域平面是共享契约；北向单独记录。外部毫米及 x/y 数据需显式适配。
- 需求与事实记录来源；概念、估算、校准、冲突及用户确认分离。颜色和厚度推断不能成为承重或施工结论。
- 候选隔离于当前方案，允许保留待解决的几何问题；权限违规、固定事实修改以及缺少必要检查不能借候选绕过。硬冲突阻止正式采用。
- 正式提交绑定项目基础修订、候选修订、检查报告和真实授权事件；模型不能提交自造确认标志。一次批量变化及幂等结果原子持久化。
- 撤销依据已提交变化及后续依赖处理，不用旧快照覆盖新编辑；手动输入和 Agent 共用领域命令。
- 固定事实纠正走独立应用入口，用户确认具体影响后形成新基础版本，并使相关候选、检查与成果过期。
- 后台通过持久化检查点、执行租约和递增代次恢复。新需求、取消及提交在写入边界复核；失效工作进程或迟到响应不能继续产生副作用。
- 任务预算包含重试、恢复、回退及未知外部用量预留。到上限保留部分成果，不能通过改任务标识绕过限制。
- 目录限定资产、材质及参数范围；布局生成使用有限能力和确定性检查，默认一个推荐，有实际取舍时最多两个。
- 静态图在后台按指定修订生成，交互 3D 使用相同数据、资产与渲染规则；输出候选不隐含采用。
- 复用现有 UI、镜头、示例资产和可验证行为；本地快照不是服务端事务，演示规则匹配不是 LLM，外部模板调试接口不是稳定生产契约。
- 身份、持久化/调度及渲染组件按已确认技术栈实施；供应商、精确版本和发布阈值由前置验证确定，后续切片不各自另建基础设施。

## Testing Decisions

- 推荐主要公共测试边界为“用户事件进入项目/任务服务 → 可查询的任务结果、项目修订及成果”。内部执行器和存储真实运行，供应商使用可控替身；只断言外部行为，不依赖模型私有推理、内部函数调用顺序或实现镜像。
- 沿用现有失败编辑不污染历史、移动持久化及撤销、锁定与非法数值拒绝的行为案例，升级为公共服务契约测试。演示文本解析只保留演示回归。
- 为坐标转换、轮廓/开口、旋转占地、斜墙凹形、尺度矛盾及容差边界保留少量独立几何测试；检查项必须区分通过、失败、未检查和不适用。
- 强制反例包括越权、跨项目读取/修改、固定事实绕过、过期采用、重复操作、共享材质污染和缺尺度采用；已知关键反例失败不能进入试用。
- 用协议替身注入截断、重复事件、拒绝、超时和迟到结果；用真实持久化验证关页、进程重启、租约失效、提交后响应丢失、新需求与取消竞争。不能 mock 掉事务和版本检查后声称恢复可靠。
- 浏览器覆盖导图、选页、纠错、采用、局部编辑、撤销、取消、重开与下载；人工检查 2D、3D 和静态图一致性，两种视觉若均保留则共用业务流程验收。
- 真实模型评估单列，固定配置与样本，记录需求满足、人工纠正、不必要追问、局部准确性、端到端时间和整任务用量。协议替身不证明识图和设计质量。
- 使用 5 个清晰图、3 个扫描图、2 个手绘图及人工基准；缺尺寸样本准备后续补充资料，验证概念与补充后完成。阈值先冻结，完整任务实测后有据校准，不在最终验收时为通过而改标准。
- 每个子工单随自身能力交付验证；最终验收汇总真实样本、组合故障、部署恢复及试用反馈，不将测试全部推迟到最后。

## Out of Scope

完整 CAD 编辑器、原生 CAD/DWG/DXF、多层、自动透视重建、结构改造或工程合规结论、预算报价、水电施工、room tour 视频、独立 AI 美化成片、BYOK、自定义模型端点、通用插件、任意代码执行、团队实时协同及未经确认的商业套餐。

## Further Notes

- 开发遵循先验证、统一契约、真实局部闭环、图纸校正、整套设计、成果与试用的顺序。局部修改只是内部里程碑，不是首版完成条件。
- 总工单用于规格，子工单用原生父子关系和阻塞边表示执行依赖；只领取阻塞项全部完成的前沿任务。`ready-for-agent` 表示规格准备程度，不等于没有依赖。
- 平台测试凭据/额度、授权样本和目标环境当前是待核验条件，不未经检查认定缺失；仅阻塞依赖它们的实际验证，不阻塞合成夹具与协议测试。
- 总规格发布后，子工单发布流程不改写或关闭父工单正文；关系维护与子工单进度单独处理。任何原生关系失败都需如实记录，正文引用不冒充已建立原生关系。
- 本文已发布，真实工单映射见发布清单；工单只引用必要的架构文档与原型目录，不粘贴实现代码。用户已恢复开发，按依赖与验收顺序推进。

## 已确认架构与本轮执行约束（2026-10-25）

用户已确认 `docs/web-stack.md`、ADR-0003–0005 并明确恢复开发：按原生依赖顺序推进，可独立工单由子 Agent 并行；验收通过后才能关闭或解除下游阻塞。精确版本及实际能力需验证，部署方案另议。

- TypeScript strict + pnpm workspace；Next.js App Router / React 承载 Web 与 API，PostgreSQL + Drizzle 保存业务与身份数据。
- 所有需要模型理解的消息统一持久化后由 Worker 执行；AI SDK Core + pg-boss + Hestia 专用有限状态运行器，领域执行器独立；SSE 返回可恢复的事件流。
- 2D 使用 Konva；3D 复用 Three.js 场景适配器；Playwright Chromium 后台出图与交互场景共享数据与资产。
- Better Auth 邀请制邮箱密码登录，私有对象存储隔离文件；具体供应商、部署规格与费用仍未定。

- 所有涉及 UI 的页面统一采用家居杂志（editorial）作为生产视觉基线，参照用户亲自迁移并确认保留的 `example/prototypes/projects` 原型：源码 `example/prototypes/projects/src`，可访问产物 `example/prototypes/projects/index.html`。使用用户指定的 `impeccable` 技能，继承该方向的间距、字体层级、布局与动画；遵循 `DESIGN.md`，不启用 hooks。中文统一使用仓耳渔阳体（Tsanger YuYang）并保留许可。建筑展馆仅作为原型历史保留，不要求生产双主题。
- 原型迁入 `example/prototypes/projects` 后保持可访问，不把演示助手、本地存储或示例空间冒充生产能力。新增 UI 需浏览器检查，自动测试不能替代视觉验收；无 UI 变更的票不强制新增页面。
- 外部凭据、真实样本和环境不足时记录具体未验证项；继续无依赖准备工作，不伪造模型或验收结果。单票共享文件与契约由主 Agent 协调，保持现有父子关系和阻塞边。
