## Problem Statement

用户需要在开始设计前知道积分消耗，并在取消、失败和恢复时得到一致的扣退结果。当前任务基础仅完成确定性协议执行，尚无积分结算，不能把“任务运行中”当作已经发生模型费用。

## Solution

在既有 AI 工作流接入固定报价、接受时预留、首次调用模型时扣除、最终系统失败/部分完成时退款。调用前取消免费，调用后用户主动取消照扣；已有成果在余额耗尽后继续可用。用户积分与供应商用量分别记录，方便之后按真实成本调整配置。

## User Stories

1. As an 注册用户, I want 接受任务前看到固定积分价格, so that 能决定是否开始。
2. As an 注册用户, I want 余额不足时不能接受新任务, so that 不会产生超出余额的扣费。
3. As an 注册用户, I want 同一账号多个项目不能重复占用同一份余额, so that 并发任务不会超花。
4. As an 注册用户, I want 排队取消后释放全部占用, so that 未调用模型时不损失积分。
5. As an 注册用户, I want 首次调用模型时只扣一次本次固定积分, so that 多步调用不反复收费。
6. As an 注册用户, I want 明白调用后主动取消仍会扣分, so that 对停止任务有合理预期。
7. As an 注册用户, I want 追问、内部修正和自动重试包含在原价中, so that 不被额外加价。
8. As an 注册用户, I want 关页、断线和恢复不重复扣费, so that 可以放心稍后回来查看。
9. As an 注册用户, I want 系统最终失败或只完成部分时全额退回, so that 不为未完成的交付支付积分。
10. As an 注册用户, I want 退款后仍保留可用成果, so that 已有工作不丢失。
11. As an 注册用户, I want 未采用正常交付的候选仍按原报价结算, so that 是否采用与任务是否完成清楚分开。
12. As an 注册用户, I want 余额耗尽后仍能查看、手动调整和导出已有成果, so that 我的设计不会被锁住。
13. As an 注册用户, I want 调价不改变已接受任务的扣退金额, so that 不会被事后涨价。
14. As an 维护者, I want 任务积分与真实模型用量可分别追溯, so that 可以用供应商费用反推试用配置。

## Implementation Decisions

- 阶段：M2/M5 任务集成及 M6 用户流程验收。所属规格：https://github.com/Olsondy/hestia/issues/26；前置依赖：C01/#27、T08/#9、T21/#22。T07/#8 是已完成的后台基础；复用 T22/#23 的组合故障先例，不另造任务状态机或循环依赖。
- 遵守 ADR-0006 的已确认扣退规则，以及 ADR-0005 的统一 Worker、关页继续、SSE 恢复；资源归属和项目操作校验保持不变。
- 使用 C01 的配置及积分记录，服务端确定工作类型、价格与范围，并固定保存到已接受工作。初值为问答 1、小改 5、整套设计 20；不接受客户端自报金额，不按内部模型/工具调用或家具数量逐次扣分。
- 工作接受与积分预留保持原子性、幂等性；不足时不留下任务或账务残留。所有需要模型的工作，包括不创建完整设计任务的普通问答，均经过同一余额约束，不能从聊天入口绕过。
- 首次开始供应商模型调用时将预留转为扣除一次。队列领取、running 状态、纯本地准备、静态渲染或已返回文本不能冒充模型调用开始。不得为了预估费用先进行未纳入身份和用量约束的隐藏模型调用。
- 持久化调用开始与取消的先后关系，避免扣分后崩溃、调用结果丢失、迟到响应和重复事件造成重复扣退或错误免单。供应商未知用量按既有恢复规则核对，不宣称外部调用严格只执行一次。
- 调用前取消释放占用；调用后主动取消保留扣除。用户取消导致的中断不按系统失败退款；关闭页面不触发取消。系统最终 failed/非用户取消的 partial 且未完成交付全额退回，重试期间不提前退回。正常交付保留扣除，不以是否采用候选判断退款。
- 保留已有可用成果和真实已提交修改。积分不足只阻止新增 AI 工作，不影响查看已有 3D、手动调整、采用已有候选及无需 AI 重新生成的导出；不显示不可购买的升级套餐。
- 重试、恢复、重复消息与终态只能形成一次对应的积分变动。取消和失败竞争依据持久化事实归因，同一工作不能既已退款又被迟到事件重新扣费。
- 用户积分不复用 protocol-step 预算；按既有用量追踪记录模型调用、重试、取消及失败的供应商用量，未知用量明确标示，不能记零。保留任务报价版本，使维护者后续改配置不改变旧工作金额。
- 不将 Q13–Q15 的未确认收费细则、验证邮箱条件作为必选验收项；不新增复杂积分档位或大量弹窗。沿用已有工作范围与候选采用边界，完整交付必须对应真实成果，不能只信模型宣称成功。

## Testing Decisions

复用用户已认可的“任务公开服务 + 真实 PostgreSQL/pg-boss”和真实浏览器入口。供应商使用可控协议替身，内部数据库、队列和执行器真实运行；只断言余额、任务状态、可查询成果和外部权限，不镜像内部实现。

- [ ] 普通问答与设计工作都受余额约束；同账号跨项目并发不会超花，重复接受不重复占用，余额不足无残留。
- [ ] 队列运行但尚未调用模型时取消释放占用；真正调用后取消保留固定扣除；状态页和余额一致。
- [ ] 同任务多步调用、追问、自动重试、断线、重复事件和恢复不会重复扣分；纯本地示例或静态渲染不误触发模型调用扣分。
- [ ] 最终系统 failed/partial 全额退款一次，已有成果保留；用户取消不被误判成系统失败；正常交付未采用不退款。
- [ ] 调用开始与取消竞争、扣除后恢复、终态回复丢失及迟到响应不会产生重复扣退、余额漂移或未授权项目副作用。
- [ ] 数据库调价后，新工作用新价，已接受工作仍按原价扣退；既有用户余额不重算。
- [ ] 浏览器可看到报价、占用、扣除与退款；刷新/重开以服务端结果为准。余额用完仍可查看和操作已有成果，需新增 AI 的工作被明确阻止。
- [ ] 供应商用量和用户积分分别可追溯，缺失实际费用时明确未核对，协议替身数据不被当成真实成本。

真实成本校准与真实设计质量另用授权样本和实际供应商验证，完整设计链路未就绪时记录未验证，不因本票结算测试通过宣称定价合理。服务和隔离 Worker 进程的启动/重启继续遵守用户授权限制，不在默认测试中自动拉起。

## Out of Scope

重新实现模型能力、任务状态机或图纸设计链路；注册赠送基础（由 C01 完成）；匿名体验、按 token 或进度百分比收费、动态加价、付费/充值/订阅及管理后台；真实供应商采购、部署与最终价格承诺。

## Further Notes

现有任务运行器不启动模型，确定性协议测试不能证明模型调用扣分边界已接通。仅在前置模型与失败处理能力就绪后完成集成验收；必要准备工作不能冒充完整通过。金额测试必须包含系统退款后余额与保留成果的共同检查。
