## Problem Statement

系统只有企业内的管理员与成员，没有我方的平台管理员，模型登记与跨企业分配没有可以授权的人和入口。

## Solution

新增平台管理员与超级管理员角色、命令行授予与撤销、`/admin` 管理后台外壳（仅后台域名 `HESTIA_ADMIN_HOST`）与审计记录。超级管理员只读进入企业工作台拆到 [AM06](AM06.md)。

## User Stories

1. As a 维护者, I want 用一条命令把某个邮箱账号设为平台管理员或撤销, so that 权限只在服务器上发放。
2. As a 平台管理员, I want 在后台域名登录管理后台, so that 管理模型与企业。

## Implementation Decisions

- 新表记录平台管理员（账号、授予时间、授予方式）；`pnpm platform:admin grant|revoke|list`。
- `/admin` 与 `/api/admin/*` 只在 `HESTIA_ADMIN_HOST` 上响应；其他域名上与不存在的路径相同。`admin`、`www`、`api` 等保留名不能登记为企业域名。
- 超级管理员用 `pnpm platform:admin grant --super <email>` 授予（同一张表，级别 `super`）；进入企业工作台见 AM06。每个接口在服务端校验平台管理员身份，不依赖页面隐藏。
- 2026-11-14 实现：`platform_admins`、`platform_audit`（迁移 `0008_platform_admins`）；`proxy.ts` 在后台域名以外把 `/admin`、`/api/admin` 改写为标准 404，在后台域名上只放行后台、登录与静态资源，其余重定向到 `/admin`；页面与接口再各自检查一次。来源校验接受后台域名。
- 审计记录表：操作者、时间、动作、对象、变更摘要（不含密钥）；后台提供只读列表。
- 后台外壳按工作台视觉（柔和中性，1440 为主）实现：导航「模型」「企业」「用量」「审计」，其余页面由后续工单接入。
