# M03 后台队列按企业限流与用量报告验证

日期：2026-11-10。范围：工单 #61，依据 ADR-0017。PostgreSQL 17.7（同 M01），pg-boss 12.38 安装在一次性 schema 中；两个用户的个人工作空间代表两家企业。

## 实现要点

- **任务带企业**：设计任务、出图、图纸转换三个队列入队时，在同一事务里按任务所属项目查出工作空间，作为 pg-boss 的 `group`（企业 slug 作为 `tier`）。
- **公平顺序**：一个工作空间已有 n 个等待或运行中的任务时，新任务优先级为 -n（下限 -1000）。只有一个处理槽位时，别家的第一个任务也排在这家的第二个任务之前；任务完成后不再计数。
- **并发上限**：Worker 读取 `HESTIA_<TASK|RENDER|IMPORT>_WORKER_SLOTS`（默认 1）、`…_GROUP_LIMIT`（默认槽位数减一，至少 1）与 `…_GROUP_LIMITS`（按企业 slug 覆盖的 JSON），交给 pg-boss 的 `localConcurrency` 与 `groupConcurrency`；值非法时 Worker 启动即报错。工单原写“工作空间配置”覆盖，实现为按 slug 的环境变量，不改数据结构。
- **不变的部分**：任务 id、幂等、重试、租约与崩溃恢复逻辑不变；默认 1 个槽位时并发行为与之前相同，只是领取顺序改为公平。
- **用量报告**：`pnpm usage:report --month YYYY-MM [--workspace <slug>]`，按北京时间自然月、按工作空间汇总：设计任务数（按状态）、模型调用次数与输入 / 输出 token（来自任务的 token 用量事件，供应商未报告 token 的调用计入 `unverifiedCalls`，不记为 0）、出图数（完成 / 失败 / 尝试次数 / 完成耗时）、图纸转换数（按状态）。只读。

断言：A 连续提交 4 张出图后 B 提交 1 张，任务带各自工作空间、优先级为 0、-1、-2、-3 与 0，单槽位领取顺序为 A1、B1、A2、A3、A4；A 的任务完成后再提交，优先级回到 0。组上限 1 时，A1 运行中第二个槽位领到 B，两家都在上限时领不到任务。槽位与上限的默认值、覆盖值，以及 0、小数、非法 JSON 均被拒绝。用量报告：1 个任务、2 次 token 调用（1200 / 300 token，另 1 次未报告 token 计入 `unverifiedCalls`，协议步数事件不计入）、出图完成与失败均统计；另一工作空间不混入；其他月份为空；非法月份 400、不存在的 slug 404。

## 未验证

- 出图完成耗时依赖 `render_attempts` 的开始时间，测试的合成数据没有尝试记录，只验证了该项为 0 时不出错；真实出图后的耗时需在 Worker 运行时核对。
- 多槽位下 Agent 与出图的资源占用（内存、CPU）未测，默认仍为 1 个槽位。
- 用量只计次数与 token，不换算金额；计费与账单不在本票范围。
