## Problem Statement

项目、资源、出图与操作直接按用户归属，无法表达企业有多名成员、客户访问企业项目、个人用户拥有个人空间。

## Solution

引入工作空间作为项目、资源、出图、操作与用量的归属单位，提供成员与角色。现有用户迁移为个人工作空间，访问行为不变。

## User Stories

1. As a 个人用户, I want 原有项目自动归入我的个人工作空间, so that 访问不受影响。
2. As an 企业成员, I want 访问本企业工作空间的全部项目, so that 能协同处理客户方案。
3. As an 企业管理员, I want 管理成员和角色, so that 控制谁能处理方案。
4. As a 用户, I want 无法访问不属于我的工作空间, so that 资料隔离。

## Implementation Decisions

- 新增工作空间、成员与角色；项目及其资源、出图、候选、任务、操作的归属从用户改为工作空间，授权检查统一经工作空间成员关系（客户访问在 D02/D08 扩展）。
- 迁移为每个现有用户创建个人工作空间并迁移项目，保持幂等、可在已有数据上重复执行；迁移前后现有测试行为一致。
- 归属变更波及项目、候选、任务、出图、资源、操作与风格等多个模块，按扩展–迁移–收缩推进：先并存新旧归属并回填，再逐模块切换授权，最后移除旧归属；每步保持 `pnpm check` 与 `pnpm test:db` 通过。
- 企业工作空间由脚本或服务端接口创建，本票不做界面。积分规则保持只作用于个人工作空间。
- 依据 ADR-0007；不新增企业专用分支逻辑，能力差异通过工作空间配置表达。

## Testing Decisions

- [ ] 在含已有项目的数据库上迁移后，原用户仍能访问自己的项目、资源、出图与候选，修订号不变。
- [ ] 企业成员可访问本空间项目，非成员和其他空间成员被拒绝，包括直接请求已知资源 ID。
- [ ] 迁移可重复执行，不产生重复空间或重复归属。
- [ ] 既有 `pnpm check` 与 `pnpm test:db` 全部通过。

## Out of Scope

客户身份与手机号（D02）、分享与绑定（D08）、成员管理界面、企业额度规则。
