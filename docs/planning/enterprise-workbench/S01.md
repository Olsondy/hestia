## Problem Statement

> 2026-11-03 按 [ADR-0013](../../decisions/0013-drawing-requests-without-review-gate.md) 改写：原来“先生成待审方案、由成员发布”的设计作废。

图纸需求在 DXF 转换后一律停在“待审核”，要等企业成员发布才生成方案；转换失败时客户只看到等待，不知道原因。

## Solution

DXF 转换成功即自动出方案并发布，与示例别墅一致；转换不了在客户端直接说明原因，客户可重新上传或交给企业整理；照片、PDF、DWG 进入企业的整理队列；上传按客户每天限次。

## User Stories

1. As a 客户, I want 上传 DXF 后直接看到方案, so that 不必等企业。
2. As a 客户, I want 图纸识别不了时知道原因并能重新上传或交给企业, so that 不被卡住。
3. As a 客户, I want 上传照片或 PDF 后在「我的项目」看到排队处理中, so that 像下单一样知道进度。
4. As a 维护者, I want 上传有每日次数限制, so that 转换与出图资源不被滥用。

## Implementation Decisions

- 转换 Worker 完成 DXF 后调用 `generateForImport`：候选通过校验 → 采用为项目空间、派生地面与楼梯饰面、规则生成方案并出图，只保留通过排版校验的方案直接发布；候选不通过或没有可用方案 → 转换记为失败并写明原因。上传请求在关联图纸后也调用一次，两边谁后完成谁生成，幂等。
- 需求状态增加 `conversion_failed`，客户视图返回 `conversionError`；失败后可重新上传（替换图纸）或 `POST …/requests/{id}/hand-over` 交给企业（进入 `assisted_conversion`，显示“排队处理中”）。
- 上传限次：每位客户在每家企业每天 3 次（北京时间），失败也计入，超出 429 `DRAWING_DAILY_LIMIT`；工作空间设置 `drawingUploadsPerDay` 可调。
- 企业的“全部审核后发布”设置保留（默认关闭），仅此时需求等待成员发布。
- 不调用任何模型。

## Testing Decisions

- [x] HTTP + PostgreSQL + 转换 Worker 逻辑：DXF 转换后直接发布且重复生成不重复；空白或无法识别的 DXF 返回原因，可重新上传后发布、可交给企业进入排队；图片排队；每日第 4 次上传 429，其他客户不受影响。见 [S01 验证](../../validation/S01-drawing-requests.md)。
