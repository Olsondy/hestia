# K01 软装风格目录、家具素材与多楼层布局验证

日期：2026-11-03。范围：工单 #52。本机 PostgreSQL；渲染用 Playwright Chromium（SwiftShader）中的交互式 `SpatialScene`。

## 实现要点

- **风格契约** `packages/contracts/src/soft-styles.ts`：风格 = 名称、描述、色块、家具材质色调（布艺、靠垫、木色、深木、金属、点缀）+ 按房间类型（客厅、餐厅、卧室、茶室、书房）的换款规则与补充陈设规则；房间类型由房间名识别（「餐厅 · 客厅」同时属于两类）。场景物品新增可选的 `softStyle`（风格与版本、换款前的原款式）与 `tones`，项目状态沿用同一结构。
- **目录** `workspace_soft_styles`（迁移 `0003_soft_styles`）：工作空间私有，版本不可变（重复写入保留原内容），可下架；下架版本不再出现在可选列表，但仍可按版本读取，已用它的方案照常显示。客户端目录 `GET /api/client/{entry}/catalog` 增加 `softStyles`（只含名称、描述、色块，不含布置规则）。
- **布置** `packages/soft-styles/src/furnish.ts`：按楼层与房间类型，在原家具占地内换款并上色，再放补充陈设——落地灯放在主家具旁，绿植与屏风放在空角落，挂画挂在主家具背后的墙上（那段墙有门窗时改挂本房间其他墙），吊灯和灯笼挂在桌子上方，圈椅放在茶桌旁并面向茶桌。每件陈设都校验：在房间内、不与家具重叠（陈设之间留 15 cm 余量）、不挡门（门洞两侧各留 0.8 m）、不压楼梯、高的陈设避开窗户、挂画不挂在门窗上、不挂在高柜后面。放不下的陈设会被记录下来，不强行摆放。换风格时先还原原家具再重新布置。
- **素材**（`scene-runtime` 程序生成，示意素材）：新增弧形沙发、圆茶几、椭圆餐桌、圈椅、挂画、屏风、线性吊灯、灯笼、室内落地灯；所有道具材质按风格色调渲染。
- **演示目录**：现代简约、轻奢、新中式三套（与 H5 演示数据同名同色块）；示例别墅的家具改为由默认风格（现代简约）生成；`pnpm demo:seed` 把三套风格写入演示企业。

## 渲染复核

`node --import tsx scripts/validation/soft-styles-render.ts` 生成 18 张图（3 套风格 × 客厅两个机位、餐厅、二层家庭厅、主卧、茶室），输出到 `.impeccable/review/k01/`（不入库）。独立复核（未参与实现的代理逐张看图）第一轮的结论与处理：

- 圈椅看不出是椅子 → 重做为方座、四腿、靠背板加半圆椅圈。
- 轻奢餐厅与其他风格无差别 → 换为椭圆大理石桌。
- 屏风挡窗 → 高的陈设避开窗户。
- 茶室没有座椅 → 新中式在茶桌旁加圈椅、上方加灯笼。
- 现代简约布艺偏白 → 布艺色加深为灰调。
- 新中式茶几仍是白色石面 → 换成木质茶桌。
- 落地灯与绿植叶丛重叠 → 陈设之间留余量。
- 弧形沙发套在 L 形沙发的进深里像床，挂画浮在落地窗前（实现时自查发现）→ 限制座深、沿弧线排列座位；挂画只挂在墙上。

修正后复看：客厅、餐厅、茶室在三套风格之间能明显区分。卧室三套之间仍主要是颜色差别，床与床头柜是同一造型。

未处理（沿用示例别墅原布局，不在本票范围）：一层客厅沙发靠近通往庭院的推拉门；远侧餐椅与餐边柜间距偏小。软装风格写入方案、客户切换风格属于 K02。
