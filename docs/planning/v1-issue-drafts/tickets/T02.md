## What to build

阶段：M0。用清晰图、扫描图和手绘图验证识图脚本及结构化初稿转换，判断哪些能力可以复用。

依据总规格及 ADR-0001–0005；适用工具、运行与模型约束随本行为执行，不扩展首版范围。每票负责此行为所需的数据、服务、交互与验证，不另拆水平层任务。

## Acceptance criteria

- [ ] 每类至少一个授权样本，有人工核对基准及漏识别/误识别记录。
- [ ] 核对毫米到米、墙中线、原点、方向、开口和尺度来源，往返误差在约定容差内。
- [ ] 估算、未知尺寸和固定设施猜测不被提升为已确认事实。
- [ ] 输出脚本支持范围、依赖、失败类型与复用结论；样本不足明确标未验证。

## 已确认架构与本轮执行约束（2026-10-25）

用户已确认 `docs/web-stack.md`、ADR-0003–0005 并明确恢复开发：按原生依赖顺序推进，可独立工单由子 Agent 并行；验收通过后才能关闭或解除下游阻塞。精确版本及实际能力需验证，部署方案另议。

- 识图输出通过纯 TypeScript 契约转换成候选空间；Python 仅用于确有复用价值的受控识图脚本，不形成第二套业务状态。
- 转换器与 Three.js/Konva 无关，输出稳定对象 ID、米制、弧度、尺度来源与未确认事实；后续生产调用归 Worker。

- 所有涉及 UI 的页面统一采用家居杂志（editorial）作为生产视觉基线，参照用户亲自迁移并确认保留的 `example/prototypes/projects` 原型：源码 `example/prototypes/projects/src`，可访问产物 `example/prototypes/projects/index.html`。使用用户指定的 `impeccable` 技能，继承该方向的间距、字体层级、布局与动画；遵循 `DESIGN.md`，不启用 hooks。中文统一使用仓耳渔阳体（Tsanger YuYang）并保留许可。建筑展馆仅作为原型历史保留，不要求生产双主题。
- 原型迁入 `example/prototypes/projects` 后保持可访问，不把演示助手、本地存储或示例空间冒充生产能力。新增 UI 需浏览器检查，自动测试不能替代视觉验收；无 UI 变更的票不强制新增页面。
- 外部凭据、真实样本和环境不足时记录具体未验证项；继续无依赖准备工作，不伪造模型或验收结果。单票共享文件与契约由主 Agent 协调，保持现有父子关系和阻塞边。
- 最新执行边界：用户已配置平台 API，并授权真实 API + 合成样本验证；禁止启动或重启服务，不读取或上传私密图纸。合成评估不代替真实住宅质量验收。
