# 首版已发布工单与并行开发顺序

状态：2026-10-25，测试边界、拆分和实现架构已获批准；总工单和 24 个子工单已发布，24 个原生父子关系、39 条原生阻塞关系及 ready-for-agent 标签已读回核验。用户已明确恢复开发，按依赖顺序推进，独立工作由子 Agent 并行；旧暂停说明已撤销。工单按定稿技术栈同步，具体远端读回信息见发布清单。

[已批准总规格](spec.md) 按 to-spec 模板准备；以下每项均有独立完整正文。T 编号用于本地切片定位，真实编号见 [发布清单](../v1-published-issues.json)；总工单为 [#1](https://github.com/Olsondy/hestia/issues/1)。

## 已批准测试边界

主边界：用户事件进入项目/任务服务，验证公开读取到的任务状态、项目修订、候选差异及成果。内部执行器与持久化真实运行；供应商替身仅控制模型响应。少量几何边界用独立夹具验证；真实模型评估、真实浏览器关键旅程及视觉核对单列。沿用现有失败编辑、锁定、持久化与撤销的行为案例，不把演示文本解析作为真实 Agent 证据。

## 编号、阻塞和可交付行为

1. **[T01 验证平台模型的图片与受限工具调用](tickets/T01.md)** — 阻塞：无工单依赖。以授权小样验证质量/快速配置，得到可运行的图片理解和受限工具调用链路及准入基线。
2. **[T02 验证图纸到空间候选的识别与转换](tickets/T02.md)** — 阻塞：无工单依赖。用清晰图、扫描图和手绘图验证识图脚本及结构化初稿转换，判断哪些能力可以复用。
3. **[T03 验证通用户型的交互与后台渲染](tickets/T03.md)** — 阻塞：无工单依赖。对比现有场景改造与外部模板适配，在两套不同户型上验证交互和服务端出图。
4. **[T04 创建并重新打开隔离的空间项目](tickets/T04.md)** — 阻塞：T03。用户可从界面创建、保存和重开带可信测试空间的项目，服务端版本成为事实来源。
5. **[T05 精确修改单件家具并撤销](tickets/T05.md)** — 阻塞：T04。用户点选家具后准确移动或旋转，看到保存的变化并可以撤销。
6. **[T06 预览候选并采用具体版本](tickets/T06.md)** — 阻塞：T05。用户可查看独立候选与当前方案差异，再一次采用已展示的具体版本。
7. **[T07 提交可关页继续的后台设计任务](tickets/T07.md)** — 阻塞：T05。用户提交确定性测试任务后可关页，重开看到同一任务进度、结果和取消状态。
8. **[T08 用平台模型完成准确局部修改](tickets/T08.md)** — 阻塞：T01、T06、T07。自然语言经平台模型、有限工具和执行器完成唯一目标的局部修改，结果可查看并撤销。
9. **[T09 上传图纸并选择、保存 PDF 页面](tickets/T09.md)** — 阻塞：T04。用户导入私有图片或 PDF 页面，调整底图并在重开后继续使用。
10. **[T10 整理有来源的居住需求并回答必要问题](tickets/T10.md)** — 阻塞：T08。助手整理居住需求、保留条件和矛盾，用户可回答持久化问题并继续任务。
11. **[T11 将用户图纸识别为可审查空间初稿](tickets/T11.md)** — 阻塞：T02、T08、T09。用户提交已上传图纸后，后台生成属于这张图的建筑候选并展示叠图及 3D。
12. **[T12 在产品内纠正墙体和门窗初稿](tickets/T12.md)** — 阻塞：T11。用户通过点选或对话修正未确认建筑，看到可核对、可恢复的初稿变化。
13. **[T13 补充可靠尺度并采用初始空间](tickets/T13.md)** — 阻塞：T12。用户提供可靠尺寸后得到重算的空间，并确认初始空间与固定设施。
14. **[T14 独立确认固定事实的纠正](tickets/T14.md)** — 阻塞：T13。用户在独立入口查看固定事实错误及影响，确认后更新基础事实。
15. **[T15 从受控目录调整候选家具组合](tickets/T15.md)** — 阻塞：T06。用户在校准测试空间选择目录家具，预览新增、替换和删除后的组合并采用。
16. **[T16 对候选应用一致的材质和展示灯光](tickets/T16.md)** — 阻塞：T15。用户查看材质与灯光调整后的视觉风格并保存，空间布局不被无意改变。
17. **[T17 自主生成满足功能要求的单房间布局](tickets/T17.md)** — 阻塞：T10、T15。助手在可靠测试空间中自行完成会客与办公等功能布局并展示推荐。
18. **[T18 将单房间设计扩展为整层推荐与比较](tickets/T18.md)** — 阻塞：T13、T16、T17。基于用户已校正图纸协调多个房间，展示完整推荐及有实际取舍的替代并采用。
19. **[T19 让运行中的设计遵循用户最新要求](tickets/T19.md)** — 阻塞：T10、T17。用户在设计中补充保留条件或反馈后，任务延续仍有效工作并重新处理受影响部分。
20. **[T20 关闭页面后生成并领取静态成果](tickets/T20.md)** — 阻塞：T03、T06、T07。后台对指定候选或当前方案生成静态图，用户重开后能查看和下载。
21. **[T21 任务到限或模型故障时保留可用成果](tickets/T21.md)** — 阻塞：T08、T10。模型故障或任务达到上限时，用户看到真实已完成部分和未完成原因。
22. **[T22 在组合故障和取消竞争中保持状态正确](tickets/T22.md)** — 阻塞：T18、T19、T20、T21。用户在整套任务遇到重启、延迟和取消时仍得到一致、可追踪的结果。
23. **[T23 在试用环境恢复项目及其全部资料](tickets/T23.md)** — 阻塞：T14、T18、T20、T21。在目标试用环境部署完整流程，备份恢复和版本回滚后仍能打开项目及成果。
24. **[T24 用十个授权样本完成首版试用验收](tickets/T24.md)** — 阻塞：T22、T23。试用用户通过产品内校正完成十个图纸到设计、采用、迭代和静态图的完整任务。

## 并行调度

- 初始前沿为 T01 / T02 / T03；T03/T04 已验收关闭，当前前沿为 T01 / T02 / T05 / T09。T01/T02 仅推进合成及协议部分；T05 与 T09 可并行消费已验收项目契约。T03 证据见 [验证报告](../../validation/T03-rendering.md)。
- 本轮用户指定先使用合成样本，真实模型 API 稍后配置；T01/T02 可推进协议、适配和合成验证，但真实模型与真实图纸验收仍未通过，不能据此关闭这两票。
- 所有 UI 工单仅参照用户迁入 `example/prototypes/projects` 的家居杂志（editorial）原型；建筑展馆仅留作历史，使用用户指定的 `impeccable` 技能；沿用间距、字体层级、布局和动画，中文使用仓耳渔阳体（Tsanger YuYang），保留字体许可，不启用 hooks。
- T04 汇合共享项目契约、身份和存储入口；之后 T05 与 T09 可并行，T05 后 T06 与 T07 可并行。
- T06 后目录组合 T15 可独立推进；T06/T07 完成即可验证后台输出 T20，不必等待整套设计。
- T08 后需求 T10 与识图 T11（需 T02/T09）并行；图纸校正 T12→T13、风格 T16 和房间布局 T17 在 T18 汇合。
- 最新意图 T19、模型故障 T21 及后台输出 T20 按各自真实前置推进；组合故障 T22 与部署恢复 T23 可并行，最终汇合 T24。
- 同时最多三个开发子 Agent，主 Agent 保留集成、调度与验收职责。只领取依赖已完成且无人负责的工单；同一前沿不等于共享文件可同时写。
- 每次委派明确输入契约、允许改动范围、产物和退出标准。共享项目/候选/几何/任务状态由当轮指定负责人维护，其他 Agent 提出接口需求，不另造平行状态；发生重叠时串行集成或使用隔离工作区。
- 每票交付真实行为和验证证据后才能解除下游阻塞，失败不通过关闭工单伪装完成。总工单正文不由子票流程改写或关闭。

## 阻塞状态的表达

`ready-for-agent` 表示规格已可执行；是否可领取取决于原生依赖和外部条件。外部阻塞记录具体缺项、受影响验收与解除证据，不凭空增加已完成日期或固定工期。

| 条件 | 当前状态 | 只阻塞的工作 |
| --- | --- | --- |
| 测试边界、拆分与实现架构 | 已批准并恢复开发 | 按原生依赖和验收推进，不再受旧开发暂停记录限制 |
| GitHub CLI 身份 | 已登录，写入及原生关系核验通过 | 无发布阻塞；连接器实际无写入权限，本次使用 CLI |
| 平台模型凭据/权限/额度 | 用户明确稍后配置，目前先做合成/协议验证 | T01 真实评估、T08 真实接入、最终真实模型验收 |
| 授权图纸与人工基准 | 本轮先使用合成样本，真实样本验收保留 | T02 真实识图评估、T11 图纸贯通及 T24 十样本验收 |
| 通用渲染与共享契约 | T03/T04 本地验收通过 | T05 与 T09 已无开放工单阻塞，仍须各自实施和验收 |
| 试用部署环境 | 待落定 | T23/T24；不阻塞本地合成空间开发 |

## 发布规则

总规格及 T01–T24 已发布；更新现有正文与进度，不重新创建重复 Issue。保留 ready-for-agent、原生父子关系与真正阻塞项。工单可引用定稿文档与用户指定的原型目录，不粘贴实现代码。原生关系和标签需要读回核对；发生部分成功时记录已更新编号并续传。

采用原生关系后可省略正文 Blocked by，若平台确实不支持则保留真实 Issue 引用并说明限制。缺少 CLI 登录不等于 GitHub 不支持原生依赖；应补齐操作能力再建立，不能默默降级。
