# W07 工作台 Agent 出方案界面验证

日期：2026-11-15。范围：工单 #56，依据 ADR-0019 与定稿原型 P02（`example/prototypes/enterprise-workbench`，「Agent 助手」各状态）。PostgreSQL 17.7（局域网主机上的本地 Compose 容器，经 SSH 隧道映射到 127.0.0.1:54329）。

## 实现要点

- **入口**：线索详情画面底部工具栏加「Agent」按钮，打开右侧悬浮的 Agent 助手（`components/enterprise/workbench-agent.tsx`）。空间还没有可铺贴的饰面时，按钮不可用并说明原因：图纸未上传、正在识别、排队整理或识别失败。窗口宽度不超过 1180 时，左右两个面板只开一个，和原型一致。
- **对话**：
  - 第一次发送新建对话任务，之后在同一任务里追加（保留需求记录），模型选择随消息提交；
  - 回复经事件流实时显示，处理中显示当前阶段（排队、出方案、校验、保存）；
  - 关页再回来，从头重放最新任务的事件，看得到进行中的任务和结果；
  - 网络中断时用同一个操作标识重发，不会重复创建；空间版本变化时重新读取线索并提示再发一次。
- **状态提示**：未开通（企业管理员可直接进企业设置）、本月额度已用完、所选模型不可用、被拒绝的提案及原因（最多列 5 条冲突），都如实说明，不模拟结果。
- **候选**：草稿候选与线索方案并列在左侧方案列表里，标「候选」，过期的标「已过期」。画面、说明栏、硬装清单、软装风格（名称、说明、配色、客户可切换的风格）和校验提示与方案一样显示。效果图出完前每 5 秒刷新一次；3D 和平面图读取候选出图时的场景（新增 `GET …/candidates/{id}/scene`）。
- **采用、放弃、发布**：
  - 采用和放弃都要确认，放弃对应新增的 `POST …/candidates/{id}/discard`，候选状态新增 `discarded`（迁移 `0013`）；
  - 采用后自动选中新的待审方案。待审方案的底栏是「发布方案 X」，确认后客户才看得到（线索本身也已发布时）；
  - 已过期的候选不能采用。
- **线索视图**新增 `projectRevision`，Agent 的每一轮都以它为基准版本。

验收中发现并已修复：

- 模型回复的换行被合并成一段：`.msg` 改为 `white-space:pre-line`。
- 采用、放弃、发布用的是浏览器原生 `confirm`，与工作台其他二次确认（W04 的 `Modal`）不一致：改用同一个 `Modal`，放弃按钮为危险样式。
- 演示数据的效果图文件是在另一台机器生成的，本机读取返回 503 `OUTPUT_UNAVAILABLE`（环境问题，不是代码缺陷）；重建演示数据后正常。
